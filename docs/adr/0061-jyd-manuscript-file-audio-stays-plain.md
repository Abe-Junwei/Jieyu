# ADR 0061：文稿是 .jyd 文件，音频保持原文件，声文稿只是展示

## 状态

accepted。用户 2026-10-16 选定。本篇取代以下条款，其余不变，两篇正文都不改：

- [0058-card-sqlite-file.md](./0058-card-sqlite-file.md) 第 1 条（一张卡片是一个装着音频字节、文稿和语段的 SQLite 文件），以及第 2 条里「磁盘文件名是可读名称加卡片 id」「声文稿沿用音频卡的 id」。
- [0060-card-file-ownership-and-operations.md](./0060-card-file-ownership-and-operations.md) 第 1 条里「录音、它的字节、来源登记进卡片文件」，第 5 条（音频分块存）和第 6 条（局部删除先写新文件再 `VACUUM INTO`）。

这是产品和格式决定，不表示工程可以发布，也不表示 D14 可以冻结。可发布以 `docs/execution/specs/card-sqlite-file/` 的原型和验收为准。

第 5 条「按 sha256 认回」在多个文件哈希相同时不够，必须停下问用户。主动删除、意外丢失、暂时离线和已还原也还要分开表示。这两点没有新 ADR，规格里先写成实施约束。决策正文不改。「不用 WAL」只表示关闭后不留 `-wal`/`-shm`；写入过程中仍会有 `-journal`，也不表示放进同步盘就安全。

影响里「按录音拆成多个 `.jyd`」不再采用。用户 2026-10-16 更正：一个语段只挂一条录音；一份文稿可以改挂到另一条音频，但不能同时关联多条；父子链接不能跨文稿。同时挂上两条、或父语段在另一份文稿里，都要拒绝，不是拆开。正文不改。

## 背景

把音频字节装进卡片文件后，Praat、ELAN 和归档机构都打不开；改一个语段，按文件备份的工具也要重新复制约 2 GB；拿掉一部分时文件不会变小，`VACUUM` 还要再占一份空间；正在写的大文件放在同步盘里容易出事。Audacity 3 的 `.aup3` 用 SQLite 存音频块，碰到的正是这些问题。ELAN 和 SayMore 让音频和标注文件并排放，没有这些问题。

JYT、JYM、JYB 是 zip 加 JSON 的交换包（[ADR-0046](./0046-desktop-sqlite-project-folder.md) 第 2 条），改一处就要整份重写，不适合当日常编辑的文件。

## 决策

1. **文稿是 `.jyd` 文件。** 一份文稿一个 SQLite 文件，只在项目文件夹里使用。它装这份文稿的层、语段、内容、词与词素切分、锚点、备注，加上它对着的音频引用（音频 id、相对路径、sha256、时长）和 ADR-0060 第 2 条的定义副本。文件用 SQLite 的 `application_id` 标明是解语文稿，用 `user_version` 记录格式版本。JYT、JYM、JYB 仍只是交换包。
2. **音频保持原文件。** 导入的音频原样复制进项目文件夹，不进任何数据库。项目库登记每条音频的 id、相对路径、sha256、时长和来源。
3. **声文稿只是展示。** 看板把一条音频和引用它的文稿显示成一张声文稿卡片，磁盘上没有对应的单个文件。只有音频的是录音卡片，没有音频引用的是文稿卡片。配对就是在文稿里写下音频引用，拆开就是清掉它。卡片清单仍是 ADR-0060 第 3 条的可重建缓存。
4. **文件名是用户能读的名字，不加 id。** 例如 `录音01.wav`、`录音01.jyd`，同一条录音的第二份文稿是 `录音01 (2).jyd`。id 存在 `.jyd` 和项目库里。同名配对按主名比较。
5. **删除一部分就是对一个文件操作。** 从声文稿拿掉音频，就是把那个音频文件送进系统垃圾箱；拿掉一份文稿，就是送走那个 `.jyd`。不再写拆出文件，也不压缩原文件。用户从垃圾箱还原后，按 sha256 和 `.jyd` 里的 id 认回。
6. **不用 WAL。** `.jyd` 和项目库使用 SQLite 默认的回滚日志，关闭后只剩一个文件。写入速度是否够用由原型验证；不够时另开 ADR。

## 影响

- ADR-0060 的操作 id 仍然需要：隐藏或删除一张声文稿卡片会移动一个音频和若干 `.jyd`，导入音频加 EAF 会写两个文件。
- 导入的 EAF 转成 `.jyd`，原名存在文件里。导出给别的工具用时，由 `.jyd` 转成 EAF 或 JYT/JYM。
- 现有一份标注文稿可能跨多条录音，迁移时要按录音拆成多个 `.jyd`。

## 被放弃的备选方案

1. 一张卡片一个 SQLite 文件、音频字节在里面（ADR-0058 原第 1 条）：理由见背景。
2. 同一条音频的全部文稿放进一个文件：删一份文稿又要局部删除。
3. 直接用 JYT 当文稿文件：它是整项目交换包，改一处要整份重写。
4. 直接用 EAF 当文稿文件：词素切分、锚点和定义副本要另外存，又成了两份真源。
