# ADR 0070：定义副本只含这张文稿用到的语言、正字法和说话人

## 状态

accepted。用户 2026-10-22 选定。本篇不改已接受 ADR 的正文。[ADR-0060](./0060-card-file-ownership-and-operations.md) 第 2 条仍然有效。ADR-0067、ADR-0068、ADR-0069 里「这题未定」的句子留在原处，以本篇为这题的决定。

## 背景

定义副本贴在 `.jyd` 上，记下这张文稿用过哪些共用定义。同一项目里打开文稿时读项目库，不读副本。副本只在把这份文稿导入另一个项目时用来列出差异，由用户映射或导入。

当时未定的是：词条、标签定义、自定义字段定义、缩写要不要跟着进副本。

## 决策

1. 副本维持 ADR-0060 第 2 条已经点名的范围：这张文稿用到的语言（id 和名称）、这些语言的显示名和别名、用到的正字法、用到的说话人。每次写这张文稿时按实际用到的行刷新。
2. 词条、标签定义、自定义字段定义、缩写留在项目库，不进 `.jyd` 的定义副本。文稿上的词条链接只存词条 id。导入另一个项目时，对不上的词条链接列为对不上的引用。词典另行导入。
3. 语言行上的国家、使用领域、行政区划、备注和自定义字段值仍按 ADR-0067 留在项目库，不进副本。

## 影响

- 存储接口的 SQLite 实现沿用这个副本范围。
- 跨项目导入若以后要逐条映射词条，另写一篇 ADR，再把文稿引用到的词条行放进副本。

## 被放弃的备选方案

1. 把这张文稿引用到的词条行放进副本。词形已经在文稿自己的词和词素上。词条是项目共用目录，不是这张文稿的身份。
2. 把引用到的标签定义、自定义字段定义、缩写也放进副本。这三样是项目约定，文稿行不靠它们才能读。
3. 继续留到存储接口实现时再定。用户已经选定。
