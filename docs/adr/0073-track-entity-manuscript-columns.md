# ADR 0073：轨道行记下项目和更新时间

## 状态

accepted。#275 的存储接口继续写 `.jyd`。本篇不改已接受 ADR 的正文。

## 背景

轨道行已经有 `lane_lock_json`（ADR-0069）。存储接口还要按项目列出轨道，并在写入后读回媒体、模式、车道锁定表和更新时间。这两列文稿文件里还没有。

## 决策

1. `.jyd` 的 `track_entities` 增加 `text_id` 和 `updated_at`。迁移没写过的格子留空。车道锁定表仍是 `lane_lock_json`。不进项目库，不进定义副本。
2. 一次写入只改一份 `.jyd`：已有行所在的那一份，或者文件夹里唯一的一份。新建行碰上两份文稿就拒绝，不写。同一 id 出现在两份文稿里也拒绝。
3. 已有行的 `text_id` 去掉空白后非空、又对不上这次的项目，就拒绝，原行不动。`text_id` 空着的旧行不挡这次写入。
4. 车道锁定表在事务开始前必须是有限数字的对象，空对象可写。对不上就拒绝，不写。迁移时丢掉坏列、留下轨道行仍按 ADR-0069，不用于这次活写入。
5. 写入是这一份文稿里的一次事务。提交后读回项目、媒体、模式、更新时间，以及车道锁定表的键和值。读回失败不撤销。

## 影响

- 存储接口的 SQLite 实现按这个顺序写和列出。浏览器里的 Dexie 仍然是一次事务，表也不变。
- 列出时只返回 `text_id` 对得上的行。查询是空白就返回空。

## 被放弃的备选方案

1. 把轨道行放进项目库。车道锁定表已经定在 `.jyd`。
2. 活写入也按迁移那样丢掉坏的车道锁定表再留下轨道行。提交后读回会对不上，又不能撤销。
3. 把两份文稿 ATTACH 成一个事务，让新建行自己挑文件。一份轨道行只属于一份文稿。
