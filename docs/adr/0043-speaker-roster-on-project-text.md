# 0043 — 说话人名单挂在项目文本上

## 背景

说话人行没有 `textId`，转写页和标注页读取整张 `speakers` 表。两份项目会看到同一份名单。说话人仍是一个人，可以出现在多份材料里，不宜把整行复制进每个项目，也不宜给说话人加单一 `textId`。

## 决策

1. 项目名单是 `texts.metadata.projectSpeakerIds`。说话人行继续全局保存姓名和田野属性。
2. 在当前项目里新建说话人，或把已有同名说话人用于当前项目，只把 id 写入该文本。
3. 打开项目时，名单是这份 id 列表，并补上该项目语段上已经引用、但还没写入列表的说话人。
4. 协作快照带走文本行，因此带走名单。说话人行仍按语段引用拷贝，规则不变（见项目快照过滤）。
5. 不新增父级项目表。一份材料仍是一个 `textId`。语言表和正字法仍是全库目录。

## 影响

- 从未写入名单、也没有被语段引用的旧说话人，不会出现在新打开的项目里。在该项目里用同名再建一次，会挂上原来的那个人。
- 删除说话人时从各项目名单去掉该 id。删除项目不删除说话人行。

## 被放弃的备选方案

- **说话人行上的 `projectTextIds`**：快照按整行 upsert 说话人，会盖掉另一份项目已经写上的名单。
- **只按语段引用过滤**：还没指派到句子上的人会从名单消失，无法先建名单再指派。
