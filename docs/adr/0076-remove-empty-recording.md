# ADR 0076：去掉一条空录音

## 状态

accepted。#275 的存储接口继续写 SQLite。本篇不改已接受 ADR 的正文。

## 背景

录音行已经在项目库（ADR-0075）。去掉一条空录音还会碰到文稿里的语段、锚点和轨道，以及来源记录上的关联。SQLite 一个事务只覆盖一个文件（ADR-0060 第 4 条）。浏览器里的 Dexie 还会删句段元数据和几张快照表。文件夹格式里还没有这些表。

## 决策

1. 编号去掉空白后是空的，或项目库里没有这一行，就拒绝，不写。时间轴是占位，或这一行现在能播（非空地址，或带字节的 Blob），也拒绝，不写。状态写着有文件、但库里没有地址也没有字节，允许去掉。
2. 先改每一份碰到的 `.jyd`，再改项目库。只扫项目目录里的 `.jyd`，不进子目录。一份文稿一次事务：语段和锚点的 `media_id` 改成 `__unknown_media__`，语段带上新的 `updated_at`，锚点不改时间；删掉这条录音上的轨道行。然后项目库一次事务：来源记录清掉 `media_id` 并写下 `updated_at`，删掉录音行。
3. 全部提交后再读回。录音行不在了。原先挂着的来源还在，而且不再挂这条录音。改过的语段和锚点读回是 `__unknown_media__`。轨道行不在了。读回失败不撤销。中途后一份文稿失败时，先改过的文稿留着，录音行也留着，再试可以接着做。
4. 不删磁盘上的音频文件，不改文稿的 `meta.audio_id`。句段元数据和快照表还没进文件夹格式，这一刀不建这些表，也不删它们。

## 影响

- 存储接口的 SQLite 实现按这个顺序写。浏览器里的 Dexie 仍是一次事务，并继续删那些表。
- 文稿改挂录音仍是下一刀。

## 被放弃的备选方案

1. 先删项目库里的录音行，再改文稿。后一步失败后再试会当成录音不存在，文稿却还指着它。
2. 把两个库 ATTACH 成一个事务。ADR-0060 第 4 条不这么做。
3. 为了删句段元数据和快照，先把这些表建出来。表还没定，不在这一刀造。
