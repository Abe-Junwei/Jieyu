# ADR 0089：分析代际、曾经接受与恢复写入

## 状态

accepted。用户 2026-10-25 确认用代际判断过期、保留曾经接受的事实，并把恢复写成一次新的写入；同日补齐文稿代际、重复接受、正文一致才可恢复、备注与链接冲突，以及待复核快照与新建议的区分。本篇不改 [ADR-0088](./0088-desktop-sqlite-domain-landings.md) 的正文。与本篇冲突的句子以本篇为准。不改 `schema.ts`，不扩大 [ADR-0085](./0085-desktop-project-one-sqlite.md) 的 M1 验收。R1 的字段编码、R5 的附件文件协议和 R6 的逐列空值不在本篇决定。

## 背景

ADR-0088 第 4、6、7 条已决定：转写正文改变时，旧分析成为待复核候选并卸下当前投影；消失节点上的链接和备注显式卸下；接受候选时核对生成时的图指纹。图指纹只覆盖图对象。文稿删除后再恢复时，语段和图都可以与删除前相同。`accepted` 若同时表示「曾经接受」和「当前正在使用」，后来改回相同图内容就无法分辨。待复核快照若与新分析建议共用「待定」状态，提交新建议会把为恢复保留的快照改成拒绝。

## 决策

1. 文稿代际沿用 ADR-0087，只增不减；恢复文稿不把它拨回。语段分析代际也是只增不减的整数。推进它的写入是：转写正文改变、对已接受分析的人工编辑（含词形、gloss、词类）、写入已接受分析的导入、建议的首次接受、恢复旧分析。查看、生成建议、把同一投影再重建一遍、对已经接受的同一条建议再次接受，都不推进它。

2. 分析建议和待复核快照在生成时保存文稿代际、语段分析代际和图指纹。后台任务在启动时保存与其目标相应的这些凭据。结果回来时用当时保存的凭据检查，不改读最新代际。

3. 接受建议，以及后台任务把语言内容写回，都在同一次事务里先检查再写入。检查是：文稿当前可写；文稿代际相同；操作落到语段分析时，语段分析代际相同且图指纹相同。任一项不符，整次拒绝。

4. 建议上的 `accepted` 只表示它曾经被接受。不把这条事实改写成 `rejected`。当前正在使用的是语段上的当前分析图，不靠图内容是否相等来判断。一个语段至多一份当前分析图，可以留下多条曾经接受的建议。这收窄 ADR-0088 第 7 条「至多一条 accepted」。

5. 对已经是 `accepted` 的同一条建议再次接受，只返回已接受。不重新应用其内容，不推进语段分析代际。要把它重新用作当前分析，走恢复，并按决策 3 核对当前凭据。

6. 转写正文从旧句改为新句时，仍按 ADR-0088 第 4 条留下待复核快照并清空当前图、卸下实时投影。快照保存它对应的转写正文、完整图、当时的投影、词义链接，以及目标落在这些节点上的备注正文。当时的投影只作历史证据。词形、gloss 或词类的修改只更新当前分析并推进语段分析代际，不另存可恢复快照。

7. 待复核快照和新分析建议是两种种类，可以共用存储。提交新建议时，该语段其余待定建议改为 `rejected`。待复核快照不进入这组状态，也不被这次提交改写。保存快照不是用户拒绝了一份建议。种类决定展示和保留。

8. 查看快照不改当前分析、转写正文、链接、备注和两种代际。

9. 恢复分析是一次新的写入，不修改转写正文。只有快照保存的转写正文与当前转写正文一致时，才允许直接恢复。正文不同时仍可查看；提交前要经过明确的重新对齐或编辑。连转写正文一起恢复是另一种操作，影响范围不在本篇。

10. 允许的恢复在同一事务内完成：先把当时的当前分析收成一条待复核快照；再检查快照引用的词条、义项和目录行是否仍满足这些链接。不满足则整次拒绝并列出问题，不自动复活，也不猜测替代对象。通过后写入被恢复的图和词义链接，并按完整图合同生成当前投影、再与图核对。快照中的投影不成为第二份真值。语段分析代际加一。同一个备注 id 若在快照之后已被编辑，保留现有备注；快照里的正文只供查看。卸下的链接和备注改为可查询的脱离关联。脱离关联不是一条指向已经不存在的节点的有效关联，也不删除这些记录。这收窄 ADR-0088 第 6 条：卸下必须留下可查询状态。

## 影响

- 共同提交入口仍等 R1 字段合同确认后再实现。本篇不实现该入口。
- 实现该片时，代际、种类和脱离关联进入当时的 `schema.ts`，只重建合成项目。打开约束对不上的文件直接拒绝。
- 验收要覆盖这条流程，而不只是首次接受后重开：改正文或词项后旧建议被拒绝；删除文稿并恢复后，删除前的建议和任务仍被拒绝；再次接受不覆盖后来的编辑；正文不一致时恢复被拒绝；后来改过的备注保持现有正文；引用已失效时整次拒绝；新建议不把待复核快照改成拒绝。

## 被放弃的备选方案

1. 候选只保存语段代际和图指纹。删除文稿再恢复后，未改的语段仍会接受删除前的候选。
2. 用图内容相等判断当前正在使用。
3. 再次接受时重新应用内容并推进代际。
4. 把对应旧句的图和跨度直接放到新的转写正文上。
5. 用快照里的旧备注正文覆盖后来的编辑。
6. 卸下时删除记录，或留下指向不存在节点的有效关联。
7. 让快照投影和当前图同时充当真值。
8. 提交新建议时把待复核快照改成 `rejected`。
9. 每次词项编辑都保存一份可恢复历史。
