# ADR 0101：桌面视觉方向重新探索，设计稿改用 Superdesign

## 背景

用户在 2026-11-15 确认：Penpot 稿的问题既在工具（画得慢、页面稿不像真实应用），也在风格（墨色主按钮、中性灰选中、青色焦点这套视觉不满意）。在知道 ADR-0099 视觉基线、`DESIGN.md` 规范和已定稿的转写板 51–61 之后，用户仍选择全部重来，不只换工具。

## 决定

1. **设计稿只有一个来源：Superdesign。** Penpot（00–61）、Stitch、Figma 稿保留为历史参考，被新稿替换的部分不再作为实现依据。
2. **视觉方向重新探索。** 替换 ADR-0099「Penpot 00–18 是视觉与局部交互基线」这一句。ADR-0099 的 R01–R12 产品要求不变，新稿必须满足，尤其是 R02 草稿与离开、R04 时间轴与 IGT、R11 窗口与无障碍。
3. **`DESIGN.md` 仍是 UI 视觉权威（ADR-0100 不变）。** 新方向获批之前，现行 `DESIGN.md` 和 `tokens.css` 继续有效，代码不跟着设计探索改色。获批后重写 `DESIGN.md`；新配色作为新外观注册进 `theme.ts` / `tokens.css`，不覆盖用户已有的外观选择。
4. **与风格无关的工程规则保留。** 包括：语义 token 命名；主操作、选中、焦点分开表达；可见容器边框最多两层；按钮和单行输入默认 32px、紧凑 28px，点击目标至少 24×24；字号放大不裁切；IPA 字体只用于研究内容；时间码等宽且固定 LTR；图标走现有 Lucide 入口；复用现有组件，不另建平行组件库；文案走字典；正文对比度 ≥ 4.5，焦点和控件边界 ≥ 3。
5. **流程：约束 → 小范围探索 → 规范 → 全套方向稿 → 逐片精稿。**
   - 约束：先写与风格无关的工程规则、现有组件清单和桌面范围，不定颜色。
   - 小范围探索：只画工程夹页和转写页，出 2–3 个方向，由用户选定一个。
   - 规范：从选定方向整理 token（颜色、字阶、间距、圆角）和组件状态表（按钮、输入、列表行、标签页、菜单、对话框、提示条的默认／悬停／选中／焦点／禁用／出错，亮暗两套），核对比度后写进 `DESIGN.md` 并注册为新外观。规范不能先于方向。
   - 全套方向稿：用规范铺开标注、词典、语料、分析复核，只核整体一致性。
   - 逐片精稿：按四页切片逐片定稿，实现第 N 片时设计第 N+1 片。切片 1 的 Penpot 精稿（板 51–61）重新打开：新的切片 1 精稿定稿前，涉及布局和视觉的任务暂停；不依赖布局的数据链、`desktopCall` 接线和测试可以继续。
6. **Superdesign 导出的 HTML 只作参考，不进代码。** 稿中只用合成数据，不上传木雅语料。

## 未选方案

- **只换工具，保留 `DESIGN.md` 风格**：不需要新 ADR，切片 1 也不受影响，但保留了用户不满意的风格。
- **继续用 Penpot**：工具本身是问题之一。

## 影响

- 四页实施清单中切片 1「精稿已定稿」改为未完成；切片 2–6 的精稿改在 Superdesign 中做。
- 首发设计验收清单与各规格中的 Penpot 板号，在对应新稿定稿后转为历史引用。
- 新方向获批时，`DESIGN.md` 中指向 Penpot 的段落（§7 转写主工作区、§9 目录）随之重写。
