# 0044 — 目录按项目分开，跨项目不共用

## 背景

词条、说话人档案、正字法、语言记录、音位、标签、文献、地点、语法文档、自定义字段和结构规则原先是全库一份。打开另一份项目会看到并改到同一条记录。ADR-0034 因此不把词库放进协作快照。ADR-0043 只把说话人名单写在项目上，档案行仍然全局。

## 决策

1. 这些记录带项目编号（`textId`，结构规则用已有的 `projectId`）。列表、搜索和新建都只碰当前项目。
2. **（2026-10-09 修订，rev5 4.2-9，切片 2B-B）归属在写入时强制。**
   - 每个目录行都必须带项目编号。统一写入校验（4.4）拦下缺编号或编号为空的 `put`、`bulkPut`、`update`、`modify` 和导入；服务层在没有项目时直接报错（“请先选择项目”）。
   - 不再有“第一次读取时认领”：读操作（列表、搜索、解析）从不写库。没有项目时，读出来是空的。
   - 一份项目的行不能拿到另一份项目里用（例如给 B 的句段指派 A 的说话人），会报归属不符；要复用就复制一行。
   - 没有活动项目时（D11），词库、语言目录、正字法、结构规则等页面只显示“请先选择项目”和返回项目列表的入口，页面本身不挂载，所以不读也不写目录。
   - 系统模板只放在代码里，不属于任何项目，ID 带版本号（如 `system.leipzig-structural.v1`）：
     - 数据库里没有 `scope: 'system'` 的行；任何目录表都拒绝写入 `system.*` ID。
     - 列表 = 代码里的系统模板（只读，带系统标记）+ 本项目的行；解析 ID 时先查代码，再查项目行。
     - 要修改就先“复制到项目”：生成新 UUID，记下 `derivedFromSystemId`，再改副本。
     - 导出包只写引用（manifest `systemRefs`），不写模板本身；导入预览列出当前代码解析不了的引用。
     - 冻结点之后，已发布的系统模板 ID 不再改内容；要改就发布新 ID（如 `.v2`）。
3. 同一名字的说话人、同一词头的词条，在另一份项目里是新的一行。
4. 协作快照带上该项目的这些行，恢复时先删掉该项目的旧行再写入。其它项目的行不动。AI、审计表仍然不进快照。
5. 内置语言代码和内置正字法种子仍是只读模板，不是某一份项目改过的档案。

## 被放弃的备选方案

- **继续全库一份，只在界面上隐藏**：改名和编辑仍然写到别人的项目。
- **给词条整库复制进每次快照**：会把 A 的词库写进 B。按 `textId` 过滤之后不需要。
- **旧行在第一次读取时归到当前项目（原第 2 条）**：读操作会写库，系统模板也会被第一个项目认领（rev5 N13）。D9 不要求兼容旧数据，所以改为写入时强制。
- **“待归属”收件箱 / 个人库作用域**：D8 已作废，D11 不提供个人库；没有项目时只能先选项目。

## 影响

- 本决定取代 ADR-0034 里「快照不含词库 / 语言 / 正字法」和 ADR-0043 里「说话人行全局」这两句。快照仍不整库覆盖。
- 已知限制：语言覆盖行、内置正字法覆盖行和 LIFT 词条沿用全局 ID 作主键。同一个 ID 只能由一份项目持有；另一份项目再写同一 ID 会报归属不符，不会悄悄认领或覆盖。
