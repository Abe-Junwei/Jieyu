# ADR 0080：会话和消息留在项目库

## 状态

accepted。#275 的存储接口继续写 SQLite。本篇不改已接受 ADR 的正文。

## 背景

迁移脚本已经把会话和消息建在项目库里。活的会话行还要记下创建时间和更新时间，消息行也要。引用、推理正文和上下文快照没有进迁移用的那几列。

## 决策

1. 会话和消息都在项目库。不进 `.jyd`，不进 userData。
2. 会话列维持迁移已有的那些，另加可空的 `created_at` 和 `updated_at`。消息列同样另加这两列。迁移的写入和读出不碰这两列，所以旧的迁移对象不变。
3. 列出或改一条时，项目编号、创建时间或更新时间是空的，就不改。模式、角色或状态不在已定的那一组里，也不改。
4. 改标题、改一条消息的正文、清空一个会话的消息，各是项目库里的一次事务。清空只删这个会话的消息，会话行留下，并改 `updated_at`。提交后读回。读回失败不撤销。
5. 消息行不存引用、推理正文和上下文快照。

## 影响

- 存储接口的 SQLite 实现按这个规则读和改。浏览器里的 Dexie 仍走原来的会话写入。
- 其余还没实现的存储方法仍拒绝。

## 被放弃的备选方案

1. 把会话放进 userData。项目库的迁移表已经按项目编号记下会话。
2. 为了存引用和推理正文，给消息行加 JSON 列。那些正文还没定进这一行。
3. 让迁移读出把空的时间列也带上。空列不出现，来回对照才稳定。
