# ADR 0086：首发单库集成、有限开放与开发格式

用户在 2026-10-25 的逐项访谈中确定下列范围，并同意评估中的冲突修正。决定已接受，代码尚未实施。旧 ADR 正文保留；与本篇冲突的冻结顺序、旧数据迁入和演练门槛以本篇为准。

## 取消当前旧数据工作，不取消保留责任

取消 #326「旧浏览器库经 JYB 迁入」及其首发阻塞，首发只支持新项目；取消 #281 本次加法迁移演练及其 D14 阻塞。不是把未执行的任务记成验收通过，也不删除现存用户数据、旧库或包。
首发严格拒绝不兼容项目格式，不做旧文件补列或迁移器；未来发布后的格式演进另定，不据此承诺未来永无迁移。JYM/JYT 的有效交换、含音频备份和恢复要求保留。

## 开发格式与首发表集

M1 仍只验证创建文稿/层/语段与正文、关闭重开读回、事务中途失败回滚，不追加删除、录音导入或界面验收。
保留既有首发能力。词典词条、语言/正字法、模型运行记录等存储缺口逐领域核对，必要结构用新 ADR 确认后再接替；不能塞进 settings_json 规避建模，也不能因 ADR-0085 暂未列出就撤掉用户能力。
D14 前的新格式仅使用可重建的合成项目。新决定允许改变表和字段，结构变化后重建受控测试项目，不为开发文件写迁移器，不覆盖或重置任意已有目录。M1 初始表集不是首发表集冻结承诺。
M4 是内部验证可用闭环，D14 前不向试用者开放真实材料写入。#275 中转写、示例导入与备份的工程验收使用合成等价材料；#313 真实示例的最终试用验收由用户在 D14 后完成，归 #282，不反向阻塞 D14。用户已有语料与旧文件不受“测试项目可重建”授权覆盖；代理仍不读真实语料。

## M4 后有限开放，其他新功能继续冻结

M4 验收项目入口、录音播放、文稿/层/语段编辑及应用重启读回后，允许推进以下清单：

- 首发必需：本机转写 #303–#306、诊断反馈 #312、示例首启导入 #313、发布流水线 #277；既有首发能力的 SQLite 接替、删除恢复、交换与备份。
- 额外允许但不挡首发：LIFT 往返验证 #311、词表音位配列质检 #333、语料标准格式接入 #299；不得加进 #275 或 #282 的关闭前置。
- #298/B7 仍在第二程；其他新功能继续冻结。新增白名单另行确认，不把“词典/语料页”当作无限功能授权。

M4 前继续存储主线、#280、#325、#329、bug 与防丢数据工作；原本允许的纯调研/文档和用户本人制作示例不受阻。不是现在全面解冻，也不再以 #275 整单关闭作为白名单开工条件。

## issue 和冻结的边界

- #275：首发所需的单库集成终验，包括项目读写、既有词典/基础语料等首发能力、转写结果、示例、交换与备份。M1–M4 是子进度；M5/M6 与首发功能真正接通并验收后才完成。
- #325：按 ADR-0087 完成可恢复删除、任务协调、到期清除、录音文件收尾与重新登记后才完成；不是 M4 能列文稿就关闭。现有任务和可控迟到任务先验收写入保护，本机转写接入后复用并回归。
- #280：导入桶指标归零只是已有证据，仍须核对实际业务读写/后台路径接替。#329 随完整场景逐组迁 Electron，不等 #275 整单关闭才准备或迁移。
- #277/#312/#282：安装、更新、反馈与整体发布证据由各自负责，#275 不吞并这些验收。#282 收齐不丢数据、Mac Apple 芯片与 Windows x64 安装启动更新、示例核心流程含本机转写三项硬门槛。
- #259：#275/#325、必要恢复验收与实际业务接替通过，首发表集稳定后才做 D14；不再等 #281/#326，不在 M4 提前冻结。
- 浏览器/Dexie 删除不再等已取消的 #326；仍须 #329 替代验收、生产路径接替和数据保留核对，保留独立 userData 需求与协作代码既有边界。不能只凭导入基线 0 删除实现。

活动执行依据见[单库计划](../execution/plans/desktop-project-sqlite-2026-10-25.md)。相关 GitHub issue 顶部切片与本篇一致；折叠的旧正文不是当前依据。

## 未选方案与原因

保留“#275 完成前不得做首发功能”同时要求 #275 验收这些功能，会循环阻塞；改用 M4 的有限开放门。
开发阶段锁死 ADR-0085 初始表集，会迫使必要数据塞进错误字段或丢掉首发能力；因此冻结前按新决定调整，只重建合成项目。
不把允许提前做的三项工作变成首发门槛，避免白名单扩张等同扩大必须交付范围。
