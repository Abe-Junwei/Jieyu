# ADR 0084：后加的空列是未补全，不是坏行

## 状态

accepted。用户 2026-10-25 要求用扩展再收缩来避开「一行空列让整次列出失败」。本篇不改 ADR-0081、ADR-0082、ADR-0083 的决策正文。

## 背景

ADR-0081 起，新列只加在新建表的末尾，迁移不读，旧库不加列。读到空值就拒绝这一行。列一层时，文件夹里任意一行不完整，整次列出失败，一个编号都不返回。

迁移写出来的旧行，这些列本来就是空的，而且还没有写入路径去补。空因此同时表示「还没补」和「这行是坏的」。建层补偿靠列出前后的差集判断新层有没有落地；整次失败时，它分不清没建成和建成了但读不回来。按编号读只看那一行，列出却被旁边的行拖垮，两条路对「能不能读」给出不同答案。

## 决策

1. 行已经存在之后才加的描述列，列不在或值是 `NULL`，表示未补全。不表示没有这行，也不表示这行是坏的。名称、层类型、内容类型、创建时间、更新时间属于这一类。
2. 坏行是值已经写下、但本身不合法。名称解析失败、不是字符串映射、或里面一条非空字符串都没有；层类型或内容类型不在已接受的集合里；时间字符串解析不了。不编造默认值。
3. 按编号读和列出用同一套逐行判断。没有这行，就是没有。未补全的行，按编号读得到未补全，列出时不放进编号，并计入未补全。坏行只拒绝这一行，列出时不放进编号，并计入坏行，其余齐全的编号仍返回。
4. 同一个编号出现在两份文稿里，仍然整次拒绝，行留下。这是冲突，不是空列。ADR-0082 的归属列也保持原样：没有项目编号不能判断这层属于谁，不能当成未补全跳过。
5. 问「在不在」或「有哪些编号」时，不返回套着整份层定义类型的半份文档。父层、模态、排序等还没有列、也没有写入的字段，不出现在结果里。
6. 写入要在同一次事务里写下这些必填列。补完之前，列出可以是空编号加上未补全的计数。空编号表示没有齐全的匹配行，不表示文件夹读不了。
7. 强制「空列即坏行」要等写入把现有行补完，另写一篇 ADR。在那之前保持可空，不改旧库。
8. ADR-0081、ADR-0082、ADR-0083 已经落地的方法维持现有代码和测试。本篇约束还没实现的方法。层定义的读和列出按本篇实现，不按「任意坏行让整次列出失败」实现。

## 影响

- 存储接口上还没写的列出，要能同时给出齐全编号、未补全行数和坏行数。浏览器里的 Dexie 在实现那一刀时再对齐；这一篇不改它。
- 开关仍默认关。
- 建层补偿在列出失败时仍把原错误抛回。未补全不再占用这次失败。

## 被放弃的备选方案

1. 文件夹里任意一行未补全或是坏行，整次列出失败，不返回已找到的编号。旧行全是空列，列出会一直失败，补偿无法做差集。
2. 把空列读成默认名称、`custom` 或当前时间。那是在补写之前编造数据。
3. 打开旧库时 `ALTER TABLE` 并当场补值。已接受的 ADR 规定旧库不加列。
4. 改写 ADR-0082，让没有 `text_id` 的层被跳过。没有项目编号时不能判断归属。
5. 把 ADR-0083 已落地的 `readProject` 在本篇里改掉。它的测试保持不动，等有写入补全后再单独改。
