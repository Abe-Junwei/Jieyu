# ADR 0060：卡片文件、项目层和跨文件操作的分工

## 状态

accepted。用户 2026-10-16 选定：项目层是共用定义的唯一权威，卡片里另存一份用到的定义副本。本篇补全 [0058-card-sqlite-file.md](./0058-card-sqlite-file.md)，并取代 [0058-indexeddb-two-layer-placement.md](./0058-indexeddb-two-layer-placement.md) 背景与影响里「项目文件夹 = `project.sqlite` + `media/`」「#275 把第 2 条的项目文件夹类都建进 `project.sqlite`」的说法。两篇的其他决策不变。

第 1 条里录音、字节、来源登记的去处，以及第 5、6 条，由 [ADR-0061](./0061-jyd-manuscript-file-audio-stays-plain.md) 取代；下面的决策正文不改。

这是产品和格式决定，不表示工程可以发布。可发布以 `docs/execution/specs/card-sqlite-file/` 的原型和验收为准。

## 背景

两份 0058 同日接受。卡片那份把音频、文稿、语段放进每卡一个 SQLite 文件；归层那份仍让项目内容整体进 `project.sqlite` + `media/`。实现 #275 的人无法同时满足。卡片复制到另一个项目、索引丢失、局部删除和大音频这几件事，也还没有写清谁负责。

## 决策

1. **按归属分库。** 归层那份第 2 条里属于项目文件夹的行，再按归属分：只属于一张卡片的行（录音、它的字节、来源登记、文稿、层、语段、锚点）进那张卡片文件；被多张卡片共用或属于项目本身的行（项目行、语言、正字法、说话人、词条、项目记忆、项目 AI、`model_runs`）进项目文件夹里的项目库。每张表的归属在规格里逐表写，不在这里抄表名。
2. **共用定义。** 项目库是语言、正字法、说话人的唯一权威。卡片文件里另存一份它用到的定义副本，每次写这张卡片时刷新。同一项目里打开卡片时不读副本。副本只在把卡片导入另一个项目时用来列出差异，由用户映射或导入；不静默改目标项目的配置。
3. **索引是缓存。** 卡片清单（卡片 id、路径、显示名、是否在「已隐藏」）和看板上的时长、句数、进度都从卡片文件算出来，属于归层那份的 `derived`，放在 userData。丢了就扫项目文件夹重建，重建不改任何卡片 id，也不写回卡片。
4. **跨文件操作有操作 id。** 一次用户动作如果改到两个卡片文件、改到文件位置或用到系统垃圾箱，就是一条有记录的操作：开始时分配操作 id，并预先分配要新建的卡片 id；每一阶段写下完成标记。记录放在项目文件夹里，跟着项目走。重启后按操作 id 续做，或停在可以解释的待处理状态，不按同名重做，不再造第二张卡片。SQLite 事务只管一个文件；WAL 模式下附加多个库的事务也不是整体原子，所以不把这类操作写成一次事务。
5. **音频分块存。** 卡片里的音频字节按固定大小分块存成多行，不存成一个值。SQLite 单个值默认上限约 1 GB；波形允许的 3 小时 48 kHz 双声道 16 位 WAV 约 2.07 GB。
6. **局部删除先写新文件。** 从卡片里拿掉音频或一份文稿时：先把拿掉的部分写成一张可独立打开的卡片并读回，再用 `VACUUM INTO` 写出不含这部分的紧凑原卡并读回，然后替换原卡，最后把拿掉的那张送进系统垃圾箱。空间不够时停在替换之前，原卡不动，提示删除没有完成。界面只报告文件实际变小了多少，不把删掉的行说成已释放空间。
7. **同名合并只在提交时判断。** 导入或改名提交之后，在同一条操作里判断唯一同名并合并。看板重新加载只读结果，不触发合并。合并记下原来的卡片 id，以便拆开。

## 影响

- #275 建两类库：项目库和卡片文件。表的归属清单、音频分块大小、操作记录的格式写在规格里，并由 better-sqlite3 原型验证。
- 跨项目导入卡片时，重新分配卡片和内部对象 id，原 id 作为来源保留；从系统垃圾箱还原回原项目时保留原 id。
- 同名的规范化规则、匹配范围（是否包括「已隐藏」）、并发导入时的唯一性，未在本篇定，规格里先写成待定项。

## 被放弃的备选方案

1. 卡片只存定义 id。导入到另一个项目时没有原定义可以对比。
2. 定义只放在卡片里。同一项目里同一种语言会出现互相不一致的定义。
3. 把卡片索引放进项目库并当作权威。索引会成为第二份内容真源，丢了也无法从卡片重建。
