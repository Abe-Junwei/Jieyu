# ADR 0093：AI 聊天消息的引用、推理与导出

## 状态

accepted。用户 2026-10-26 确认。本篇仅替代 [ADR-0080](./0080-conversations-stay-in-project-library.md) 第 5 条对**引用和推理正文**的排除；上下文快照仍不存入消息行。ADR-0080 的会话归属、事务和清空规则仍有效。本篇是待实施合同，不表示新库消息读写或导出入口已经落地。

## 背景

旧聊天消息有引用和模型返回的推理正文，聊天界面已有默认收起、按需展开的推理展示。新单库 `messages` 目前只有身份、会话、角色、正文和创建时间；普通用户可用的聊天导出入口尚不存在。若直接沿用 ADR-0080 的排除规则，关库重开后将失去回答依据和推理。旧流式路径会定期保存正文，但推理要到最后才保存，不满足崩溃后的部分读回。

## 决策

1. **消息保留引用和模型实际返回的推理正文。** 引用保存原类型、标识、简短标签和已有的短摘录；不保存整份生成上下文。推理为空或提供方未返回时不伪造内容。状态、生成来源、模型和错误信息可随消息领域按字段修订接替。其他旧消息字段须逐项决定，不因本篇自动进入新表。
2. **历史引用指向当前目标。** 目标仍在时可以打开其当前内容；目标已不存在时显示“引用已失效”。保留历史标识、标签和短摘录，不按文字猜测替代对象，也不把短摘录当成可恢复的正文真值。核验和跳转按引用类型各自的真实身份进行。
3. **部分回复也是消息。** 用户停止或生成失败时，保留已收到的正文、引用和推理，并标明相应状态。重新生成写新消息，不覆盖原消息。生成途中定期持久化已收到的正文和推理；进程异常退出后，重开保留最后一次成功提交的内容并标为“已中断”，不自动续做。最后尚未提交的片段可以丢失。单次保存仍按项目库事务执行。
4. **同生命周期。** 引用和推理随消息删除、清空会话和项目备份恢复；不另存一份脱离消息生命周期的副本。历史聊天中的推理默认收起，可由用户展开。
5. **提供普通用户可用的聊天导出。** 用户选择 JSON 或 Markdown，导出当前整段会话，按消息顺序包含用户发言、AI 回复、状态、引用的原标识/标签/短摘录，以及已保存的推理正文。JSON 保留结构；Markdown 供直接阅读。导出读取一次确定的会话快照，不改聊天记录。没有上下文快照的字段。导出时不得把“引用已失效”伪装成可打开的当前目标。

本篇不设 AI 写入总入口。写入提案、审批和领域执行继续分开。

## 被放弃的备选方案

1. 继续永久排除引用和推理，导致重开后回答依据和推理丢失。
2. 为了保留引用而把整份上下文快照写进消息。
3. 停止、失败或崩溃后丢掉已经提交的部分回复，或自动重试生成并覆盖原消息。
4. 只导出单条回复，或只提供一种文件格式。
