# ADR 0075：录音行写在项目库

## 状态

accepted。#275 的存储接口继续写项目库。本篇不改已接受 ADR 的正文。

## 背景

存储接口要按项目保存并读回一条录音的文件名、时长和字节在不在。音频字节已经定了是文件夹里的普通文件（ADR-0061）。迁移用的 `audio` 表只记文件路径和哈希。来源记录要挂录音时，还分不清这行在不在、属不属于本项目（ADR-0074）。

## 决策

1. 项目库新增 `media_items`。记下项目、文件名、可选地址、时长、`details_json`、是否离线缓存、访问限制、创建时间、时间轴种类、字节位置、是否可播、内容大小和内容哈希。不进 `.jyd`，不进定义副本。不并进迁移用的 `audio` 表。
2. `details_json` 是 JSON 对象。里面带音频字节就拒绝，不写。字节仍在普通文件里。
3. 保存、按项目列出、列出编号，都只动这一份项目库。编号去掉空白后是空的，就拒绝，不写。已有同一编号就整行覆盖，包括项目编号。提交后读回整行。读回失败不撤销。
4. 来源记录挂录音时读这张表。没有这一行就是录音不存在。`text_id` 不是来源那一项的项目，就是另一项目的录音。空编号仍只清掉来源上的关联。
5. 这一刀不改文稿的 `meta.audio_id`，不删磁盘上的音频文件，也不做去掉一条空录音。

## 影响

- 存储接口的 SQLite 实现按这个顺序写。浏览器里的 Dexie 仍然把整行放在 `media_items`，表也不变。
- 一份文稿只关联一条音频，仍按 ADR-0061。挂上和替换不在这一刀。

## 被放弃的备选方案

1. 把音频字节写进 `details_json`。字节已经定了留在普通文件里。
2. 把录音行放进 `.jyd`。一个项目里的录音可以被多份文稿引用，行跟项目走。
3. 把时间轴状态塞进迁移用的 `audio` 表。那张表只记文件路径和哈希。
