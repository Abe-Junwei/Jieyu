# ADR 0072：正则拆分写在一份文稿里

## 状态

accepted。#275 的存储接口继续写 `.jyd`。本篇不改已接受 ADR 的正文。

## 背景

正则拆分在 Dexie 里一次事务改锚点、语段和正文，提交后再读回起止时间、更新时间和正文。文稿文件里的语段行还没有起止时间、更新时间和所属项目，正文行也还没有更新时间和所属项目。

## 决策

1. `.jyd` 的 `units` 增加 `text_id`、`start_time`、`end_time`、`updated_at`。`unit_contents` 增加 `text_id`、`updated_at`。迁移没写过的格子留空。锚点仍用已有的 `time`。
2. 一次正则拆分只写一份 `.jyd`：已有行所在的那一份，或者文件夹里唯一的一份。跨两份文稿就拒绝，不写。这不是项目库和文稿各写一次的说话人分配。
3. 写入列出的项目编号多于一个，或已有行的 `text_id` 对不上这次的项目，就拒绝，锚点也不写。`text_id` 空着的旧行不挡这次写入。
4. 调用方点名的句段，其下已有的 `segment` 子行在同一次事务里改成句段的新起止时间和更新时间，再写入调用方算好的锚点、语段和正文。提交后读回。读回失败不撤销。

## 影响

- 存储接口的 SQLite 实现按这个顺序写。浏览器里的 Dexie 仍然是一次事务，表也不变。
- 正文列原来就是 `NOT NULL`。这次没带正文时写成空串。

## 被放弃的备选方案

1. 把起止时间只留在锚点上，不在语段行上记。读回要比对的是语段自己的起止时间。
2. 跨两份文稿时造一条文件操作记录再接着写。一次拆分碰到的行应该在同一份文稿里。
