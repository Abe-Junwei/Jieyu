# ADR 0052：工具结果的三步保持分开

## 状态

accepted。不改 [ADR-0025](./0025-ai-propose-changes-b2-rollback-boundary.md)。

## 背景

一次架构审查建议把工具执行、审计和会话记忆收成一次提交。人工确认、自动执行和 `propose_changes` 的后续并不相同。

`src/ai/runtime/commitToolEffects.ts` 只在工具结果之后写入会话记忆，不写项目事实，也不代表业务写入、审计和回滚的一次原子提交。人工确认在回滚后直接返回。自动执行在回滚后返回一条错误结果。切换会话时回滚一次，并且不写会话记忆、不标记已执行。

## 决策

1. 工具结果保持三步：执行结果、审计之后才 `markExecutedRequestId`、会话记忆。三步不收成一个模块。
2. `commitToolEffects` 仍只写会话记忆。
3. 切换会话时的回滚留在人工确认和自动执行各自的调用方。不因为两处都回滚一次就抽成同一个函数。
4. `propose_changes` 的反向回滚，以及仅在全部子步成功后标记已执行，仍按 ADR-0025 留在确认执行路径。
5. 现有顺序测试保持为业务保证：成功时 `apply → audit → mark`；失败不标记已执行；切换会话时执行一次并回滚一次。只检查最终状态不能代替这些次数和顺序。

## 影响

- 架构审查不要再建议一个模块同时完成执行、审计和会话记忆。
- 架构审查不要再建议把切换会话的回滚抽成人工确认与自动执行共用的函数。
- ADR-0025 的落位和回滚规则保持不变。

## 被放弃的备选方案

1. 新增一个模块，按同一次提交跑完执行、审计和会话记忆。
2. 把切换会话时的回滚抽成一个共享函数。人工确认与自动执行在回滚后的返回不同。
3. 为了让测试只断言最终存储，删掉有业务含义的次数和顺序断言。
