# ADR 0090：完整分析载荷、全项目字段与失效引用

## 状态

accepted。用户 2026-10-25 确认 R1 设计第 13 节（审阅版 `R1-contract-2026-10-25-r3`）的字段合同和切片 C1–C8，并确认本篇对既有 ADR 的替代范围。同日决策 11 补上再导入：更新 id 的拒绝边界、关系的显式删除、失配跨度不作为已验证对齐。例子在规格 E1–E16。字段清单留在该规格，不在本篇重复。不改 ADR-0088、ADR-0089、ADR-0087 的正文。与那些篇冲突的句子以本篇为准。本篇不改 `schema.ts`。R5 附件协议和 R6 逐列空值不在本篇。

## 背景

ADR-0088 已决定已接受图是分析真值，线性词项和词义表是投影。单字符串投影不能保住多语词形、gloss 和来源。自定义字段当时只接语言记录。ADR-0088 第 9 条在仍有词义链接、例句或出现引用时拒绝删除词条或义项。ADR-0089 第 10 条在快照引用不满足时整次拒绝恢复。

用户选择：完整载荷为真值；已定义字段和未解释来源扩展分开；被引用目标可以显式删除并留下失效引用；删除字段定义时清除当前库内对应历史。这些取舍不在原篇里。

## 决策

1. **完整载荷为真值。** 词项节点保存严格校验的领域载荷，词义链接的身份和来源跟随关系。显示由完整内容生成，带显式派生标记，只重建带标记的副本。未标记的非线性语义和独立备注不被线性重建替代。实验键 `jieyuLinear`、`jieyuProvenance`、`jieyuLexemeLink` 不是协议，生产写入见到它们整次拒绝。编码以已确认的 R1 设计第 13 节为准。

2. **三类内容分开。** 内置领域载荷、已定义自定义字段、未解释来源扩展各有合同。未知扩展只隔离保留。理解并转换后才进入已定义字段。

3. **身份。** 首次接收的新投影节点和持久词义关系分配项目 id，并同次映射已知引用。内部编辑和纯重排沿用 id。真正拆分或合并时旧节点退出，新节点用新 id。旧链接和备注脱离保留，不按词形或位置猜继承者。

4. **来源与编辑分开。** 保留原生成或导入来源。真实修改另记操作者、时间和实际字段。局部编辑不把整词标成已审校。

5. **字段管理共用合同，不共用一张值表。** 定义属于项目和一种对象类型。同名不合并，复制不共享 id。选项用稳定 id。语言值留在 `languages.custom_fields_json`。词条和义项的自定义值留在 `jieyu_json`，不进 `entry_json`。图节点和关系的值留在图 JSON。其余已登记宿主用规格写明的值表。不把 DMLex 正文或语言具名 JSON 迁走。宿主清单以规格第 13.3 节为准，共 17 类。

6. **不兼容定义修改要显式迁移。** 当前值转换并全部校验后，与定义同事务提交。历史保留当时的值和定义。恢复要转换后再校验。旧候选保留原文，旧接受凭据失效，不重签。

7. **删除定义是当前库内的永久清除。** 一次事务清掉规格第 13.5 节列出的载体，包括候选和快照里的对应值。快照标明已清除，不把剩余内容标成原来的图指纹，不改写“曾经接受”。不追删项目文件夹以外的包。再导入可能带回。

8. **新建引用必须有效；已有引用可以失效。** 这替代 ADR-0088 第 9 条里核心词义链接一律阻塞删除的部分，也替代 ADR-0089 第 10 条里“核心词义或自定义引用因目标缺失就整次拒绝恢复”的部分。显式删除词条、义项或自定义引用目标时，保留原身份和来源，标记失效。同 id 恢复并校验通过后重新有效。同名新 id 不接替。失效引用不计入有效链接、计数和必填基数，也不阻塞无关编辑。例句引用和出现引用仍按 ADR-0088 第 9 条，本篇不放宽。类型矛盾、跨项目、缺父节点和其他图结构错误仍整次拒绝。

9. **代际。** 推进语段分析代际的写入仍是 ADR-0089 第 1 条，并补上跨度、链接的指向、角色、置信度，以及自定义字段值的人工编辑。只改 `index` 以及因此重写的 `next` 不推进代际，也不把未知扩展标成需复核；这次写入仍核对旧图指纹，成功后指纹改变。只改显示名同样不触发复核。

10. **一次事务。** `analysis.apply` 与 `units.updateText` 共用内部原子边界。图、投影、链接、正文失效、代际和相应快照同成败。调用方提交业务操作和预期凭据，不提交整份快照来覆盖其他已保存内容。实施顺序是规格第 13.8 节的 C1–C8。第一次改表把 `user_version` 从 4 升到 5，其后每次改表再加一。旧文件只拒绝，不补列。

11. **再导入。** 图节点不另存外部标注 id，不按词形或位置猜测。语段由操作里的 `unitId` 指定；EAF 语段行仍按 ADR-0088 第 16 条用 `external_ref`，该列若另加，`user_version` 再加一。5 只是第一次改表。对上语段之后，带项目节点 id 的局部更新，没提到的节点、关系和字段留下。没有项目 id 的词才新建；用户再次导入同一份无 id 材料会再追加。预览给出更新、追加、删除的数量。提交后 IPC 失败按 ADR-0085 第 4 条是结果未知，不自动重试。更新或删除的 id 不在该语段图上，或同一请求对同一 id 既更新又删除，整次拒绝，不降级为新建。删除节点时，以它为端点的关系必须在同一请求里显式删除，否则整次拒绝。换正字法键不改跨度；跨度与当时词形不一致就是失配，显示、导出和投影不把它当成已验证对齐。本篇仍不改 `schema.ts`。

## 影响

- 可以按 C1 起实现 M5-C。本篇不实现。
- 当前库的 `lexeme_id` 外键仍在。去掉它是 C7，在那之前删除仍会被这道外键挡住。决策 8 从本篇接受时起是规则，代码要到该片才跟上。
- 规格在实施完成前仍是字段编码的载体。完成后按 ADR-0051 删除规格，本篇保留决定。

## 被放弃的备选方案

- 继续用 ADR-0088 第 9 条挡住一切删除，直到引用被手工改完。用户选择保留失效引用。
- 把所有自定义值收进一张通用表。语言 JSON 和 DMLex 边界已由 ADR-0067、ADR-0068、ADR-0088 决定，本篇不改落点。
- 把实验 JSON 键冻结成协议。那只证明容器能往返。
