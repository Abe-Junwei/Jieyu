# ADR 0143：命令行只是操作合同的另一个入口

## 背景

需要命令行给三类人用：用户批量或脚本操作、外部 AI 调用、排错。桌面写入已经全部走 `src/db/desktop/operationContract.ts` 的 `desktopOperations`，由 `desktopCall.ts` 的 `runContract` 统一校验、清栈和执行。同一项目只能有一个写者（ADR-0100 E08），撤销栈只在主进程内存里按会话保存，`better-sqlite3` 按 Electron ABI 编译。

`openProject` 不是只读的：库不存在会新建，打开时还会清理附件临时文件。

## 决定

1. **不另写业务逻辑。** 命令行的写命令只调用 `desktopOperations` 里已有的操作，走同一份校验、事务和回执。缺的能力先补进操作合同，再从命令行暴露。读命令只调用现有读函数和导出函数。
2. **用应用自带的二进制运行，关闭 `runAsNode`。** 不要求用户另装 Node，也不另编一份原生模块。打包时关闭 Electron 的 `runAsNode` fuse，不让签名后的应用被借来跑任意脚本；CLI 走主进程无窗口模式。Windows 打包版拿不到终端输出时，加一个只转发参数和输出的小启动器。
3. **面向最终用户。** macOS 在应用菜单提供「安装 jieyu 命令」，Windows 安装器提供勾选加入 PATH。人读输出跟应用界面语言一致，文案走字典；`--json` 字段名固定英文。
4. **先只开放只读和诊断。** 第一程只有读、检查、导出和诊断包。只读命令另走只读打开：库不存在报错，不建库，不清理附件，不做打开时修正，文件字节保持原样。格式版本不是当前值时按 ADR-0140 报「不是解语项目库」，不改写。
5. **单写者不放宽。** 只读命令也先取项目锁。锁被占用（应用正打开该项目）时以固定退出码失败，提示先在应用里关闭项目，不排队，不绕锁读。应用开着时转交给它执行，等第三阶段另定。
6. **撤销语义。** 以后转交给运行中应用的写入，进入该会话的撤销栈，写后界面整体刷新。应用没开时的独立写入没有撤销，只靠操作 id 和回执可查。缺操作 id 或回执的操作不开放给独立写入。
7. **外部 AI 只出候选。** 外部 AI 通过 MCP stdio 接入，工具定义由操作合同生成。AI 产生的写入按 E11 作为候选，经人工采纳才落库，不提供直接写入。应用内智能体运行时仍只有 ToolLoopAgent（ADR-0056）；MCP 服务是对外接口，不是第二个运行时。
8. **输出约定。** 默认给人读；`--json` 输出带 `schemaVersion` 的稳定结构。stdout 只放结果，日志和进度放 stderr。退出码固定：0 成功，1 内部错误，2 用法或输入无效，3 项目被占用，4 不是解语项目库或格式版本不符，5 一致性检查不通过。
9. **诊断沿 E13。** 只输出操作标识、时间、版本、错误类别和计数，不输出原文、录音、gloss、词典正文和密钥。检查只报告，不原位修复。诊断包是单个 JSON 文件，含项目检查结果、应用版本、系统信息和本机技术日志摘录；先预览再写出，不上传。
10. **本机技术日志。** 用 electron-log 写到系统日志目录，按大小轮转，约 5MB×3。记录启动、打开和关闭项目、每次写操作的操作名、操作 id、耗时和结果、失败的错误类别与版本；不记入参内容。
11. **随首发交付，不阻断。** 按 ADR-0099「其余条件功能按实际启用边界呈现」处理：开发期挂开关默认关；首发前通过两平台打包验收才切默认开，否则保持关，不延发布，也不阻塞 1b 各片。

## 未选方案

- **命令行直接写 SQLite。** 绕过合同的校验、回执和撤销，等于第二套写路径。
- **命令行另开写连接，与应用同时写。** 违反单写者。
- **复用 `openProject` 做只读。** 它会建库和清理附件，读坏库时会改动现场。
- **外部 AI 直接写入。** 违反 E11 的人工采纳。
- **在 CLI 里内嵌第二个智能体循环。** 违反 ADR-0056。
- **保留 `runAsNode`，照 VS Code 用 `ELECTRON_RUN_AS_NODE`。** 更简单、启动更快，但签名应用可被借来跑任意脚本。
- **自写日志。** electron-log 已有轮转和平台日志目录，MIT、无依赖、约 93KB。
