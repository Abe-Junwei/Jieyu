# Design — card-sqlite-file

## 1. 成熟方案扫描 / Research

- 仓库既有模式：ADR-0048 一次业务操作一次事务；文件不进事务。表分类以 `src/db/tableRegistry.ts` 为准。
- 标杆：ELAN、SayMore 让音频和标注文件并排放；Audacity 3 的 `.aup3` 把音频块放进 SQLite，结果是文件大、不缩小、不宜放同步盘。SQLite 官方把单文件数据库作为应用文件格式，用 `application_id` 和 `user_version` 标识。
- 决定：**适配**。音频保持原文件，文稿是 `.jyd` SQLite 文件，声文稿只在看板上组合（ADR-0061）。
- 坑：better-sqlite3 是原生模块，要随 Electron 重新编译；回滚日志模式下大量小写入可能偏慢，要原型测。

## 2. 归属（ADR-0060 第 1 条，ADR-0061 第 1、2 条）

`project_content` 分到两边。下表是本规格的映射，表名变了以登记表为准。

| 去处         | 表                                                                                                                                                                                                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 每个 `.jyd`  | `annotation_documents`（本文稿一行）、`tier_definitions`、`layer_links`、`tier_annotations`、`layer_units`、`layer_unit_contents`、`unit_tokens`、`unit_morphemes`、`token_lexeme_links`（只存词条 id）、`anchors`、`track_entities`、`segment_meta`（可从语段重建）；外加音频引用和定义副本 |
| 项目库       | `texts`（项目行）、`media_items`（音频登记）、`source_records`、全部 `project_catalog`、全部 `project_ai`、`model_runs`、操作记录                                                                                                                                                            |
| 音频原文件   | 音频字节，不进任何库                                                                                                                                                                                                                                                                         |
| 不能整表划定 | `unit_relations`：两个端点都在同一份 `.jyd` 里的，随该文件走；跨文稿的关系一律不存（ADR-0062 第 4 条）。`parentUnitId` 不能跨文稿，不是项目级关系。`user_notes` 跟着它所指的对象：指语段、词、词素的随那份文稿，指项目对象的进项目库                                                         |

`derived` 和卡片清单在 userData。一份文稿同时只关联一条音频。已经同时挂着两条的旧文稿，迁移时按 ADR-0062 第 5 条先列清单，经确认后拆开。

## 3. 定义副本（ADR-0060 第 2 条）

副本包含文稿引用到的 `languages`（及显示名、别名）、`orthographies`、`speakers`。词条、标签、自定义字段、缩写是否进副本，待定。副本只在跨项目导入时用于列差异。

## 4. 操作记录（ADR-0060 第 4 条）

记录在项目库里，一行一个操作 id，字段：动作、预分配的新 id、涉及的路径、已完成阶段。以删除一张声文稿卡片（一个音频加两个 `.jyd`）为例：

| 阶段                               | 失败或中断时的状态                                         |
| ---------------------------------- | ---------------------------------------------------------- |
| 写下操作记录和要送走的路径         | 什么都没动                                                 |
| 逐个送进系统垃圾箱，每送一个记一次 | 已送的不回拉；没送的还在，卡片显示「删除没有完成」，可重试 |
| 更新项目库里的音频登记             | 重开时按记录核对文件是否还在                               |
| 刷新卡片清单                       | 清单可重建，重开时重扫                                     |

导入音频加 EAF：先复制音频并核对 sha256，再写 `.jyd` 并读回，最后写音频登记。任何一步失败，清掉本操作已写的项目内文件，项目外原件不动。

## 5. 认回与缺失状态

哈希标识的是内容，不是某一条音频。两份有意保留的录音可以有相同的 sha256。

- 扫到的文件与「已送走」或「不见了」的登记只有一条哈希相同：认回那个 id。
- 有两条或更多：停下，让用户选。不自动认回。
- `.jyd` 按文件内 id 认回。Finder 复制出的第二份带着同一个 id 时，同样停下。
- 看板上要能区分：文件在、用户主动送进垃圾箱、意外不见了、路径在但字节不在本机（例如同步盘把内容移走）。「已还原」是回到「文件在」的结果，不是第五种状态。

回滚日志模式下，写入过程中会有 `-journal`。关闭并提交之后它才消失。「不用 WAL」不表示运行中永远只有一个文件，也不表示放进同步盘就安全。

## 6. 尚未批准、不能冻结的部分

这些方向已写入 ADR-0062。仍不能据此做 D14 冻结，也不能对真实资料做迁移。

- **一份文稿同时只关联一条音频。** 语段上出现两个 `mediaId` 就拒绝。改挂到另一条音频是替换，每个语段只留下新的那一个。没有语段的文稿可以先挂上一条音频。检查在 `src/db/projectFiles/manuscriptAudio.ts`。
- **父子链接不能跨文稿。** `parentUnitId` 的两端必须在同一份文稿里。检查在 `src/db/projectFiles/manuscriptParents.ts`。
- **备份。** ADR-0046 第 6 条的每日 JYM 仍有效。替换方案未批准。2026-10-16 用合成 WAV 做了一次现有 JYM 的导出、恢复、再读采样，macOS 上 `afinfo` 能打开恢复后的文件（`src/services/jymAudioRestorePlayback.test.ts`）。这证明现有 JYM 能带回可播放字节，不是新的文件夹备份。任何替换仍必须带上可播放的音频字节（相同哈希只复制一次），并再做一次从那个备份目录恢复然后播放的演练。备份放在哪、要不要加密，写进验收。
- **同名配对。** 「已隐藏」里的文件参加「是不是唯一」的检查。唯一的那个在「已隐藏」里时，不暗中配对，返回需要选择。隐藏只影响看板显不显示。
- **迁库。** 优先用保留项目 AI 的 JYB 做一次性输入，先做容量预检。现在单个媒体条目 1 GiB、整包约 4 GiB；超过的必须有分批或流式通道。未批准对真实资料执行。
- **接口。** 选文件夹是系统对话框，看板变化是订阅，送进垃圾箱是业务动作。不放进同一个可选的 `files` 对象，也不在页面里写 `files!`。桌面能力在装配处接上；调用方只看到当时可用的业务方法，订阅另有订阅和取消。
- 同名的字符规范化、并发导入的唯一性、回滚日志下的写入速度，仍待原型。定义副本目前只复制文稿引用到的语言 id 和名称、显示名、别名、正字法 id 和名称、说话人 id 和名称。语言记录的其余字段仍待原型。
