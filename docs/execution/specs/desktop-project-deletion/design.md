# Design — desktop-project-deletion

## 1. Research

- 复用单库同步业务事务、SQLite 外键及已有桌面主进程，不复用扫描 .jyd 的删除协议。
- [SQLite 原子提交](https://www.sqlite.org/atomiccommit.html) 约束数据库修改，不把 OS 垃圾箱当作同一事务资源。
- [Electron shell.trashItem](https://www.electronjs.org/docs/latest/api/shell#shelltrashitempath) 是主进程文件移走 API，完成 Promise 不提供可恢复的垃圾箱句柄；用它适配磁盘操作，不造跨平台垃圾箱实现。
- 旧 sqliteRemoveEmptyRecording.ts 写占位 media id、跨库提交，不可直接用作新删除；其“不删原件”测试意图可保留。
- 无新增依赖；复用平台 API 和现有测试工具。反模式是先删音频、只查 deleted 布尔值、用文件缺失当成功，或按后台通知投递启动宽限期。

## 2. 结构提案（实施前核对）

- effect/actions 在数据库领域与主进程服务，derived 是清除资格；界面仅状态展示/事件装配。
- manuscripts/media 各持久保存删除时点、不得早于的清除期限、本周期提醒展示时点，列名是 `deleted_at`、`retain_until`、`reminder_shown_at`（[ADR-0096](../../../adr/0096-deletion-cycle-columns.md)）。恢复清掉这三列，再删除开启新周期。
- 文稿持久写入代际，任务启动携带该代际；每次写入在同事务检查有效性。删除后即使恢复旧任务也不再匹配；同步编辑与后台结果不能绕过校验。分析建议和快照同样抄下这一代际。删除再恢复后，之前的建议不能接受，之前的快照不能恢复。
- 清除操作记录在 `media_cleanups`：`id`、`media_id`、`relpath`、`sha256`，状态是 `intent`、`confirmed`、`failed`、`unknown`。不放 userData/settings_json。
- 列已写入 schema.ts，见 [ADR-0096](../../../adr/0096-deletion-cycle-columns.md)。文稿删除写下 `retain_until` 并清空 `reminder_shown_at`；恢复清空文稿和该录音的周期。删除录音会标记录音并连带有效文稿，已删除文稿的期限只延长。
- 文稿标记删除这一刀已经落地，只增加 `manuscripts.deleted_at`（空表示有效）。删除和恢复各把 `lifecycle_generation` 加一。普通列表排除已删除行，层、语段、备注和词的普通列表同样排除。`manuscripts.listDeleted` 只返回文稿行。已删除期间，文稿、层、语段、正文、备注、转写运行、词、词素、分析候选，以及挂在文稿、层、语段上的自定义字段写入会被 SQLite 触发器拒绝。仍有 `running` 转写时删除不生效，也不代为中断。恢复后旧运行不能收尾、预览、放弃或接受。停止只打断目标文稿或录音上仍在运行的转写，不写入删除标记。文件夹页确认后才删除。文件夹页打开到期提醒后才记下时点。垃圾箱仍未做。
- 已删除列表有专用读接口；普通领域查询默认只读有效对象，不能靠每个 UI 记得手动加过滤。词条链接、转写接受、接收批次、本地 id 和备注字段在文稿已删除时也不能写入。清除仍可删除这些行。
- 标记删除时同库一次事务改全部目标；前置保存/任务停止按 ADR 保留已完成效果，不声明跨整个 UI 流程回滚。

## 3. 清除与恢复

- 最早清除 = max(保留期限, 本周期提醒实际展示时点+7 天)，未展示不具备资格；时间判定支持受控测试时钟。
- 删除录音时各文稿清除期限取原期限与本次删除+90 天的较晚者；本周期提醒不足以覆盖新窗口时仍需满足新的清除资格。
- 恢复一份文稿在同事务取消录音待清除状态；其他文稿不变。清除与恢复并发时重读有效状态，不能用提前缓存的候选列表直接清除。
- 文稿清除只清自身标注/备注；共享说话人、录音等不级联。录音无任何文稿引用且自身期限满足才移走音频。
- 清除阶段、删除前的新工作限制和备份快照期间的文件保留以 ADR-0091 为准。调用垃圾箱前再查一次数据库不是互斥。trash 成功后才清理 media 和来源关联；失败或未知进入可处理状态，不按路径缺失重试。录音满足引用和期限后先记下 intent。移走成功才清登记并解除来源。同路径另一份文件不移走。重新登记给新 id。哈希撞上仍在的已删除录音时只列出候选，确认后只恢复录音。垃圾箱界面未做。macOS Electron 已把临时文件送进垃圾箱。失败不记成已移走。Linux/Windows 未跑。
- 包恢复保留删除状态但使旧提醒不再授权立即清除；重新实际展示后至少留 7 天。旧备份副本不追删。到期提醒写明清除只删当前项目，已有备份还在。没有独立隐藏目录。
- 普通 JYT 是单库表快照，格式版本为 2，不带音频字节。导入只写空文件夹。完整包保留删除周期。普通文稿导出只保留选中的有效文稿及其标注。含音频的 JYM 在导入空文件夹时核对录音哈希，对不上或路径越出文件夹就不写目标。导入清掉旧的提醒时点，删除状态和保留期限保留。没有新的提醒展示就不能清除。过期的每日备份恢复到另一文件夹后也清掉旧提醒，保留期限不变。重新看到提醒后再留 7 天。当前项目清除后这份备份还在。每天一份含音频 JYM 放在项目外并保留 3 份。恢复后用播放区间读出的字节与原录音一致。JYM 带上附件字节。导入空文件夹后哈希对得上。坏哈希不写目标。JYT 仍不含这些字节。每日备份也带上这些字节。当前项目删掉附件后，备份里的副本还在，恢复后文件读得回。打开项目会话时写入当天的 JYM。同一天再打开换掉当天那份。缺了录音文件就不留下会话。项目一直开着不会另存。界面播放仍未做。文件夹页列出最多 3 个日期快照。没有就写明没有。恢复前先说明，确认后选空文件夹。成功只显示路径，不打开那份副本。

## 4. 四片与落位

- D1：manuscripts/media 状态、普通读过滤、已删除列表、删除/恢复 UI/字典；引入 D2 必需写门禁后才可对用户开放。
- D2：保存/任务停止协调、持久写入代际、迟到结果拒绝；复用现有任务入口，不能读运行时私有字段。
- D3：提醒/受控期限/文稿清除/包保留与恢复；数据模型和打包服务同步验收。
- D4：主进程垃圾箱操作记录、故障收尾、来源解除、新 id 登记和重复候选提示。
- D1/D2 属同一安全发布边界，不把可恢复状态 UI 提前接给仍可后台写的文稿。后续每片补具体文件清单后才进入实施。

## 5. 验证

- 表驱动场景覆盖 90 天前后、未看提醒、迟看/重开、重新删除、关联期限不同、恢复一份/整录音、导入过期备份。
- SQLite 真实临时库：多目标状态写入/清除中途失败，关闭全部连接重开核对；清除并发恢复重查状态。
- 可控任务：保存失败、停止失败、删除后迟到、恢复后迟到、重新启动合法任务；原内容与停止副作用按规则断言。
- 磁盘适配故障注入：trash 失败、成功后回写失败、未知结果、同路径替换文件；Electron 真实临时文件送垃圾箱单独验收。
- typecheck、定向 vitest、architecture-guard、workflow；触界面/ReadyWorkspace 跑 Chromium/Electron 相应门槛，触 AI 跑 agent-evals:full；docs-governance。
