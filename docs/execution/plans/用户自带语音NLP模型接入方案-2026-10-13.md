# 用户自带语音与 NLP 模型接入方案（待评审）

## 0. 决策摘要

目标是让研究者把**为自己的语言训练的模型**用于解语中的转写、强制对齐及后续明确的语言学任务。首选接法是由用户在本机或自选主机运行模型，解语通过**按任务定义的接口**请求推理；复用现有 STT、增强、embedding、LLM provider。不给任意权重文件一个笼统的“导入即可运行”承诺。

**建议次序**：先打通用户自带的离线/批量 STT → 再独立完成“校订文本 + 音频”的强制对齐 → 依据真实需求增加词法/语素等 NLP 能力。实时流式转写、说话人分离、TTS、任意模型权重导入分别评估。模型推理是确定性的产品任务；AI agent 可以建议操作，但不能绕过用户选择、预览、确认和领域写入门禁。

此计划**不推翻**[Wave E++ 重型 Provider 门槛卡](./声学WaveE++重型Provider触发门槛卡-2026-04-09.md)的当前 `no-go`。R0 先用具体需求和证据复审；未过门槛时，可做隔离的本机模型接入试点，不把 MFA/WhisperX/pyannote 作为默认或已发布能力。新增中等以上复杂度功能在实施前依仓库流程建立 SDD 三件套。

## 1. 已读事实与缺口

| 领域 | 当前代码 | 对方案的约束 |
| --- | --- | --- |
| STT | `VoiceInputService.types.ts` 的 `CommercialSttProvider`；本地 Whisper、商业和 `custom-http` registry；设置页可填地址、模型、凭据 | 优先适配既有入口，不另建平行语音平台。`custom-http` 当前复用 `OpenAISttProvider`，固定 `/audio/transcriptions`、`verbose_json` 和 `/models` 探测，工厂未透传用户填的 `model`；匿名本机服务在商业凭据探测中也可能被跳过。 |
| 输入 | 录音器产出 WebM Blob；Whisper 路径会将音频与语言送到 HTTP 服务 | 自训模型可能只接受 PCM/WAV、固定采样率或专用语言码；转码与语言映射应在适配器/用户服务边界明确完成。 |
| 增强 | `stt/enhancementRegistry.ts` 有 `whisperx-align`、`mfa-align`、`pyannote-diarize` 实验入口；`applyEnhancement` 在 STT 后自动请求 | 当前无法对**用户校订后的文本**独立重跑对齐；`HEAD` 成功和数组浅检查不证明模型有该能力；错误时返回原转写，且即使返回空数组也可能标记 `applied: true`。 |
| 结果 | `SttResult` 可携带 `wordTimings` / `speakerTurns`，但生产代码没有把这些字段接到标注持久化与读回 | 不得用“接口有字段”宣称词级对齐已完成。需要真实 UI → 服务 → 保存 → 重载路径。 |
| 语言 | OpenAI STT 适配器将传入语言截成 ISO 639-1 风格前缀；解语支持用户自定义语言资产 | 语言资产 ID、模型内部语言码、书写法、分词/语素单位必须显式映射；不能把 `user:*` 或三字母代码强行截短。 |
| NLP | 聊天已有 OpenAI 兼容/自定义 HTTP/Ollama；embedding 已有本地与远程 provider，缓存键含模型 ID/版本 | 复用现有 provider。词法、语素切分、自动释义等新增任务必须各自有输入输出合同；聊天 API 不代表这些任务的结构化结果可靠。 |
| 浏览器/隐私 | 桌面 Chrome/Edge/Firefox/Safari n/n-1；CSP `connect-src` 枚举来源，AI chat 有单源动态放行；语音商业凭据只保留内存 | 自带语音地址不因填写 URL 就自动通过 CSP/CORS/本地网络许可。外发音频需明确提示；密钥不能随项目导出或写进日志。 |

## 2. 成熟方案与复用结论

| 方案 | 参考 | 取舍 |
| --- | --- | --- |
| 用户运行本机/远程推理服务，解语只接标准化任务端点 | [whisper.cpp HTTP server](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/README.md)、[MFA 单文件/语料对齐](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/workflows/alignment.html) | **首选**。支持用户自己的训练框架，运行依赖、词典和模型文件留在用户环境；解语只维护少量经验证的协议适配。 |
| 浏览器内加载受支持的 ONNX/Transformers 模型 | [Transformers.js ASR](https://huggingface.co/docs/transformers.js/en/pipelines)、[ONNX Runtime Web](https://onnxruntime.ai/docs/tutorials/web/) | 只对选定架构/模型包单独评测。ONNX 不等于所有模型可在 WebGPU 运行；需算子、内存、下载/缓存和四浏览器验证。 |
| 每个用户权重直接塞入解语并自动识别训练框架 | 无统一的权重、tokenizer、音频前处理或对齐词典格式 | **本期不做**。会把推理平台、模型转换和依赖维护变成解语的核心工程。 |

MFA 对齐需要文本、发音词典和声学模型；WhisperX 的对齐模型/词表依赖语言，部分单位可能无法对齐。对于低资源语言，用户可能需要**独立的对齐模型与词典**，其 ASR 模型本身未必支持强制对齐。[MFA 文档](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/workflows/alignment.html)、[WhisperX 对齐代码](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py)。

依赖引入前重新核对锁定版本、维护、许可证、模型许可、体积、CSP 与多浏览器成本；优先使用仓库已有运行时，不因“BYOM”新增通用插件框架。

## 3. 产品能力合同

### 3.1 模型配置（每个服务一份）

用户在 AI/语音设置中登记：显示名称、服务地址、模型标识与版本、**声明的能力**、支持的项目语言及模型语言码映射、数据去向（本机/远程）、认证方式。按能力补充：可接收音频 MIME/采样率、是否支持时间戳/中间结果、对齐输出单位（词/语素/音节/音素）、所需书写法/分词规则/发音词典。配置不是任意可执行代码或自由 JSON 请求模板。

“连接成功”分三层显示：① 地址可达；② 一个真实短样本可完成该能力；③ 结果通过解语合同校验。`HEAD` 或 `/models` 成功只证明第一层。服务若声明转写和对齐，分别测试；同一模型名不自动意味着两个能力都存在。

### 3.2 转写 `transcribe`

输入：确定的媒体文件或选区、项目语言资产 ID、映射后的模型语言码、音频格式与选项。输出最低为文本和运行来源；可选语段/词时间、说话人、置信度。必须标明时间相对**整段媒体**还是**选区**，单位统一为秒。未提供置信度则为“未知”，不得填 `1.0` 当作可靠性证据。

流程：用户选模型和范围 → 适配器按模型能力准备音频 → 调用 → 严格解析 → 显示候选文本与失败/缺失能力 → 人工校订或确认 → 通过现有领域服务写入 → 重载读回。默认不在模型返回时覆盖人工文本；批量写入、自动跳下一段另有明确确认。

### 3.3 强制对齐 `align`

输入必须包含**音频及其范围、用户确认的当前文本及修订标识**，再加项目语言、书写法/分词单位和模型要求的词典/映射。可直接对已有人工文本调用，**不要求重新转写**。输出是对齐单位的 `label/start/end`、可选置信度、未对齐项及原因；对齐不改写原文本。

流程：从现有标注或确认过的转写取文本 → 用户选单位/模型 → 调用 → 检查音频长度、有限数值、起止顺序、选区偏移、模型支持的文字覆盖率和未对齐项 → 波形/时间轴预览 → 用户确认 → 写入对应层并读回。若文本或音频在调用期间改变，结果作废或重新请求。多人语音可有合法重叠，不用全局“禁止重叠”规则。

强制对齐失败时保留文本与原时间；不把缺失时间的词静默插值成“模型给出的时间”。如用户选择显式估算，必须以不同来源标注。MFA 的 TextGrid/JSON 与 WhisperX 的对齐输出只在各自适配器内解析，不直接作为解语数据模型。

### 3.4 后续 NLP 能力

每个任务独立登记合同：输入文本/项目语言/书写法/上下文范围，输出对应的**结构化候选**及跨度、词条或语段引用。优先顺序由真实需求决定，候选包括分词/语素切分、词性、自动释义、翻译、说话人分离；TTS 属另一条输出音频路径。不得把任意聊天回复解析后直接写入结构化标注。Embedding 和通用聊天继续使用现有入口，不另建同义配置。

## 4. 运行与数据边界

```text
用户操作/选区
  → 任务能力检查 + 权限/语言/书写法映射
  → 适配器（音频前处理、协议、超时/取消、解析）
  → 候选结果（原媒体/文本修订/模型版本/失败项）
  → 预览与人工确认
  → 既有领域写服务/作用域校验
  → Dexie 写入 → reload/requery 读回 + 来源记录
```

- 使用现有 `CommercialSttProvider`、`SttEnhancementProvider` 作起点；MFA/WhisperX 可以由用户服务包装，解语不管理其 Python 环境。若现有接口无法表达独立对齐任务，**最小扩展任务合同**，不要扩出通用推理 DSL。
- 记录模型标识/版本、适配器版本、请求能力、输入媒体/选区引用与文本修订、时间单位、生成时间、用户确认状态和失败/未对齐项；复用现有 provenance 能力，具体表结构由 SDD 与写入链审查决定。不要把原始音频或 API Key 写入审计日志。
- 自带服务仅在用户显式选择后外发数据。本机服务优先 loopback；远程服务优先 HTTPS，显示实际目的地。校验端点，遵守现有 CSP、CORS 和本地网络权限策略；凭据只在会话/受控密钥层使用，不进入项目文件。自动云回退必须另获用户显式选择，不能因本地模型失败而暗中上传音频。
- 长任务支持取消、超时、进度和重复提交防护。中断/重载后显示未完成或失败，不把旧请求结果写到已修改的文本上。模型服务应自管加载、内存、训练权重与资源释放；解语负责 UI 与任务结果的生命周期。

## 5. 阶段、落位与验收

| 阶段 | 工作 | 主要落位 | 通过条件 |
| --- | --- | --- | --- |
| R0 需求与门槛 | 收集至少一套真实自训模型的权重/运行方式、输入输出样例；选两组目标语言语料；复审 Wave E++ 条件与本机服务可行性；确定转写、对齐单位及人工边界基线 | 本计划、对应 SDD `requirements/design/tasks`；不改产品代码 | 可复现模型调用；转写 CER/WER 或适合该语言的单位指标、对齐边界/覆盖率、延迟和硬件预算事先定好。门槛未过则只做隔离试点。 |
| R1 BYO STT | 修复 `custom-http` 的模型透传、匿名本地连接与能力检测；仅适配一个明确协议；项目语言码映射与候选转写预览 | `src/services/stt/`、`VoiceInputService*`、设置页/语音入口 | 用户可从真实入口选自训模型，发送音频，校订候选，确认保存并重载读回；坏响应、取消、超时、离线失败均不改旧文本。 |
| R2 独立对齐 | 对用户校订文本单独发起 `align`；接 MFA/WhisperX **其中一个真实用户服务**的适配器；预览词/音素边界与未对齐项 | `src/services/stt/enhancementRegistry.ts` 附近的任务适配、转写/标注 service、时间轴 UI | 同一音频在校订前后可重跑；错语言、OOV、空结果、越界时间和旧文本修订不能写入；确认后重载读回对齐数据与来源。R0 门槛复审未过不发布。 |
| R3 扩能力 | 按真实需求添加第二类模型或结构化 NLP 任务；决定是否需要批量任务与实时中间结果 | 复用现有 provider/领域 service，按任务补规格 | 至少两类不同架构模型都通过各自合同；旧模型/旧项目兼容，支持的浏览器和性能门槛通过。 |
| R4 权重直载研究 | 仅在用户确有“无需自启服务”的需求时，对**一种明确模型包格式**做浏览器 WASM/WebGPU 或本机封装试验 | 独立技术 spike | 证明目标浏览器、内存、缓存、模型许可与音频正确性后再决定产品化；不影响 R1/R2。 |

R1/R2 是交互和持久化改动：至少跑 `npm run typecheck`、定向 vitest、`npm run test:e2e:chromium`、`npm run check:architecture-guard`、`npm run check:docs-governance`；敏感浏览器 API 及本机网络路径加 Chrome/Edge/Firefox/Safari 目标矩阵与真实服务手工验收。以请求 fixture 测协议不足以证明模型质量；真实金标音频要分别报告转写错误、对齐边界误差、未对齐率、延迟、内存与失败回退。保存路径必须验证“写 → 关页/重载 → 重新查询 → 读回”。

## 6. 评审时需确定的产品选择

1. 首个用户模型的实际架构、运行平台、权重格式、音频预处理、语言码、输出样例，以及是否已有本机 API。没有这些，R1 只能做协议设计，不能声称兼容。
2. 目标项目的书写法和对齐单位：按词、语素、音节或音素；是否已有发音词典/对齐模型。**ASR 权重不自动等于对齐器。**
3. 候选转写与对齐结果应放在哪个现有标注层、何时要求用户确认；批量处理是否允许覆盖已有人工标注。
4. 是否允许远程用户服务处理音频、如何提示数据去向与管理凭据；首期可只支持本机 loopback。
5. Wave E++ 触发门槛是否满足；若不满足，限定为内部试点并保留原 `no-go` 发布状态。

## 7. 本方案的完成定义

“支持用户自训模型”只有在**至少一套真实模型**通过用户入口、能力调用、结果校验、人工确认、保存与重载读回，且目标语言金标评测和浏览器/本地服务测试留有证据时才成立。STT 与强制对齐分别验收；R1 成功不得写成“对齐已支持”。
