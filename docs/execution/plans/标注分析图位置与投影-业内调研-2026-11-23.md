# 标注分析图的句内位置与投影：业内调研

调研日期 2026-11-23。规范只核一方文档、作者论文和本仓库代码。

落位：主路线图切片 2「IGT 与局部复核」（[#622](https://github.com/Abe-Junwei/Jieyu/issues/622)）。现在不改代码、不改 ADR。该片开工写 SDD 时，把位置约定写成新的 ADR，再按下面三小片落地，本页随即删除（ADR-0051）。已接受的 ADR-0022 不改写（ADR-0049）。1b-3（[#563](https://github.com/Abe-Junwei/Jieyu/issues/563)）维持整份卸下，不在那里补位置。

## 调研综述

结论：**adapt**。内部真值继续用 ADR-0022 的 `analysisGraph`。CLDF、Xigt、LAF/GrAF、Web Annotation、CoNLL-U、FLEx/LIFT、LIGT、莱比齐规则、UniMorph 都不是能换上的存储格式。

值得加进图里的，是词在 `graph.text` 里的位置。计数单位用 JavaScript 字符串下标（UTF-16 码元）。码点、字素簇、音节序号不作存储单位。位置在桌面首次空白分词时写上，不先做人工锚点编辑器。按位置自动保留分析另做：拆句和改正文现在仍整份卸下。

不新造「表达方式」枚举。词素的词内偏移不在这一片：桌面词素生成只记下宿主词。

投影维持实体表。整段删除再插入没有改掉 `created_at`。

「可选字段所以不升版本」不成立。节点 schema 是 `.strict()`，旧程序读到带 `span` 的版本 1 图会拒绝，但拒绝发生在读图时。打开阶段只看 SQLite 头里的 `user_version`。第一片升 `user_version`，不加列、不写迁移器。`payloadVersion` 仍为 1，缺 `span` 的图继续有效。

## 计数单位

三套现成单位对不上，不能折中成一个字段：

| 单位 | 谁在用 | 和本仓库的关系 |
| --- | --- | --- |
| UTF-16 码元 | JavaScript `String.slice` / `String.length` | 拆分切点、`surfaceParts`、`sliceMatches` 已经是这个。BMP 里的声调附加符（如 U+0301）占一个码元。补充平面字符占两个。 |
| Unicode 码点 | Web Annotation 的位置选择器；[NIF 2.0](https://persistence.uni-leipzig.org/nlp2rdf/specification/core/core-draft.html) 对 `nif:String` 的硬性规定。UDPipe 的 `TokenRange` 在它自己的手册里按 Unicode 字符计，官方 CoNLL-U 不收这个键，也不定义整数单位。Xigt 只写「字符」，没有写成码点 | 导出到 NIF 或 Web Annotation 时换算。存成码点之后，拆分切点仍是码元，非 BMP 会切错。 |
| 字素簇（UAX #29） | Web Annotation 只说选择**不应当**从簇中间切开，簇不是它的计数单位 | 簇边界会随 Unicode 版本变。不存簇序号。 |
| 音节或音段序号 | 没有任何一份上述规范把它当作句内锚点 | 没有语言无关的音节切分。声调落在第几个音节，是以后的手工标注，不从字符位置推。 |

组合附加符的问题出在规范化，不在 UTF-16：NFC 的 `á` 是一个码点，NFD 是 `a` 加附加符。两者在 BMP 里码元数和码点数相同。若把已存正文改成 NFC，现有 `surfaceParts` 的下标会错。已存正文不重写。

新的句内 `span` 因此用 UTF-16 码元，半开，指向 `graph.text`。导出码点位置时单独换算。这个选择的上限：补充平面字符和字素簇边界不作为存储单位；真有这类正字法再改，并同时改拆分切点。

## 复审（2026-11-23，静态）

对照桌面分词、词素生成、正文保存、拆句和打开准入。读了 `analysisSegment.test.ts`，没有跑测试。早先三条建议作废：跨度不绑当前显示正字；「重复词形则留空」只适用于没有切分下标的旧图，不用于新建分词；「不升版本」只证明了新程序能读旧图。按位置保留分析不在第一片。

### 跨度指哪一份文字

`span` 半开，单位是 UTF-16 码元，只指向该图的 `graph.text`。`graph.text.slice(start, end)` 是原文里的出现，不是 `displayContext.formKey` 选中的分析词形。显示键切换不移动跨度。`domain.form` 可以改成和原文不同的规范词形；要不要复核看改动本身，不靠「跨度文本必须等于词形」这条总校验。改正文之后，旧跨度属于旧正文，不能当作新位置。

新建空白分词时，用和 `\s+` 同一套非空白匹配，边走边记下起点和终点。`ka ka` 是 `[0,2)` 和 `[4,6)`。重复词形在这一步是确定的。已有 `token` 的图这次调用直接返回，不事后搜索回填。缺位置就保持缺位置。

词素偏移不从词的句内跨度推导。零词素、非连续词素和抽象词素不能套 `-` / `=` 切分。词素创建入口另写 `startOffset` / `endOffset`。

### 版本

| 方向 | 仍写 `payloadVersion: 1` 并加上 `span` | 另升 `payloadVersion` | 升 `user_version`、不加列 |
| --- | --- | --- | --- |
| 新程序读没有 `span` 的图 | 可以 | 新程序必须继续接受 1 | 旧库整份被打开拒绝（无迁移器）。新库里的无 `span` 图仍须读过 |
| 旧程序遇到带 `span` 的图 | 打开成功，读图时 `.strict()` 拒绝 | 打开成功，读图时「unknown analysis payload version」 | 打开时 header 不符，抛「不是解语项目库」 |

第一片升 `user_version`，使旧程序在打开阶段拒绝。`formatFreeze` 记录里的 `userVersion` 一并改，schema SQL 可以不动。图内 `payloadVersion` 保持 1，`span` 可缺。测试要覆盖：新校验接受无 `span` 的版本 1 图；按现行 strict 规则解析带 `span` 的节点必须失败；旧 `user_version` 常量打开新库必须在 header 检查失败，且不改文件字节。

### 三片

| 顺序 | 交付 | 验收 |
| --- | --- | --- |
| 第一片 | 跨度合同、计数单位、上面的版本措施；`segmentUnitWords` 在首次分词写入跨度 | 重复词、多空格、换行、组合附加符、补充平面；再次分词不改结果；关闭重开跨度还在。扩展 `analysisSegment.test.ts`。已有词的旧图保持缺位置。拆句和改正文仍整份卸下 |
| 第二片 | 现有 IGT 用跨度定位原文；缺位置和失配保持可见 | 切换显示正字不移动跨度；改分析词形不改写正文；缺位置不编造高亮 |
| 第三片 | 按引用决定保留、待复核或只留历史。接入查询、统计、AI 和导出资格 | 跨切点的词不自动分到任一侧；关系跨两侧则待复核；备注、词义链接、候选随所依赖对象走。失败回滚和撤销后没有错误生效的分析 |

第三片不能收成「加了 `span` 再跑两条字符串」。拆句今天把文本、草稿、回执、快照、投影、关联、备注、候选、接收批次和采纳记录集中留在左段，前提是整份分析不再生效。右段要带有效分析，这些归属都要改。两个词分居切点两侧、又同属一个 MWE 时，词跨度都不跨界，关系跨界。只按词的区间切会留下缺成员的 MWE。

## 先不做

- 人工锚点编辑器。首次分词已经知道匹配区间。
- 第一片里按位置自动保留分析，包括拆句时把右段下标减去切点。
- 第一片里给词素补 `startOffset` / `endOffset`。
- 按差异写投影。`created_at` 来自 `domain.createdAt`。事务内读回只证明这一次写入一致，不代替关闭重开、导入、恢复和拆句。等有写入量或「表和图不一致还能打开」的证据再改投影。
- 投影表加字符列。
- 把投影改成视图或 `json_each`。链接和备注要实体 id。
- `expression.kind` 闭枚举、`from` / `to` 校验、音节锚点。schema 里已有 `process`、`exponent`、`overwritesTone`、`substitutesSegment`。桌面要能创建时，复用 `morphologyRelations.ts`，再给过程节点加可选锚点；那一片单独做，并先读 Pixso 精稿。显示若要一种已发表的过程写法，再用 GGG 的 `{A>B}`，不把它收成存储枚举。
- 用 Web Annotation 的引用选择器在改正文后找回位置。规范把位置选择器标成很脆，前后文只在多处相同字符串里做选择。应用内有旧串和新串，用 diff。
- 特征对照表。导出时的有损映射，不改变存储。
- LIGT 命名空间扩展、ELAN 声调层。等锚点真的写进图里再降级导出，并沿用现有 diagnostic。
