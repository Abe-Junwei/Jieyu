## 2. 全体阶段共用原则与门禁

### 2.1 原则

1. **读/写分离**：read model 只增加 **只读派生**；可变标量仍只经 **视口写者**（及本方案新增的 **交互写者**）更新。
2. **声学边界**：插件只输出窄事实（时长、解码态、seek、可选波形 scroll）；**不**承载套索/拖建/选区状态。
3. **壳不判业务**：[`TranscriptionTimelineWorkspaceHost`](../../../src/pages/TranscriptionTimelineWorkspaceHost.tsx)、[`OrchestratorWaveformContent`](../../../src/pages/OrchestratorWaveformContent.tsx) **禁止**新增 `if (textOnly)` 式业务分支；只消费投影与 chrome 映射。
4. **每阶段必有**：[`TIMELINE_PARITY_MATRIX_VERSION`](../../../src/pages/timelineParityMatrix.ts) 升版或新增行 + 定向测试 + [`TranscriptionPage.structure.test.ts`](../../../src/pages/TranscriptionPage.structure.test.ts) 门禁之一。

### 2.2 每 PR 必带清单（防回潮）

- [ ] 更新 [`TIMELINE_PARITY_MATRIX_VERSION`](../../../src/pages/timelineParityMatrix.ts) 或新增矩阵行 id；[`timelineParityMatrix.test.ts`](../../../src/pages/timelineParityMatrix.test.ts) 锚点存在。
- [ ] [`TranscriptionPage.structure.test.ts`](../../../src/pages/TranscriptionPage.structure.test.ts) 至少一条与「单源 / 单映射 / 单 writer」相关的结构门禁。
- [ ] CI 或结构测试禁止新增裸 `shell === 'text-only'` **业务**分支（chrome 映射除外）。

## 3. 前置硬化与数据契约

本节为评审中确认的 **P1–P2 改进项**，与 §4 各阶段 **正交**：可单独 PR 交付，但在 **阶段 C（chrome 单映射）** 与 **依赖 `timelineReadModel.acoustic` 的 orchestrator 策略** 之前，**§3.1 建议优先合入**，避免壳与能力位继续分裂。

**本轮已确认结论（执行口径）**

- **结论 A（针对壳层驱动语义）**：当前实现中 `TimelineReadModel` 使用 unit 数量参与壳层判定，属于收敛过程中的实现分叉，**不视为刻意定义“以 unit 存在性驱动 shell”**。落地目标以 layer 维度单源为准。
- **结论 B（针对宿主 link 语义）**：业务与数据契约允许一个翻译层存在多条 host link（含历史脏数据与导入场景）；因此 **§3.2 为必须修复项（required）**，不是可选优化。

### 3.1 壳层判定与 `layersCount` 单源（P1）— **已落地（2026-06，矩阵 v13）**

**原问题**：ReadModel 与 Timeline Content VM 的 `layersCount` 输入不一致（unit 数 vs 层列表长度）。

**现状**：[`buildTimelineReadModel`](../../../src/pages/timelineReadModel.ts) 经 `computeEffectiveTimelineShellLayersCount` 统一 `timelineShellLayersCount`，与 content VM 同口径；矩阵行 **`timeline-shell-layers-count-single-source`** 三壳 `full`。

**验收（已通过）**

- [`timelineReadModel.test.ts`](../../../src/pages/timelineReadModel.test.ts) + [`useTranscriptionTimelineContentViewModel.test.tsx`](../../../src/pages/useTranscriptionTimelineContentViewModel.test.tsx) + 结构门禁。

---

### 3.2 宿主层 link 全量择优（P1）— **已落地（2026-06）**

**原问题**：[`resolveSegmentTimelineSourceLayer`](../../../src/hooks/layer/useLayerSegments.ts) 曾仅解析 `isPreferred ?? links[0]`，preferred 失效时不尝试其余 link。

**现状**：[`useLayerSegments.ts:90-102`](../../../src/hooks/layer/useLayerSegments.ts) 对 inbound links **preferred first**，再遍历其余；命中第一个可解析且宿主满足 `layerUsesOwnSegments` 的层即返回。

**验收（已通过）**

- [`useLayerSegments.test.ts`](../../../src/hooks/layer/useLayerSegments.test.ts)：`preferred` 宿主无效时回落次级 link。
- 矩阵锚点：`layer-link-connector` 行含上述测试（矩阵 v21）。

### 3.3 独立层 segment 查询并行化（P2）— **已落地（2026-06）**

**原问题**：[`useLayerSegments`](../../../src/hooks/layer/useLayerSegments.ts) 对每层串行 `await`。

**现状**：`Promise.all` 并行拉取 + 一次性 `setSegmentsByLayer`；保留 `loadSequence` 竞态保护（`:170-178`）。

**验收（已通过）**：行为与串行一致；层数 >1 时并发完成后再 commit。

### 3.4 segment 宿主解析失败的轻量可观测性（P2）— **已落地（2026-06）**

**原问题**：[`listSegmentTimelineUnitsForLayer`](../../../src/utils/timelineLaneSegmentIteration.ts) 静默 fallback。

## 7. 开放问题（实施前评审）

1. **`timelineExtentSec` 定义**：**已决（2026-06-26）** — 见 [`resolveTimelineExtentSec`](../../../src/utils/timelineExtent.ts)：`max(文献, 声学)` 用于显示 / lanes 宽度 / fit；持久化逻辑时长冻结见 ADR-0004 与 `mergeImportedTimelineMetadata`。
2. **`layersCount` 精确定义**（与 §3.1 联动）：**已文档化（2026-06-26）** — 见 [`computeEffectiveTimelineShellLayersCount`](../../../src/utils/timelineShellMode.ts) JSDoc：`max(编排 layers 长度, 转写层数, 翻译层数)`；不计 unit/segment 数；全 0 → empty 壳。
