# 1b-6：批量编辑与转写入口收口

本页产品语义经 2026-11-25 grilling 逐项确认；2026-11-26 用户授权修复全部审查问题并完成剩余实现。当前本地实现与验收覆盖 6r/6p、6a–6e，具体证据与尚待全片 CI 的关账项以 [tasks](../specs/desktop-4ws-slice1b-transcription-editing/tasks.md) 为准。本页保留调研和实施合同，随 #566 最终关账后删除，不以历史调研或点层测试替代本片证据。首次调研基线 `82cb87cb`，复审基线 `1cc938e0`；本次修改建立在 `a02d3eae` 及已有工作区实现上。

## 1. 成熟方案扫描 / Research

- 外部一手证据与采用范围见[专项调研](./1b-6-转写批量编辑-调研-2026-11-25.md)。采用显式选择、影响预览、批量原子写入和可撤销编辑；不照搬其他工具的级联删除、推挤时间或下级延时。
- 仓库复用：`useDesktopTranscriptionSelectionController`、`desktopTranscriptionEdgeActions`、`speakerAssign`、`unitMerge`、`notes`、`sessionEdit`、`editReceipts`。旧网页只提供交互及业务语义参考，不挂旧 controller、Dexie 或 ReadyWorkspace。
- 选择：**适配现有模块，不新增依赖**。React 现有状态与纯函数足够表达选择；SQLite 现有事务与约束承担原子性；现有回执承担未知结果核对。不另造批处理平台、持久撤销表或自动对齐算法。
- 反模式：前端循环发 N 次合并/删除/指派会出现半批成功、N 步撤销及中途媒体清理；筛选后把“当前可见”误当“全部已选”会误改隐藏内容；把 AI confidence 当人工确信会改变两者含义。
- 风险：同 unit 多层投影去重、过滤后残留选择、预览与提交之间草稿/引用变更、同说话人重叠、录音累计超限、迟到响应串稿、未保存正文与备注、后改数据被撤销覆盖。

## 2. 实施前基线的已读事实与差额

1. 页面 `DesktopTranscriptionWorkspacePage` → selection controller 已支持一个主 id 加附加 id，框选不是待从零实现；缺显式增减、范围选择、作用域与过期选择清理合同。
2. 边界 actions → client.deleteUnits → `units.deleteMany` → `removeUnits` → SQLite → sessionEdit.deleteMany → reload 已有原子批删与一步撤销；本片补入口一致性和数据完整性，不再建第二套。
3. `removeUnits` 检查同稿，遇任何时间细分子段则整批拒绝。确认框列影响不等于允许级联删除；沿用先删子段的既有决定。结构删除预览目前没有与清空文本相同的 fingerprint 合同，需补预览后数据改变的拒绝用例。
4. `speakers.assign/clear` 接数组，底层单事务并登记 assign 撤销；但不带 operationId，且未在叶函数检查所有段同稿。批量开放前补作用域和未知结果处理，不能只加菜单。
5. `unitMerge` 的输入、预览、撤销均是 earlier/later 两段；已有多层正文/草稿、引用、录音、基准与新身份合同。多段合并要扩展这一领域实现，不能前端反复调用两段接口。
6. 项目说话人已有 create/list/patch，完整字段 patch 带 revision 与回执；旧 `DesktopSpeakerCatalogPanel` 混语言/正字法等内容，不适合整体移入。转写上下文栏 speakers 区目前没有行。
7. `notes` 已支持 unit、unit_text、waveform/timeline 等锚点，`desktopUnitNoteActions` 在旧只读页有增改删，层正文备注另经 `DesktopScopeNote` 写入；转写工作区尚未接备注 UI。复用的是领域能力和交互参考，不是已接好的工作区闭环；notes 写操作目前是 `clear` 撤销策略：定义在 `operationContract.ts` 的 `notes.create/update/delete`，`desktopCall.ts::runContract` 在调用 handler 前执行 `clearSessionEdit(sessionId)`；并非 `notes.ts` 自己清栈。不能宣称已具备与句段编辑共存的一步撤销、草稿与未知结果恢复。
8. `units.self_certainty` 有三值约束，但公开 Unit 读模型未带 selfCertainty，没有桌面专用更新合同；`confidence` 已表示机器概率，两者不可混用。
9. split/merge/RemovedUnit 已读写 unit 级 self_certainty；`unitTextLayers.resolveUnitTextContext` 从层 content_type 派生 role。`unitTextClear.clearUnitTexts` 清空时保留行，而 `units.updateUnitText` 在无录音时可能删除空正文行；`analysisRestore` 也有同类清理路径，`recordingClips.detachRecording` 删最后一条录音时也可能删空载体。6c 必须统一载体保留条件，不能假定现有行为满足新合同。
10. FR-066/068 是允许缺段、空转写和无转写前置的译释；FR-082 是用户手动听辨定位。无录音、无时间段排版/补时间属于 1b-7；VAD 属 #604；ASR 不进入本片。

以上是静态追链事实。首次基线 `82cb87cb` 的定向 Vitest 4 文件 31 项通过是历史证据，不改写成新基线证据；本次复审重跑结果单列在 §9，只证明已有断言，不证明 #566 新能力已实现。

## 3. 用户已确认的行为合同（2026-11-25）

### 3.1 选择与筛选

- 选择身份使用结构 unit id；关联层重复显示同一 unit 只算一个。另带当前显示层和稿件上下文；point 不混入句段集合。
- 普通点击单选；Cmd/Ctrl 点击切换；Shift 点击以锚点选择同一结构层有序范围。已有波形框选保留；文本框内的快捷键优先编辑文字。
- 菜单右键命中已选段时保留集合，命中未选段时改为该段单选；摘要始终显示真实目标数。前后全选限定当前层，不默认跨层或跨稿。
- 目录名称搜索与说话人筛选分开。说话人筛选支持多选、未指派及全部；对所有独立转写层过滤，只显示所选说话人的句段，关联翻译/口译随宿主显示；层本身保留。启用筛选时暂时隐藏全部点。
- 时间轴保留原始时间位置及空白，波形、刻度和正常播放不变，不自动跳过隐藏段。筛选期间禁止拖建新段，需切回全部后创建。
- 隐藏段立即取消选中，批量操作不包含隐藏目标。改派后不再匹配筛选的句段立即隐藏并取消选中，保持当前筛选并提示成功，可撤销；不自动加入新说话人。
- 切稿或重开项目恢复全部，不持久化每稿筛选。一次多选仅限同一个结构层，进入另一个独立层开始新选择；批量确信和备注作用于发起文本层。
- 切稿清空集合、锚点和菜单，切层取消旧批量目标；reload 后移除已消失 id。筛选不成为隐式批量写入目标。
- 用户补充决定（2026-11-25）：单边编辑可见目标保留；共享边界、父子随动等若会改变隐藏段，整次阻断并提示切回全部。前端发送前检查本地筛选修订，后端按请求携带的视图快照与完整受影响集合核对，不能只在 UI 隐藏按钮；依赖变化使基准过期则拒绝。筛选不持久化，服务器不声称能察觉发送之后的界面变化，详见 §10。
- 整稿 retime 在筛选激活时不可提交，先恢复全部；禁止把完整稿件调时偷偷缩成可见子集。撤销/重做按原事务恢复数据，再重新派生可见性，不因筛选裁剪历史步骤；改派撤销后恢复显示，不自动选中，也不覆盖当前新选择。
- 拆分与合并资格只以完整稿件数据判断。其依赖闭包含隐藏段则阻断；“连续”按完整同层同说话人序列，不按可见数组。合并下级保护仍是已确认的改挂例外，不借筛选跳过约束；若其中有隐藏的下级也不允许静默改挂。

### 3.2 批量指派、清除与创建

- 对明确集合一次事务提交，去重且校验同稿、层未删除、unit 有效、speaker 存在。不同说话人改为同一个后如重叠，整批拒绝且不追加撤销。
- 已有单段菜单和新批量入口共用叶函数。请求持有稳定 operationId；未知结果查回执，不盲目再提交，不多登记一次撤销。
- 提供新建并指派：输入姓名一次确认，创建目录项与指派所选段同一事务，全部成功或全部不做。重复请求不重复创建或登记撤销。撤销指派恢复原说话人，但保留新目录项；重做复用该目录身份，不再次创建。单独新建复用项目目录的业务创建能力，但必须完成下述保栈与回执接线，不沿用现有 clear 策略。
- 本片做项目目录名称搜索、最近使用、创建和指派；不复制说话人层，不扩建完整人物信息编辑器。新建不能清掉现存句段撤销栈；必要时补创建回执合同。
- `speakers.create`、`speakers.patch`、`speakers.redeliver` 当前均为 clear，连失败/no-op/补交都可能在 handler 前清栈。6b 计划将三者改为 keep；资料修改仍由原字段 revision/delivery 保护，不因此变成句段撤销步骤。单独创建沿用目录行为、新建并指派复用创建领域函数，均不得绕 clear handler 导致清栈。接受清栈不再列为可选产品方案。
- 6b 回执链必须同片接完：`operationContract.ts` 的 operationId/视图与影响基准；`client.ts` 的方法/种类映射和查询重试；`desktopCall.ts` 的 EDIT_METHODS/handler；`editReceipts.ts` 的种类与摘要。拟加入 assign/clear/create-and-assign 的编辑回执，注册时统一命名；单独创建按需接稳定创建回执。既有 speakers.patch/redeliver 保留字段 delivery 协议，不为同一修改再造重复回执。重放返回原结果，不第二次创建 speaker 或追加 assign frame。notes 的批量回执在 6c 单独接线，不能用其清单替代 6b。
- 撤销优先复用现有 `SessionEdit` 的 `assign` frame：`SpeakerAssignUndo` 已保存目标 speakerId、稿件和每段原 speakerId，`redoAssign` 复用该 speakerId。新建并指派只在成功提交后登记一次 frame；undo 不删新目录项，redo 不再创建，目标被移除则按过期步骤拒绝。新增原子业务操作和回执，不仅因缺少“createAndAssign”类型名就新造 frame。

### 3.3 删除与清空本层文本

- 结构层删除目标为所选 units；1 个目标路由 `units.delete`，至少 2 个才调用 `units.deleteMany`，不通过补重复 id 凑批量；关联文本层操作名为清空本层文本，保留宿主、其他层与时间。两者明确分开。
- 预览逐项列关联文本、分析、备注、草稿及录音影响；提交重新核对基准。任一目标有时间细分子段时整体阻断，沿用既有非级联语义。
- 沿用现有 deleteMany 回执与快照；检查音频引用在撤销/重做栈期间不被回收。取消不保存或丢弃输入，失败原集合及数据不变。

### 3.4 N 段一次合并

- 只接受同稿、同结构层、同说话人且在该说话人时间顺序中连续的 N≥2 段；可有空隙、可夹其他说话人，不能漏选中间同说话人段。无时间合并留 1b-7。
- 一个新 id、原 N 个 id 到新 id 的完整映射、一次事务、一个回执、一步撤销。内部可以复用两段规则，但中间身份不成为用户可见结果，不留下中间回执或媒体清理副作用。
- 各文本层按时序拼接，非空之间一个空格；正式正文及未保存草稿逐层展示，确认才消费目标草稿。不得把预览前的草稿强制保存后再称“取消保留”。
- 子段仅改上级，保留顺序与时间；字段冲突整批拒绝；分析沿用 1b-4 待复核与快照规则，不提前做切片 2 局部保留。
- 每层累计录音按原段顺序排列，同文件保留最早条；超过既有 5 条上限，用户勾选丢弃后才能确认。引用持有、备注迁移和未知结果与两段合并相同。
- 先评估把 `unitMerge` 改为数组内核、两段入口作为适配器；拒绝维护两套合并语义。扩展前必须完成 6p 的行为不变拆分，按预览/写入/快照的实际依赖落位，不建通用 transaction pipeline。数据库文件不套 hook 的 300 行硬阈值，但不能在 1165 行原文件继续叠加数组语义。

### 3.5 备注与人工确信

- 句段备注、层文本备注、说话人资料备注是不同对象。波形入口写 unit 锚点，关联文本行写该层 unit_text 锚点；空正文仍可有载体，不为写备注伪造正文。
- 备注使用现有类别及多语内容；列表、添加、编辑、删除闭环，保存失败保输入；取消不落库；切稿迟到响应不得关闭新编辑框。允许批量添加：确认后在每个目标上各建一条独立备注，整批同一事务、一步撤销；各自可独立编辑。文本卡批量操作遵循发起文本层，波形批量操作使用整段锚点。
- 正文清空保留该层备注与必要空正文载体，清除该层确信；不顺带删除备注。只有明确删除对应句段或备注才删除，撤销恢复相应内容。
- 人工确信三档沿用 `not_understood / uncertain / certain`，清除存 null；不提供百分比，不修改机器 confidence。混合选择显示“值不一致”，用户选值才批量写。
- 各层合并时，只要任一来源未标记，结果未标记；否则按未理解 > 存疑 > 确定取最不确定档。各层独立计算。拆分时有正文的左右侧继承原值，空正文侧不继承。
- 正文实际改变即清除这一层确信，撤销正文修改恢复原值；未改变正文的保存不清除。空正文卡也能主动设置三档确信；主动清空已有正文仍先清除原值。
- **用户决定（2026-11-25）：按文本层独立保存**，同一句段的转写与翻译可有不同确信程度。存储合同见 [ADR-0144](../../adr/0144-per-layer-self-certainty.md)：role 派生、空行载体、删除旧共享列、升 36 与拒旧/交换边界。6c 同批切换全部消费者，覆盖空文本载体、拆合、删除恢复、项目交换及 readback 消费链。不得用 units 共享列或本机 UI 覆盖表充当按层实现；元数据 UI 仍待精稿。
- 备注增改删及确信修改应不清空原句段历史；分别接会话撤销与稳定回执，不把现有 notes `clear` 行为直接暴露为新工作区完成态。说话人资料备注仍走 speaker revision patch，不改为内容 note。

### 3.6 部分转写与手动定位

- 只转写音频的一部分合法；空白时间不要求补段，空正文不等于删除 unit。只有翻译/口译、没有转写正文也可保留、重开和继续编辑。
- 复用现有播放头、时间码输入、波形定位、边界微调，验证能手动找到馆藏音频片段并建立/调整边界。没有依据的时间不得自动生成。
- 不新增“完成率”“整稿已完成”字段，不把 skipProcessing 当已转写；这些语义无本片授权。

## 5. 落位、依赖与 flag

类别：state 为选择/筛选/待提交框；derived 为资格/影响闭包/可见性；actions 为事务；effect 为重查和过期响应清理；routing 为入口到领域操作。页面只装配，纯领域代码不依赖 React。

## 10. 视图快照与写入影响合同（6a 定义、6b 开放筛选前接齐）

筛选是本机视图状态，不是权限边界，也不写项目库。拟采用每次工作区提交显式携带 `viewScope: { manuscriptId, kind: 'all' } | { manuscriptId, kind: 'speakers', speakerIds, includeUnassigned }`，其中 speakerIds 为稳定排序去重的 id 集合；不能以空数组含糊地同时表示全部与无人，具体 TS 类型名在实施时统一。调用方不传 SQL、表名或回调。

- 预览在完整数据库上计算已存在的直接目标和将被修改/改挂的依赖闭包，返回稳定排序的 `affectedUnitIds` 与完整业务基准。提交携带相同 viewScope、`expectedAffectedUnitIds` 和基准；事务内重新计算并比对，任一受影响旧对象不符合所携快照就整次拒绝。不信任前端单独报“这些都可见”。有点的全稿 retime 还需处理点影响；筛选激活时该命令直接拒绝，无需偷偷缩小范围。
- 覆盖操作清单：`units.create`、`units.moveEdge`、`units.moveSharedBoundary`、`units.moveUnit`、兼容入口 `units.updateBoundary`、`units.split`、`units.merge`、`units.delete`、`units.deleteMany`、`speakers.assign`、`speakers.clear`、新建并指派及 `manuscripts.retime`；6c 新增 notes/确信写入口复用同一合同。按实际公开方法而非“约九个”验收，所有 wrapper/client/handler/回执/测试同片更新。隐藏点的入口及快捷键不可绕过筛选状态去新建或改点。
- 筛选期间 create 拖建和全稿 retime 禁止；指派按修改前目标判断资格，改派后目标不再匹配是已允许结果，随后隐藏。拆合的新身份由合法来源派生，不拿尚未存在的新 id 当可见性证据。undo/redo 不裁剪原步骤，不套当前筛选去部分撤销，完整回放后重新派生可见性。
- 使用现有 editDigest 把 viewScope/预期闭包/业务基准纳入 payload；同 operationId 改快照必须冲突。重试已提交请求先查询并返回原回执，不因提交之后数据或视图已改变而再次执行或误报失败。尚未接编辑回执的兼容入口须在新工作区可达前补查询协议或收口到同一受保护操作，不假定所有现有方法已经 receipted。

## 11. 现有缺陷：层正文备注孤儿（不是“待格式 36 才成立”）

静态可达：只读页 DesktopProjectReadView → DesktopScopeNote → notes.create 可以建立 unit_text 备注；notes.unit_text_id 无外键；detachNotesForDeletedTarget 仅被测试调用。units.updateUnitText、analysisRestore.undoUnitText 和 recordingClips.detachRecording 都可能删空正文行而不查备注。尚未运行专门复现，未检查真实项目是否已有损坏，不宣称已修复。

单独安排现行格式的修复项 6r：先从真实注册入口创建正文和层备注，再分别清空/撤销/删除最后录音，关闭重开验证 note attachment、unitTextId 和可见读回；统一保留有备注的载体。可以不改 schema 的应用修复先交付，不以未来加列为前提。约束分开：普通清空保留正文 id 与备注；明确删除句段按既有删除/快照规则处理所属备注，不能靠一个无差别禁止删除的触发器堵住正常删除。至少留下“提交后每条 active unit_text 备注的载体存在”以及清空后原 id 不变的不变量检查；若选择触发器，另验证删除顺序、导入和恢复，不以它替代入口测试。已存在的孤儿无法凭空恢复原 layer，先诊断，不自动猜层改挂或静默删备注。

6r 复现修复属于现有功能质量项，不等 6b；6c 吸收其载体规则并加确信条件。修复实施仍需明确批准的 Plan，不把本节加入任务当成代码已修好。

## 12. 逐项撤销与提交基准

- unitEdges.treeStillMatches：创建撤销及删除重做要核对会被删除/恢复的正文层、判断、备注、录音与相关引用，不能维持只看时间和转写正文。后改目标则原步骤保留并拒绝，不覆盖。
- analysisRestore.unitTextStillAfter、units.UnitTextUndo、sessionEdit 的 redoText：按目标正文身份记录确信和将被恢复的备注/载体前后态；保留原分析/草稿/正文基准，补后改确信时拒绝及 undo/redo 恢复用例。
- unitTextClear.cells/digest、undoTextClear/redoTextClear：把本层确信和受影响载体状态纳入基准，清空保留的备注不被覆盖。若后续备注改变不在本次恢复覆盖范围，不机械把它当全局过期；测试按真实写集定义。
- unitMerge.mergeBaseline、textsOf、afterFingerprint、undoMerge，以及 sessionEdit 的 redoMerge：按层确信、备注和载体纳入预览/后态/重做前态，确保旧基准不能接受更新后的元数据。6p 拆分时维护同等比较，6c 有意增加新字段。
- unitSplit.fingerprintOf/splitStillAfter、undoSplit 与 redoSplit：记录各层左右正文、确信、备注归属及引用，不只比较共享 unit 列；空侧规则和后改拒绝覆盖关库读回。
- speakerAssign.assignStillAfter/undoAssignSpeaker、sessionEdit.redoAssign：保持单位指派后态和完整稿件作用域基准，不把目录名称或资料备注的变化当作需要撤回的内容；资料变更不应被句段撤销覆盖。
- 新增批量 notes/确信 frame：每个实际目标的稳定 id、前后内容/确信与必要引用状态；一次撤销/重做整批，任一目标冲突全批拒绝，不改变不相关目录字段。各基准只保护实际恢复/覆盖范围，不做“全库任意改动都过期”。
