# 代码审查问题统一修复方案（2026-06-01）

## 0. 文档定位

本文承接 2026-06-01 多份代码审查与落地核查，目标是把开放问题拆成可执行 PR 队列。本文不替代架构现状文档；当本文与 `docs/architecture/` 或代码冲突时，以代码和架构文档为准，并回改本文。

**总策略**：先修会阻断用户恢复与 CI 漏报的 P0，再修 a11y / 数据韧性 / 工程治理的 P1，最后收敛 P2 长尾债务。每个 PR 必须包含可复验命令，不能只改实现不补测试。

## 1. 成功标准

1. P0 项全部关闭：数据库 open 失败后的手动恢复可用；Embedding mid-flight 不再随机终止；AI 文案按 locale 分层；关键主路径有 E2E 防线。
2. P1 项有明确门禁：blocking dialog 焦点闭环；治理文档与代码事实一致；CSS/PWA/Dexie/language mapping 风险不再只停留在报告里。
3. P2 项形成可持续收敛：供应链口径统一、死 flag 清理、Snapshot / 导入导出 / token 计数进入专项测试。
4. 验证基线：`npm run typecheck`、触及域 Vitest、`npm run check:docs-governance` 必跑；交互 / ReadyWorkspace / 侧栏 / 时间轴改动追加 `npm run test:e2e:chromium`。

## 2. PR 队列

### PR-0：恢复入口状态机热修复（P0）

**问题**：`useAppDataResilienceEffects.ts` 的 `onRestoreFromBackup` 只允许 `dbMigration.kind === 'migrating'` 进入恢复逻辑；但 `engine.ts` 在 open 失败后会派发 migration done，导致 overlay 有恢复按钮但点击后走「not found」分支。

**落点**：

- `src/hooks/useAppDataResilienceEffects.ts`
- `src/db/engine.ts`（仅当需要补充事件语义时触碰）
- `src/hooks/useAppDataResilienceEffects.test.ts` 或相邻测试

**方案**：

1. 将恢复入口条件从「必须处于 migrating」改为「存在最近一次可恢复失败上下文 / open failure 上下文」。优先复用现有 db resilience state，不新增并行状态源。
2. open failure overlay 的恢复按钮直接走同一恢复函数，恢复成功后清理 open failure 与 migration 状态。
3. 为 open 失败后 `dispatchDbMigrationDoneEvent()` 的状态序列补回归测试：恢复按钮可触发 `restoreLatestPreMigrationBackup`，而不是 toast not found。

**验收**：

- `npm run typecheck`
- `npx vitest run src/hooks/useAppDataResilienceEffects.test.ts src/db/preMigrationBackup.test.ts`
- 若 overlay 交互测试已存在，追加相关 E2E 或组件测试。

### PR-2：Embedding mid-flight terminate 根因修复（P0）

**问题**：Embedding 相关 effect / provider config 引用不稳定时，运行中的 embedding 任务可能被 terminate，表现为随机失败。

**落点**：

- `src/ai/**/embedding*`
- 使用 embedding service 的 hook / controller
- 相关 worker lifecycle 测试

**方案**：

1. 先画清生命周期：创建、运行中、取消、配置变更、组件卸载、显式 terminate。
2. 将配置变化与运行中任务取消拆开：只有用户显式取消、provider 不兼容切换、页面卸载才允许 terminate。
3. 对 mid-flight provider config identity 变化补测试，断言同一任务不被中断。

**补刀（2026-06-01）**：

- ✅ `TranscriptionPage.AnalysisRuntime.tsx` 中 `deferredEmbeddingRuntime` 不再依赖 `embeddingProviderConfig` 对象引用，而是依赖由 `kind/baseUrl/model/apiKey` 组成的稳定 key；同值新对象不会重建 runtime，真实配置变化仍会重建。
- ✅ `TranscriptionPage.AnalysisRuntime.test.tsx` 补回归：rerender 等值 `{ kind: 'local' }` 不增加 `createDeferredEmbeddingRuntime` 调用；切换到 `{ kind: 'local', model: 'next-model' }` 才重建。

**验收**：

- `npm run typecheck`
- `npx vitest run` 聚焦 embedding service / hook 测试
- 若 worker 参与，追加 worker lifecycle 回归用例。


## 5. 不在本轮解决

- 不一次性重写 Dexie 全迁移系统；先建立诊断、spot-check 与 readback 测试，再逐步收紧。
- 不一次性重构所有 CSS；先堵新增债务，再拆最高风险 mega-file。
- 不在无产品拍板时承诺完整 PWA；先统一「是否承诺离线」的产品口径。
- 不为 token 计数引入重型依赖，除非能说明维护、体积、许可与 provider 兼容收益。
