# 解语 UI/UX 审查、修正与视觉落地实施方案

## 1. 目标与执行顺序

先检查现有设计与实际运行态，修正证实存在的问题，再落地已批准的新外观。执行次序为 **G0 全项目盘点与基线 → G1 UI/UX 审查 → G2 问题修正及复验 → G3 视觉基础 → G4 分模块迁移 → G5 桌面验收与灰度**。G2 未放行不得进入 G3；每个模块进入 G4 前重查自己的交互和真实状态。

本次交付是实施方案；后续实施逐切片执行、验证、复查 diff 并提交。方案不把既有截图、代码存在、静态规范检查或本地测试替代为完整运行验收。计划批准后从 G0 开始，而非直接改 token。

目标：完成任务时入口明确、对象明确、状态可信、内容可读、错误可恢复；新外观保持现代极简技术气质、清楚的平面分区和适当浮层立体感。禁止卡片层层嵌套，不新增业务功能。

## 2. 已读事实与限制

1. 路由事实源为 `src/App.tsx`；当前产品形状见[仓库现状](../../architecture/仓库现状与代码地图.md)。
2. 转写、标注、词典、语料库有可运行入口；分析受限，`/writing` 重定向至语料库，不设计虚构工作台。
3. 语言资产路由复用转写上下文；首页、设置、项目/媒体/层管理同样在范围内。
4. 主题复用 `src/styles/tokens.css`、`src/utils/theme.ts`；控件复用 `src/components/ui/`，遵循 `DESIGN.md`。
5. 页面层只装配；`ReadyWorkspace` 的文档域、波形壳层和交互 controller 保持现有边界。
6. 上轮只做了转写页部分运行检查。标准桌面多面板组合、全项目任务链、200%字号、受控刷新读回仍待执行。
7. 670×988 的遮挡是窄窗口观察，不能直接判定标准桌面 UI 缺陷；恢复/同步提示是待复现现象。
8. 新建转写层显示翻译专用说明及声学面板开发术语已有代码依据，仍应留下对应运行证据后修正。
9. 不把导入后自动聚焦、非模态窗遮挡或快捷键行为一概判错，先对照任务意图和现有合同。
10. ADR-0064 仍规定冻结；G0 核对 #275、#325 的实际合入与桌面路径，不据旧文档推断当前完成度。冻结未解除时先做审查、bug/防丢数据修复；结构重构和外观迁移等待解冻或明确调整排期。

设计输入为本地 `.superdesign/stitch-ui-engineering.latest.html`、`stitch-ui-engineering-addendum.md` 与 `stitch-ui-spec.md`。这些是设计交付材料；历史自动生成 Stitch 画板不作为精确接口来源。实施细则见[SDD design](../specs/ui-ux-modernization/design.md)。

## 3. G0：建立可复现基线

### 当前执行切片：展开侧栏缺陷修复（2026-10-24）

- 已读事实：共享注册层只广播元数据；词典/语料/分析及语言资产的动态内容均受影响。转写与标注现有 portal 保持不变，不改 ReadyWorkspace 装配或存储。
- 成熟方案：复用 React `useSyncExternalStore`，为注册内容建立独立订阅，避免内容更新反向重绘整个壳层；遵循 APG 竖向 tabs 的上下键/焦点规则。无新依赖、无新 controller/service、无 schema/flag，不新增 SDD。
- 落位：`AppSidePaneContext.tsx`（UI state/effect）、侧栏现有 CSS owner（收缩/滚动）、`AnnotationWorkspace.tsx`（只移动既有 UI 装配）、设置 primitives/Modal（UI actions/关联语义）、中英词典（删除过时说明）。
- 验证：共享内容更新与不广播壳层的 Vitest；设置焦点/标签关联 Vitest；E2E 断言片段高度/首末项操作、空标注文件导航、词典保存读回和长文滚动、语料勾选后的统计、跨页与设置键盘。随后跑完整 `test:e2e:chromium`、`typecheck`、架构/CSS/文档/i18n/agent-evals 门禁。
- 用户“规划并修复”授权本切片直接实施。视觉换肤、资源弹窗重排和新增侧栏能力仍留在后续阶段。
- 切片验证：新增回归先复现3项单元失败后修正；最终8文件84项Vitest通过，完整Chromium `--workers=4 --retries=0` 为112通过/1既有Firefox用例跳过，0失败/0重试；typecheck、架构/CSS/面板、文档、i18n、R1–R8、agent-evals smoke 4/4通过。首轮6并发曾有2项重试，已保留历史日志，不将其冒充稳定通过。

- 核对分支、HEAD、工作区已有改动、运行命令、开发构建与 Electron 构建；保留用户未提交文件，在当前检出工作。
- 从路由、导航、菜单、快捷键、功能开关和组件调用链枚举真实可达功能；建立“页面—任务—对象—状态—入口—测试”表。运行不可达项注明原因。
- 使用独立测试 profile/测试数据目录和合成项目；不复用用户恢复快照、不清除原库。导入失败、删除、重置、权限和外部 AI 等场景仅在隔离数据上触发。
- 准备空项目、4段小项目、多文稿多层、长文本/长层名、多说话人、重叠/短语段、缺媒体/失效链接、IPA/组合字符/RTL、词典附件等确定性素材；密集/长媒体素材按实际渲染方式选取并记录规模。
- 基线截图尺寸：1440×1000（设计参考）、1280×720（紧凑桌面）、1920×1080（宽桌面）；窗口不足时通过隔离 Playwright 上下文控制视口，不修改已有用户页面或绕过浏览器访问限制。
- 记录默认字号、系统/应用字号放大、浏览器200%缩放的区别；记录主题、语言、DPR、版本、初始选择与滚动位置。截图、trace 与结论同号存档，证据清除内容和密钥。

**放行 G0**：表中每个入口都有负责人（默认当前执行者）、测试数据和验收方法；已知坏基线单列，不能把实施前就失败的测试计作新回归，也不能因此略过。

### 4.2 每个模块统一检查

1. **任务与信息架构**：首次使用是否知道下一步；高频操作是否绕路；对象、范围和主次操作是否明确；术语是否与真实业务一致。记录任务是否成功、误点/回退次数、需解释的位置，不能用“看起来清爽”替代。
2. **布局与可读性**：区域边界、视觉层级、字号/行高、长名称/截断、空白与密度、对齐、滚动归属、分栏拖拽、嵌套边框；禁止固定高度裁切放大文字。
3. **行为**：点击、双击、右键、拖动、滚轮、键盘、IME；当前项/选中/编辑/播放态区分；禁用原因、加载、取消、撤销、重复点击、异步完成后对象已切换。
4. **数据与信任**：输入→校验→写入→反馈→缓存/快照→受控重开读回；无成功写入不得显示已保存。AI建议、人工确认、未检查各自独立。
5. **失败与恢复**：缺媒体、导入不匹配、保存失败、断网、未配置服务、权限拒绝、数据库错误；输入保留、重试范围、不重复执行、不把错误变为空列表。
6. **可访问性**：Tab顺序、可见焦点、焦点不被完全遮挡、模态焦点归还、非模态窗可返回工作区；名称/角色/状态、对比度、点击目标、非颜色反馈、reduced-motion。波形等二维编辑保持专用滚动和可替代操作，不强行压成手机布局。
7. **性能**：相同设备/素材对比进入页面、首次播放、滚动/缩放/编辑响应；发现主线程长任务或重渲染才定向分析，修正不能降低原有可用规模。记录原始测量，不编造毫秒门槛。

审查记录模板：`ID | 任务/对象 | 复现前提和步骤 | 预期/实际 | 截图/trace | handler→写入→读回链 | 严重度 | 证据等级 | 修正方案 | 回归用例 | 状态`。证据等级区分“代码确认 / 运行复现 / 待复现 / 设计建议”。

## 5. G2：先修现有问题，再放行外观

### 5.1 首批核查队列

| ID | 当前依据与状态 | 核查/修正方向 | 必要验证 |
|---|---|---|---|
| UX-01 | 新建转写/翻译共用创建表单显示翻译专用说明，代码已确认 | 让字段/说明依实际层类型出现；不改层数据模型 | 分别走新建转写、翻译；校验、取消、提交、读回 |
| UX-02 | 声学面板开发阶段术语，代码已确认 | 文案改为用户可理解的现有能力/限制，保留未提供能力的事实 | 中英文、实际选区/无选区、导出说明 |
| UX-03 | 左状态条过密，已有截图 | 标准桌面复测后调整信息组织/操作目标；必要布局修正先在旧外观完成 | 缩放/增益/吸附读数、拖拽、键盘、200%字号 |
| UX-04 | 670px窄窗口 AI/声学竞争空间，待标准桌面确认 | 查现有窗口拖动/收起与焦点合同，确认问题后修初始位置/约束；不擅改为模态或互斥 | 多面板组合、缩窗、恢复、焦点/选择/草稿不丢 |
| UX-05 | 切项目后恢复摘要现象，待隔离复现 | 追 `useRecoveryBanner`→检查/应用快照→项目作用域；若证实旧结果残留，在共享根因修正 | 两隔离项目、慢请求/切换、取消/失败、受控重开读回 |
| UX-06 | 协同未启用仍出现同步未保证提示，待根因核查 | 追提示事件来源和真实本地写结果；按本地/未配置/排队/失败分别反馈 | 未配置、离线、配置后失败；桌面剔除路径不能显示云可用 |

上轮报告中的 P1/P2 是审查优先级，不等于全部缺陷已复现。G1 新发现的问题按同一模板入队。

### 5.2 修正与放行规则

- P0：数据丢失、越权、错误项目写入、无法恢复的阻断；立即处理并暂停受影响任务。
- P1：核心任务无法完成、操作不可达、严重误导保存/对象状态、键盘/字号下关键控件失效；外观迁移前全部修正并复验。
- P2：增加负担的真实问题（文案、密度、重复入口、错误提示、状态混淆等）；进入外观前修正。跨功能的大改必须先形成具体设计并确认，不以“换皮”掩盖。
- 纯视觉偏好列入 G3/G4；待复现项先核查，不能直接删入口或改业务语义。若是预期行为，写明依据并关闭，不做无效改动。
- 每个修正只动根因和必要调用方；复用现有测试补一个能失败的业务回归，修后通过；不顺手重构或升级依赖。
- **放行 G2**：全项目覆盖表没有未评估的开放入口；P0/P1/P2确认问题均已关闭并有证据；待复现的核心/数据风险已确认或按阻断处理。可接受的纯外观项明确转入 G3，不留“后面再看”的关键 UX 债务。

## 6. G3：视觉基础与工程交接

G2通过后，校正设计稿，使其反映修正后的真实交互，再实现视觉基础。

- 设计方向：石墨导航轨、浅灰上下文栏、白编辑面、紫色主强调；适度阴影仅用于浮层/模态；编辑内容和状态一目了然。
- 对接 `tokens.css`、`theme.ts`、`DESIGN.md`；复用现有外观/强调色机制。新外观若需新 ThemeId，注册展示与持久化映射，不覆盖用户已有外观选择。暗色和系统模式跟随现有机制，先验证再展示可用。
- UI大改用注册表中的单一布局试运行 flag（拟名 `modernWorkspaceUiEnabled`，默认false，命名实施时查重）。flag只管视觉装配，主题只管配色；共用同一数据/handler，不复制新旧工作区和业务逻辑。
- 新视觉选择器作用域明确：flag关闭和旧主题不应被全局 token/控件改动意外覆盖。已修正的行为问题在新旧外观均有效。
- 先用真实 `PanelButton/FormField/ModalPanel/PanelFeedback` 做组件状态对照：默认、悬停、按下、焦点、禁用、加载、错误、成功；使用真实API，不造一套展示组件代替产品组件。
- 完成颜色/字号/间距/控件/分栏/层级/密度/图标/动效映射；中英文及IPA/RTL检查。面板边框最多两层，IGT/词典详情用平面行和分隔。
- 设计数值见已有规范：1440×1000参考，52px功能轨，240–320px上下文，正文14/22、密集12/18、标准控件最小32px；为默认值，放大时允许增长，不能裁切内容。

**放行 G3**：真实组件状态、浅暗主题对比度、旧外观隔离、键盘焦点、尺寸放大均验证；没有新增组件库/字体下载/CDN运行依赖。

## 10. 成熟方案取舍

复用既有控件、主题、CSS owner和交互controller；适配成熟交互原则，不新增UI框架、面板管理器或通用状态机。

- [WCAG焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)：核对焦点可见和可揭示条件，不能以任意浮窗重叠就判违反标准。
- [WCAG点击目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：24×24或符合间距/等价/内联等例外；解语常用控件32px是自己的设计选择。
- [Carbon空状态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)：按首次使用、无结果、缺数据、失败给出下一步，避免统一“暂无数据”掩盖错误。

这些来源支撑行为与审查方法，不能证明解语当前已合规。没有新增依赖，因此没有新增包体、许可和维护成本。
