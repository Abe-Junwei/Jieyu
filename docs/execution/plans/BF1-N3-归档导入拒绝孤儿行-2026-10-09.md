# BF1-N3: reject orphan rows at archive import (JYT / JYM / JYB). Plan only, no code

- **Baseline read:** `feat/rev5-integration` @ `926b05f2` (read-only, via `git archive` from the Mac repo; the main checkout was not switched or edited).
- **Depends on:** `fix/review-bugs-1` being merged into rev5. It provides `JIEYU_PARENT_CONSISTENCY_RULES` (GAP-1 + BF1-N2). At 926b05f2 the ownership middleware has no parent rules at all.

## 1. The problem in the archive paths

### How the export produces orphans
- The export filter `db/projectScopedSnapshot.ts` keeps rows by their own `textId`.
- Example: a token of project P whose `unitId` points at a unit of project Q is exported, but the unit is not. That kind of pre-fix data is exactly what BF1-N3 / BF1-GAP1-3 plant.
- Result: the package contains a child row whose parent is not in the package.

### How import makes it worse
- `projectPackageIdRemap.ts` remaps every id it finds in the package. A dangling reference keeps its old id.
- **Restore-as-new / overwrite of another project:**
  - The orphan token lands in the new project still pointing at `unit-Q-old`.
  - If that id exists locally (e.g. restoring a JYT exported from this same library), the result is a cross-project link.
  - With the merged GAP-1 middleware, this makes the whole restore throw at commit time, after the preview said everything was fine.
  - If the id is absent locally, the middleware skips the check ("parent absent"), and the orphan is written silently. This is BF1-N3.
- **JYB disaster restore:** ids are not remapped, so the same thing happens.

## 2. Import paths in scope

There are two inspectors, and every path goes through one of them before any write:

| Package | Preview | Commit paths | Inspector |
|---|---|---|---|
| JYT / JYM | `previewProjectPackageRestore` (`previewJytRestore`, `previewJymRestore`) | `restoreProjectPackageAsNew` → `prepareRestoreAsNew`; `overwriteProjectWithPackage` → `planOverwrite` | `inspectProjectPackage` (`projectPackageService.ts`) |
| JYB | `previewJybRestore` | `importJybProjectsAsNew` (per project → `prepareRestoreAsNew`); `disasterRestoreFromJyb` (`mergeForDisasterRestore`) | `inspectJyb` (`JybService.ts`) |

The plain JSON import (`db/io.ts importDatabaseFromJson`) is out of scope here. It is a follow-up if wanted; the same helper applies.

## 3. Where detection goes: in the inspector, so preview and commit share it

- Detection runs once in each inspector:
  - `inspectProjectPackage`: right after `checkProjectScope`.
  - `inspectJyb`: per project, right after `checkLibraryScope`.
- It runs before `attachIncludedBytes`, the language drop and the id remap, so ids are still the package's own.
- Preview and every commit path already consume `inspected.*`, so:
  - the preview shows exactly what the commit will do;
  - there is no second implementation, and no extra DB read (the check is pure, on the package data).
- **Behaviour: drop the orphan rows, don't reject the package.**
  - This mirrors the existing `skippedLanguageIds` / `dropCollidingLanguages` pattern.
  - Rejecting the whole package would make a user's own backup unrestorable whenever their library holds pre-fix bad data. That would be data loss by refusal.
  - The dropped rows are unreachable in the UI anyway: a token without its unit, a segment without its host.

## 4. Tables and parent refs

There is no new table list. Reuse `JIEYU_PARENT_CONSISTENCY_RULES[table].extract(row).parents` from `ownershipImmutabilityMiddleware.ts`:

| Child table | Parent refs |
|---|---|
| `layer_units` | `parentUnitId` → layer_units; `rootUnitId` → layer_units (segments) |
| `layer_unit_contents` | `unitId` → layer_units |
| `unit_tokens` | `unitId` → layer_units |
| `unit_morphemes` | `unitId` → layer_units; `tokenId` → unit_tokens |
| `token_lexeme_links` | `targetId` → unit_tokens / unit_morphemes (by `targetType`); `lexemeId` → lexemes |

- **Rule:** a ref is an orphan when its id is not a row id of the parent collection in this same package (the same project, for JYB).
- **Fixed-point loop:** a dropped unit takes its segments, then their contents, then tokens, morphemes and links. Iterate until nothing more drops. Depth is at most 4, and each pass is O(rows) with `Set` lookups.
- **Open decision: `token_lexeme_links.lexemeId`.**
  - The export only packs lexemes with `textId === project`. A link to a global or other-project lexeme would therefore count as an orphan.
  - Default proposal: drop it too. It would hit the GAP-1 cross-project check on commit anyway.
  - Needs confirmation that lexemes are always project-owned in rev5.
- **Notes:** user notes are already filtered by `noteBelongsToProject` on export and are not part of this change.

## 5. Reporting to the user

- **Type:** add `skippedOrphanRows: Array<{ collection: string; count: number }>` next to `skippedLanguageIds` on:
  - `ProjectPackageRestorePreview`
  - `JybRestorePreview` (per project)
  - the restore / overwrite / JYB results
- **Hub:**
  - `useImportExport.archiveHandlers.ts` maps it the same way as `skippedLanguageIds` (lines ~163 and ~218).
  - `LeftRailProjectHub.tsx` shows one line where it shows skipped languages (~line 1169). New i18n key `transcription.importExport.skippedOrphanRows`, for example zh/en: "{count} 条记录引用了包中不存在的上级记录，将被跳过：{collections}" / "{count} rows reference records that are not in this package and will be skipped: {collections}".
- **Logging:** log once at warn level with per-table counts, no row content.
- This is not an error and the restore goes ahead, matching the skipped-languages behaviour.

## 6. Ponytail-minimal shape

- **One pure helper** next to `dropCollidingLanguages` in `projectPackageService.ts`:
  - signature: `dropOrphanRows(collections) → { collections, skipped }`;
  - built on the middleware rules;
  - about 30 lines.
- **Two call sites:** the two inspectors. They add `skippedOrphanRows` to `inspected`.
- **Plumbing:** the field is passed through 4 result/preview builders, plus 1 UI line and 2 i18n strings.
- **What we don't build:**
  - no new error code;
  - no option to keep orphans;
  - no DB-side lookup;
  - no repair UI.
- Shortcut comment to leave: `shortcut: orphans are dropped, not repaired/re-parented; upgrade if users need to recover rows from damaged backups`.

## 7. Interaction with the ownership middleware

- **After this change:**
  - Restore-as-new / overwrite: every remaining parent ref points at a row in the same package, and the remap gives those rows fresh ids in the same new project. The middleware check therefore always passes, so commit no longer fails after a clean preview.
  - Disaster restore: the library is wiped first, and parents are in the package.
- **The middleware stays as the backstop** for live writes and the JSON import. Neither `writeValidationMiddleware` nor migrations are touched.
- **Merge prerequisite:**
  - `io.ts` from fix/review-bugs-1 (parent tables written before children: `childWriteRank`) must be in rev5.
  - Otherwise in-package parents listed after children are invisible to the check, and orphans are not the issue.
  - Extend `childWriteRank` with `layer_unit_contents` after `layer_units` if it isn't there already. Segments in the same `layer_units` bulk are fine: an absent parent is skipped, and the package-side check already guarantees that the parent exists.
- **Remaining live-write gap:** BF1-N3 in its original form (a token put before its unit exists in normal app use) is not addressed by this plan. It stays documented: the reverse check on every `layer_units` write is too costly.

## 8. Tests

1. **Unit (pure, table-driven) for `dropOrphanRows`:**
   - a token with a missing unit;
   - a morpheme whose token was dropped (cascade);
   - a link to a dropped token;
   - a segment with a missing `parentUnitId` / `rootUnitId`, plus its content;
   - a content with a missing `unitId`;
   - a link with a missing lexeme;
   - valid rows untouched;
   - an empty package returns the same object (no-op).
2. **JYT (JYM shares the code):**
   - plant pre-fix data in project P (token → unit of Q, the BF1-GAP1-3 trick);
   - `exportProjectToJyt(P)`, then `previewJytRestore`: `skippedOrphanRows = [{unit_tokens, 1}]`;
   - `restoreJytAsNewProject`: the restored project has no such token, and no row points at a non-restored id;
   - overwrite-current: same expectations.
3. **JYB:**
   - the same planted data in one of two projects;
   - per-project import: the counts are attributed to the right project;
   - disaster restore: the orphan is absent after the restore.
4. **Regression:** restoring the same package into a DB where `unit-Q-old` exists locally does not throw `JieyuParentOwnershipMismatchError`. Before the fix it fails at commit.
5. **UI:** one assertion in the existing LeftRailProjectHub import-preview test that the skipped-orphans line renders.
