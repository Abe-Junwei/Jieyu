# 文件交换丢失清单

决策见 [ADR 0037](../../adr/0037-interchange-loss-report.md)。本文保持 `active`，代码落地前不标完成。

枢纽不变。词条编辑基准是 DMLex（[ADR 0035](../../adr/0035-lexicon-edit-baseline-dmlex.md)）。EAF 往返维持 [ADR 0036](../../adr/0036-eaf-import-is-interchange.md)。整库原 id 仍是 `.jyt` / `.jym`。

对照过的做法：Pepper 的导入 / 加工 / 导出、Corflow 的文稿-层-段、reBabel 的写出前映射、LIFT 规范里「交换格式不是内部格式」。不把这些运行时接进来。

## 1. 现在丢什么

| 格式 | 现在 |
| --- | --- |
| EAF | 缺媒体、无法识别的时间单位、对不上的译文、无媒体跳过的独立层，拼在完成提示里。层角色确认已经落地 |
| TextGrid | 第一条 IntervalTier 当转写，其余进附加层。没有丢失清单，没有角色确认。层名里的 `__jieyu_meta_` 只带回正字法 |
| TRS | 说话人方言和口音已经写入说话人。没有标注 id。没有丢失清单 |
| flextext | 第一篇 interlinear-text 当转写，其余进附加层。phrase guid 只用来对齐 phrase gloss，不当往返键 |
| Toolbox | 与 flextext 相同的第一条获胜。没有标注 id |
| LIFT 0.13 | 非 0.13 整文件拒绝。`entry@id` 按 id 覆盖。对不上 DMLex 的字段进诊断码，界面只显示条数 |

`useImportExport.importHandlers.ts` 已接近行数上限。清单的代号和文案组装放在新的纯函数里，该文件只调用。`useImportExport.ts` 不再加 hook。角色确认继续用现有的待处理状态，不新开 controller，因此本计划不写 SDD。

## 2. 清单代号

`src/utils/interchangeLossReport.ts` 定义封闭代号。每条可以带计数或一个名字（文件名、层名、诊断码）。字典按代号出句子。

| 代号 | 何时写 |
| --- | --- |
| `missing-media` | 媒体文件名对不上已有媒体 |
| `unrecognized-time-unit` | 时间单位无法识别，已按毫秒读 |
| `unmatched-ref` | 有引用但父标注对不上，没有改用时间窗 |
| `skipped-tier-no-media` | 独立层因为没有媒体被整段跳过 |
| `dropped-translation` | 译文对不上宿主 |
| `unmapped-field` | 看见了字段，但没有写入枢纽。LIFT 用现有诊断码当名字 |
| `no-stable-id` | 该格式没有可往返的 id，本次会新建 |
| `replaced-by-id` | 稳定 id 对上，覆盖了已有条目或语段 |
| `appended-without-id` | 文稿里已经有语段，这次又追加了一批 |

EAF 现有四句完成提示改由前五个代号格式化，用户看见的意思不变。已经写入层、语段或 DMLex `entry` 的内容不进清单。

## 3. 切片

每条先有失败测试，再改生产代码。未打开确认开关时，层归类与现在相同。

### 3.1 清单类型和 EAF 完成提示

EAF 解析结果改为填清单。完成提示从清单格式化，不再在导入处理里手拼句子。

验证：无法识别的时间单位、缺媒体文件名、对不上的译文、无媒体跳过的独立层，完成提示仍包含现在的句子。没有这些情况时，提示只有导入条数。

### 3.2 其余标注格式填清单

TextGrid、TRS、flextext、Toolbox 的解析结果带上同一份清单。只记录它们今天已经发生的猜测或丢弃，不新增加丢弃规则。文稿里已有语段、且该格式没有稳定标注 id 时，写 `appended-without-id`。

验证：空文稿导入 TextGrid 不出现 `appended-without-id`。同一文稿再导入一份没有标注 id 的 TextGrid，清单里有这条。flextext 带 phrase guid 时不把 guid 算成「没有 id」。

### 3.3 词典诊断说出代号

LIFT 界面在条数之外列出诊断码的字典名。码仍只留给没有写入 `entry` 的字段。先对照 `parseLiftXml` 和 `lexiconLiftExport`：已经投影的字段停止报丢失。

验证：含未投影字段的 0.13 文件，导入后的提示能看出是哪一种代号。只含已投影字段的文件，诊断为空。非 0.13 仍整文件拒绝，不写词条。

### 3.4 TextGrid、flextext、Toolbox 的层角色

两个及以上独立层、文件没有角色、文稿也没有保存过角色、并且生产路径打开了确认时，复用现有层角色对话框。词层和语素层不出现在表里。默认确认：第一条转写，其后独立层翻译。TRS 不弹窗。

EAF 继续读写 `eafTierRoles`。另外三种把角色写进新的文稿元数据键，键名在实现里定一处常量。不新增 Dexie 版本。

确认开关沿用 `useTranscriptionImportExportInput` 已有的那个布尔值，调用处改成对全部标注格式生效。测试直接调用 `useImportExport` 时不传该开关。

验证：两层 TextGrid 在开关打开且未确认时不写语段，对话框里的层名与文件一致。确认默认角色后，第一条层的正文在转写里，第二条在翻译里。不传开关的现有 TextGrid 测试，语段条数和层归类不变。

### 3.5 有 id 才往返

flextext 的 phrase guid 非空时，按当前文稿加 guid 更新已有语段，规则与 EAF 的 `externalRef` 相同。对不上才新建。LIFT 覆盖已有 `entry@id` 时写 `replaced-by-id`；条目没有 id 时写 `no-stable-id` 并新建。TextGrid、TRS、Toolbox 不生成假标注 id。

验证：同一 phrase guid 的 flextext 导入两次，语段条数不增加，正文更新能读回。另一篇文稿上的相同 guid 不被改写。没有 id 的 LIFT 条目导入两次得到两条词条，并带 `no-stable-id`。
