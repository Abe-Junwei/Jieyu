# 卡片文件、项目与删除恢复改造方案

本页是待执行步骤，不表示代码已经实现。

| 状态 | 现在 |
| --- | --- |
| 产品与格式决定 | 已接受：[ADR-0058](../../adr/0058-card-sqlite-file.md)（卡片语义、隐藏、垃圾箱）、[ADR-0060](../../adr/0060-card-file-ownership-and-operations.md)（项目库分工、定义副本、清单缓存、操作 id、同名合并时机）和 [ADR-0061](../../adr/0061-jyd-manuscript-file-audio-stays-plain.md)（文稿是 `.jyd`，音频保持原文件，声文稿只是展示）。 |
| 工程可发布 | 未通过。现有检查只用 `node:sqlite` 和十几个字节证明一种复制情形；better-sqlite3、大音频、异常退出、文件移动和满盘都没测。 |

浏览器构建仍为 Dexie；真实用户库中的六条同名录音尚未逐 ID 验证，不做同名批量清理。

## 证据与取舍

- [Zotero 的附件与缺失文件说明](https://www.zotero.org/support/attaching_files)区分资料条目、受管副本与外部原件。解语沿用“导入复制、绝不删除项目外原件”，但**不照搬** Zotero 的条目/文件分离真源。
- [SQLite 外键说明](https://www.sqlite.org/foreignkeys.html)提供逐关系的 `RESTRICT`、`SET NULL`、`CASCADE`；必须在每个连接启用并验证，不以全表级联代替产品规则。
- [SQLite WAL 说明](https://www.sqlite.org/wal.html)指出 WAL 模式会出现 `-wal`、`-shm` 附属文件；“一张卡是一个可搬运文件”必须通过打开、关闭、复制、移动、异常退出的实测证明，不能只改扩展名。[SQLite Backup API](https://www.sqlite.org/backup.html)是制作一致性副本的候选，不能在数据库仍打开时普通复制主文件并声称得到完整卡片。
- [Electron `shell.trashItem`](https://www.electronjs.org/docs/latest/api/shell/)只负责把路径送进系统垃圾箱，返回完成或失败，不提供从垃圾箱查找及一键还原的句柄。因此恢复由用户先在系统文件管理器操作，应用只检测已还原到项目的文件。

取舍：保留项目文件夹作为容器。音频原样放在文件夹里；每份文稿是一个 `.jyd` SQLite 文件；声文稿是看板上的组合，没有对应的单个文件（ADR-0061）。项目库存语言、正字法、说话人等共用定义和音频登记；`.jyd` 只带一份副本供跨项目导入时对比；卡片清单和看板统计是 userData 里可重建的缓存（ADR-0060）。采用存储端业务操作与有操作 id 的可恢复记录，而不是让页面跨文件和数据库自行拼事务。

## 已确定的产品规则

| 主题 | 目标规则 |
| --- | --- |
| 卡片与真源 | 录音卡片是一个音频文件，文稿卡片是一个 `.jyd`，声文稿卡片是一个音频加引用它的 `.jyd`。卡片清单不是第二份内容真源。项目可以没有卡片。 |
| 内容上限 | 一卡最多一条音频，可有多份文稿；音频独有、文稿独有、声文稿三种状态都有效。每个语段只属于一份文稿，音频是可选的对齐对象。 |
| 身份与文件名 | 音频、文稿、语段都有稳定 ID，存在项目库和 `.jyd` 里。文件名是用户能读的名字，不加 ID（如 `录音01.wav`、`录音01.jyd`、`录音01 (2).jyd`）。配对是在 `.jyd` 里写下音频引用，拆开是清掉它。 |
| 导入与跨项目复制 | 导入复制用户原件，不移动或删除原件。卡片文件可移到别处并导入另一项目；复制导入重新分配卡片及内部对象 ID，保留原始 ID 作为来源信息。恢复回原项目则保留原 ID。目标项目缺语言、正字法或层定义时，先展示差异供映射或导入，不静默改配置。 |
| 自动配对 | 音频与文稿唯一同名时自动合并，已有卡片改名形成唯一同名也立即合并，可再拆开。同名多条或不同名不猜测，由用户指定。实施时须以临时项目和多 ID 用例固定“同名”的规范化规则；旧版“同名只建议、不自动关联”的行为须由新 ADR 明确取代。 |
| 删除音频 | 把音频文件送进系统垃圾箱，`.jyd` 及其语段保留，卡片成为文稿卡；仅删字节、留缺音录音位置是**另一种动作**，不能共用“删除音频”文案。 |
| 删除文稿 | 把那个 `.jyd` 送进系统垃圾箱，语段随它走；其他文稿与音频保持。 |
| 恢复 | 用户把文件放回项目后，只有一条哈希或文稿 id 对得上才认回。有多条候选时停下问用户。主动删除、意外不见、字节不在本机要能区分。绝不覆盖已有文件。 |
| 整卡与项目删除 | 整卡文件、整个本机项目文件夹分别送进系统垃圾箱；项目删除包含“已隐藏”。不另设应用内 30 天保留期，不承诺应用内一键从系统垃圾箱恢复。协作项目的本机删除不触发云端删除，云端删除另行决定。 |
| 隐藏 | 把卡片的全部文件（音频和引用它的 `.jyd`）移到项目内“已隐藏”子目录；主看板不显示，移回即可恢复。不是只改一个 UI 标记。 |

“自动同名合并”和“外部复制导入”是入口规则，不授权按同名、时长或哈希批量删除。内容相同也不替代稳定 ID 与明确的冲突处理。当前浏览器 Dexie 操作不代表上述桌面语义已经落地。

## 先止住当前路径

当前浏览器代码中的 `removeEmptyRecording` 会把已有句段、锚点改挂 `__unknown_media__` 后删除媒体行。这与“语段归文稿、局部删除可单独恢复”的目标不同。桌面新模型批准前，不继续扩展这条路径；单列审查它对真实数据的影响并决定保留为浏览器旧行为、收紧门禁，还是在迁移中替换。不要靠撤销整个工作区或同名清理脚本处理它。

截图中的六条同名录音仍要先做**只读**诊断：分别记录 `mediaId`、字节状态、所属文稿、句段/锚点和来源关联；在可恢复副本与新操作验收前不对真实用户库做批量删除。

## 执行顺序与完成条件

每一步都以关闭后重新打开、逐 id 与逐字节读回验收。前一步没通过，不进下一步。

1. **补全规格。** 能整表划定的归属写在规格里。`unit_relations` 和 `user_notes` 按每行所指对象，不靠一个 `home` 字段。认回在多个同哈希时必须问用户。同名检查包括「已隐藏」，唯一候选在隐藏里时返回需要选择。这些已写入 [ADR-0062](../../adr/0062-desktop-storage-decisions-2026-10-16.md)，仍不据此冻结（D14 另见 [#259](https://github.com/Abe-Junwei/Jieyu/issues/259)）。
2. **真实驱动原型。** 用 better-sqlite3（需新增这个原生依赖，并随 Electron 重新编译）在临时目录里测：回滚日志模式下万句级 `.jyd` 的连续编辑速度；关闭后只剩一个文件、复制到别处可读回；满盘时导入失败、不留半个文件；写到一半强制退出后重开。现有 `node:sqlite` 检查（`node --experimental-sqlite --test scripts/card-file-portability-check.mjs`）只算前期证据，不算这一步通过。
3. **文稿与项目库读写、清单重建。** 实现 `.jyd` 的创建、打开、关闭、按 id 读写及完整性检查；清单扫描重建，重建不改 id 和配对。导入复制原件并核对 sha256，原件保留。
4. **旧数据迁移。** 从 Dexie/现有项目结构导出到临时目录，逐 ID 构建卡片，验证数量、文本、时间码、哈希/可播放性、来源链及默认文稿，再以可回滚的迁移标记切换入口；失败保留旧库和迁移日志，不做半迁移覆盖。多文稿共享录音、来源原件字节不存在和同名多 ID 均有明确结果。
5. **卡片操作。** 建立配对、拆开、改名、隐藏、复制导入、删除音频或一份文稿、整卡删除的一次用户动作入口。页面只发出动作，不接触连接、路径或垃圾箱。跨文件的动作先分配操作 id 并写阶段记录，重启后按操作 id 续做，不按同名重做。任何一步失败不得以“已删”掩盖仍存在的内容，已提交但看板未刷新要显示视图待刷新。
6. **恢复与项目删除。** 垃圾箱拒绝时文件留在原处并提示未完成。打开项目及目录变更时识别放回的文件：唯一匹配才认回，多条候选停下问用户。项目删除先关闭所有连接并处理日志文件（含 `-journal`），再移动整个项目文件夹；失败时项目仍可打开。备份替换不在这一步：ADR-0046 第 6 条的每日 JYM 仍有效。
7. **发布验收。** 定向服务与合同测试、迁移故障注入、Chromium 交互测试和目标桌面系统的真实文件测试全过后，才把看板切到目录文件为真源。核对 JYM/JYT、快照、深链及跨项目导入。不要用“按钮消失”、mock 调用次数或临时文件存在替代关闭后读回。

## 必测故障与验收矩阵

| 场景 | 必须看到的结果 |
| --- | --- |
| 两条同名音频、多份同名文稿；导入或改名触发唯一匹配 | 只有满足唯一性的那一对配对；音频与文稿 ID 不变。可拆开并重新打开。 |
| 从声文稿删除音频或其中一份文稿 | 那一个文件进入系统垃圾箱，其余文件可打开；项目外原件不动。语段只随其 `.jyd` 走。 |
| 删除声文稿卡片中途崩溃、垃圾箱拒绝其中一个文件 | 重启后按操作 id 续做或显示未完成；没送走的文件仍可打开；不显示虚假的最终成功。 |
| 用户从系统垃圾箱还原音频或 `.jyd`；只有一条对得上、有两条相同哈希、位置已被占用 | 唯一匹配才认回；两条相同哈希时停下问用户；位置被占用时不覆盖。 |
| 隐藏、取消隐藏；索引丢失或看板刷新失败 | 文件确实进出“已隐藏”；扫描能重建主/隐藏列表；提交成功但视图未刷新时给出待刷新提示。 |
| 最后一份文稿删除、音频独有卡删除、整项目删除 | 不留空卡；整卡或整个项目文件夹进系统垃圾箱；项目外导入原件保持不变。 |
| 卡片复制到另一项目、定义不兼容、ID 冲突 | 新 ID 与原 ID 来源可读回；先展示语言/正字法/层差异；取消时目标项目没有半导入行。 |
| 满磁盘、突然断电、SQLite 连接未关闭、日志残留 | 不能生成外观看似完整而实际缺内容的 `.jyd`；失败可诊断，旧文件可恢复，关闭后单文件复制到临时目录仍可独立读回。 |

验收只使用临时项目和合成测试材料，不读取或上传用户真实语料。决定已接受，但工程可发布前本页仍为 `proposed`；实施完毕后依 [ADR-0051](../../adr/0051-every-doc-type-has-an-end.md) 删除本计划，Git 历史保留记录。
