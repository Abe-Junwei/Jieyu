## 四层交付（每片与总产物）

上一版若只按用户流程分片、却未规定交付界面，会停在设计稿或接口读回。本清单把 **UI 当作每片主交付**：先对账，再设计工作区，再按界面完整操作落实代码。

| 层 | 要回答的问题 | 产物形态 |
| --- | --- | --- |
| **1. 页面结构** | 主区域、辅助区域、跨页入口；用户如何工作 | 转写 / 标注 / 词典 / 语料（及最小分析只读）分区说明；禁止「功能各挂一个输入框」拼页 |
| **2. 控件与交互** | 入口、选中、点击/拖拽/快捷键/菜单；加载/编辑中/保存中/失败/空结果；切页草稿；撤销与结果可见位置 | 可实现、可验收的 UI 规格（例：改边界须写清时间轴选中→拖动→预览→提交→报错→撤销及播放同步） |
| **3. 组件复用映射** | 区域 → 现有文件 → 原样复用 / 调整 / 拆分 / 重做 → 读写与刷新接口 | 映射表；简化桌面页写明保留、合并或退出；防重写成熟时间轴/波形/义项表单 |
| **4. 可操作页面验收** | 产品路由真实界面 + 单库业务 + 完整状态 + Electron 操作与重开 + 视觉/焦点/键盘/滚动/窗口 | 用户能在实际桌面应用里完成该片任务；设计稿可评审，交付不止于假数据或孤立组件 |

**计划级最终产物（四项）**：功能对账表（账本）· 四页工作区设计 · UI 实施映射 · 真实桌面页及验收证据。  
**切片结束条件**：界面上真的能用；「接口已实现、数据能读回」不算页面完成。Chromium 门槛仍按 #329 逐组替换，不因桌面页绿了提前撤。

## 总原则

1. **A+B**：写入走具名业务入口 → 成功后领域事件 → **统一**映射为 TanStack Query 失效 → 重读已保存数据。禁止多路重复重拉；草稿/播放头/选区/撤销不进 Query。
2. **每片交付结构**：对应该片的第 1–3 层（功能与关键流程 → 布局/关键状态 → 精稿与组件映射）→ 第 4 层 Electron 真机接线验收（含重开）。可按用户流程分片，但片内必须带齐相关四层。
3. **顺序**：转写 → 标注 → 词典 → 语料；共享能力可提前；**跨页验证不因顺序阻塞**；最小分析只读单列。不做四页瀑布设计完再写代码。
4. **Legacy**：逐项接替、逐项退出；文案/文档标明旧入口数据源（Dexie 等）≠ 单库实时。Electron 内不回落 Legacy，延期能力在桌面标「桌面暂不可用」，不以 Legacy 保留作连续性证据，不恢复双库写入。
5. **改库**：仅显式迁移决策；UI 重排本身不是理由。
6. **冻结依据（ADR-0086）**：M4-C 已落地，本计划各片属「既有首发能力的 SQLite 接替」白名单；该白名单不含新功能，任何「新增」行开工前须单独确认。
7. **Feature flag**：切片 1 起替换用户已在用的桌面页（转写壳、IGT、完整词典、语料页）时，新界面套 flag 默认 `false`，自用一周后切默认；旧桌面简化页在 flag 关时保持原样。切片 0 **不套 flag**（已拍板；含离开确认框，出问题整片 revert）。
9. **精稿先行（已拍板）**：切片 1–6 各自的 Figma 精稿（区域分工、主操作、键盘流、加载/保存中/失败/空态、组件映射）定稿后才开该片代码。切片 0 与 P0a 不等精稿；等待精稿期间优先做 P0a。
10. **验收分工（已拍板）**：代理用合成项目跑 Playwright Electron（打开 → 操作 → 关应用 → 重开读回），用例进 `tests/e2e-desktop/`；用户每片末用木雅会话抽验，未抽验不标完成。代理不读写真实材料（D14）。
11. **优先级（已拍板）**：四页优先于 #312/#313/#277。
8. **SDD**：切片 0 引入新模块（事件、查询键、离开拦截），按 §5.2.1 写三件套，见 [desktop-4ws-slice0-text-save](../specs/desktop-4ws-slice0-text-save/)；其余各片开工前各自补。标注/词典/语料 PR 须过 `check:r1-r8`。

## 切片 0 · 转写一条真实读写链路 + 最小 A+B（第一刀）

| 项 | 内容 |
|---|---|
| **目标** | 选定**一条**现有转写编辑流程（建议：选中语段 → 改正文 → 保存），在桌面单库上打通：读 → 存 → 事件 → Query 刷新 → 切页/切文稿失败保护 → 重开读回。不先做全库基建或全量搬迁。 |
| **交付物** | （1）领域事件最小总线（写成功才广播）；（2）TanStack Query 接入桌面读路径（该链路相关 keys）；（3）**统一** event→invalidate 映射表（单处）；（4）该流程的 UI 接线（可用过渡表单壳）；（5）切库/切会话隔离；（6）#12：合法可提交则切走自动存；失败留草稿、拦静默离开、重试或明确放弃；（7）设计侧：本流程关键状态（加载/错/保存中/失败）列清即可，完整转写精稿可并行在 P1 |
| **依赖** | 现有 `units.updateText`（或所选等价入口）；`desktopCall`；开项目会话 |
| **隐含前置（审查新增）** | （a）**路由**：`src/main.tsx` 用声明式 `<BrowserRouter>`，React Router 7 的 `useBlocker` 只在数据路由下可用。按官方渐进做法换成 `createBrowserRouter([{ path: '*', element: <App /> }])` + `RouterProvider`，`App.tsx` 里的 `<Routes>` 不动；须跑全量 Chromium E2E。（b）**关窗**：Electron 里 `beforeunload` 返回值会静默取消关窗，主进程要接 `will-prevent-unload` 弹确认，否则「拦静默离开」只拦了切页没拦关窗。（c）**过渡期双机制**：`useDesktopProjectReadController`（414 行）其余 6 个写入仍是写后手动 `reload()`；本片只迁正文一条，须写明过渡规则：正文保存只走统一失效，不再调 `reload()`；其他写入暂留，按片逐条迁。新逻辑放新 hook，不加进该 controller。（d）**QueryClient**：`main.tsx` 全局 `staleTime` 5 分钟（为语言资产设）；桌面键须带 `sessionId`，并显式设自己的 `staleTime`，不吃全局默认 |
| **不做** | 波形/时间轴全量接入；四页全量搬 Query；把草稿/播放头放进缓存；失败仍广播 |
| **验收** | • 保存成功 → 仅统一失效路径触发重读 → 列表/详情已保存值更新<br>• 保存失败 → **无**成功事件、UI 保留草稿、不能静默离开<br>• 切项目/切会话 → 旧请求结果不覆盖新状态、旧缓存不污染<br>• 慢请求返回时目标已变 → 不覆盖新状态<br>• 杀进程重开 → 已提交正文在；未成功提交的不在库中冒充已存<br>• IME 组合未完成 → 不强制提交 |
