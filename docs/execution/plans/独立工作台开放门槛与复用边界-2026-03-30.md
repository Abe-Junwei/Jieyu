# 独立工作台开放门槛与复用边界（2026-03-30）

> **修订（2026-09-11）**：对照 `main`，Annotation / Corpus 在 **flag 开**时已不是纯说明页（见 [仓库现状](../../architecture/仓库现状与代码地图.md) 与 [后续路线图详细评估](../audits/后续路线图详细评估-2026-09-11.md)）。**对外口径仍为 `NO-GO`**（第五节 go 未勾完）。**本地 flag dogfood ≠ 宣告产品开放**。下文表格以代码为准，不再沿用 2026-04「三页仍是说明页」快照。

> **修订（2026-04-22）**：与当时代码对齐——`LexiconPage` 已非纯说明页，具备词典浏览工作台壳层；**产品级开放仍适用本节 `NO-GO` 判定**（未满足第五节 go）。

> **口径补充（2026-04-25）**：按产品开发口径推进四工作台能力建设，目标进入产品开放评审；但在满足第五节 go 之前，**对外口径仍为 `NO-GO`**。禁止将“里程碑开发中”或“开发者本地开 flag”表述为“已产品开放”。

> 目的：把 Annotation / Analysis / Writing / Lexicon 四个独立工作台的开放条件从“口头约束”收敛为可执行的 go / no-go 规则，并明确哪些能力必须复用转写内核，哪些实现禁止直接复制。

## 一、当前结论

当前统一结论为：`NO-GO`（四工作台同时宣告产品开放）。

原因：

1. 当前唯一**产品级开放**工作台仍是转写页。
2. Annotation 已是默认打开的 IGT 工作台（B4c/d/e），但仍受第五节全局项 2（转写主线封账）约束；CorpusLibrary 在 **flag 默认关**时渲染占位面板，flag 开时为只读索引 + 工作集出站。Analysis 是 [ADR-0033](../../adr/0033-analysis-restricted-workspace-no-transcription-dock.md) **受限工作台**。Lexicon 已有浏览壳层。四页**均未同时满足**第五节 **go**（不构成「可宣告全工作台开放」证据）。
3. 转写页主线需以新自动门禁体系与发布证据作为封账依据；缺少自动门禁证据链时仍不具备开放判定条件。**Dogfood（开发者本地开 flag）不是产品开放。**

## 三、允许复用的内核边界

以下能力可作为未来独立工作台的优先复用边界：

1. runtime contract 与 runtime props 装配：`src/pages/TranscriptionPage.runtimeContracts.ts`、`src/pages/TranscriptionPage.runtimeProps.ts`、`src/pages/useTranscriptionRuntimeProps.ts`
2. AI sidebar / assistant 装配边界：`src/pages/useTranscriptionAssistantSidebarController.ts`、`src/pages/useTranscriptionSidebarSectionsViewModel.ts`
3. 选择语义与目标解析：`src/pages/useTranscriptionSelectionSnapshot.ts`、`src/pages/transcriptionSelectionSnapshot.ts`、`src/pages/transcriptionUnitTargetResolver.ts`
4. speaker / waveform / shell 页面级 controller：`src/pages/useTranscriptionSpeakerController.ts`、`src/pages/useTranscriptionWaveformBridgeController.ts`、`src/pages/useTranscriptionShellController.ts`
5. AI / voice / citation 核心能力：`src/hooks/useAiChat.ts`、`src/hooks/useVoiceAgent.ts`、`src/pages/TranscriptionPage.citationJump.ts`

原则：先抽 controller/runtime 内核，再开放页面壳层；不允许先造新页面再回填内核。

## 四、禁止复制的页面级实现

以下内容不允许直接复制到新工作台：

1. `src/pages/TranscriptionPage.Orchestrator.tsx` 的 page-level 装配与 JSX 结构
2. 转写页内部临时胶水、局部 `useMemo` 拼装与仅服务于当前页面布局的局部状态
3. 任何为通过现有结构测试而写死的转写页专有渲染细节

原则：独立工作台若需要同类能力，应复用既有 controller/runtime，或先抽出新的共享边界，再接页面。

## 五、开放 go / no-go 清单

### 必须同时满足的 go 条件

1. 自动化基线两轮通过：
	- 首轮：`npm run typecheck` + `npm run build` + `npm run test -- <changed scope>`
	- 第二轮（放行前）：`npm test` 全量阻断
2. 转写主工作台已完成当前批次自动封账：产出可追溯发布证据（含门禁结果、日志路径与 go/no-go 结论），不再以 CASE 01-10 勾选作为阻断前置
3. architecture guard、structure tests、hotspot report 对相关核心文件无新增超线项
4. 新工作台具备明确的用户工作流定义，而不是仅有占位路由或说明文案
5. 新工作台至少复用一组已验证 controller/runtime 内核，不允许以复制 `TranscriptionPage.Orchestrator.tsx` 为起点
6. 新工作台有对应的聚焦自动化与最小手工验收脚本

### 任一命中即 `NO-GO`

1. 转写页主线自动门禁或发布证据链存在未封账阻塞项
2. 新工作台仍依赖转写页页面级 props 拼装或复制 page-level 逻辑
3. 没有专属手工验收与聚焦自动化
4. 开放理由仅是“页面已经有路由/壳层”

## 六、四个工作台的当前判定

### Annotation

当前判定：`条件性 GO`（标注页工作台开放）

已满足（本页）：

1. IGT 内核：POS/gloss/morpheme/分词/词典链接 + 段播放 + 备注/标签/selfCertainty + AutoGloss 预览确认（SDD `annotation-m1-open/`）+ 二次自动分词保守模式（SDD `annotation-retokenize/`）
2. 工作流定义、聚焦 vitest、`criticalPaths` `/annotation` 烟测、手工脚本 `手工验收执行脚本-标注页M1开放-2026-09-11.md`
3. 复用 LinguisticService / `user_notes` / AutoGloss 只读匹配；不复制 Orchestrator / ChatWindow
4. `annotationPageEnabled` 默认 `true`；env=`false` 保留占位面板

仍受第五节全局项约束：转写主线封账未完成时，**不得**把「标注页已开放」表述为四工作台产品已全部开放。

缺口（非本页阻断）：

1. 二次自动分词强制覆盖 / 快照回滚未做（B4f 仅保守模式）
2. 第五节第 2 项转写主线发布封账仍开放

### Lexicon

当前判定：`NO-GO`（产品开放）

1. 反向引用、审核流、义项树尚未形成产品闭环
2. 页面已具备浏览壳层，但上述闭环与第五节 go 条件仍未满足

## 七、解锁前的最小动作

当转写主线封账完成后，若要解锁任一工作台，按以下顺序推进：

1. 定义该工作台的最小用户工作流与数据入口
2. 从转写页抽出对应 controller/runtime 内核，禁止复制 page-level 代码
3. 为该工作台新增聚焦自动化与结构守卫
4. 编写独立手工验收脚本与执行记录模板
5. 再做一次 go / no-go 复核，结论写回路线图与 README

## 八、当前建议

在转写页手工封账未完成前：继续维持 Annotation / Corpus **flag 默认关**、Analysis 为受限工作台、Lexicon 在壳层上迭代；**未满足第五节 go 前不得宣告产品级开放**。后续如需推进，先更新本文件的判定，再进入实际开放。不要把 dogfood 写成「已开放」。
