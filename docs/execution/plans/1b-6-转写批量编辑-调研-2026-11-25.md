# 1b-6 转写批量编辑与补充入口：一手资料调研

调研日期：2026-11-25。本文是 [1b 规格](../specs/desktop-4ws-slice1b-transcription-editing/tasks.md) 的 Research 补充，不取代主路线图、不授权实施；结果并入该规格并不再被引用后删除本文。只采用产品官方手册与 W3C 一手指南；未运行 ELAN、FLEx 或 Praat，本页是文档调研，不是这些产品的实机验收。Jieyu 代码事实由主规格另行核对。

## 调研综述

结论为 **adapt**：复用仓库的选择、编辑回执、会话撤销、两段合并、说话人和备注底座；适配成熟产品的“先明确对象，再明确动作”交互。无新增依赖建议。

外部资料支持多对象选择、明确区分删除标注与清空正文、局部可空文本、备注独立于转写、精确时间定位。它们不证明 Jieyu 现有实现具有批量原子性、冲突保护、保存失败恢复或跨层合并安全性；这些必须按本仓合同测试。

推荐把 1b-6 拆成：选择与批量指派／删除 → 多段合并 → 说话人创建与筛选 → 句段备注与确信程度 → 部分转写和手动定位。每块形成桌面可操作和重开读回闭环；不借此扩展到自动对齐、VAD、无时间合并或通用批量字段编辑器。

## 1. 多选：借鉴对象选择，不照搬快捷键

**核实事实**：ELAN 支持逐个点击选择独立标注，修饰键加点击扩展选择，再次点击同一标注可移除选择。其手册给出的快捷键为 Windows Ctrl+Alt、macOS Alt，且描述的是扩展时间选择。来源：[ELAN Selecting multiple annotations](https://www.mpi.nl/tools/elan/docs/manual/Sec_Selecting_multiple_annotations.html)。

**适配建议**：Jieyu 应显式保存被选 unit id 集合，区分焦点、当前编辑段、批量集合与波形时间选区。菜单对多少段生效必须可见。不能仅拿时间包围盒推导批量目标，否则夹在中间但没选中的段可能被误操作。对点对象与 unit 不混选，切稿清空选择；切层和过滤后的选择语义需在本片明确。

**可访问性依据**：WAI-ARIA APG 区分焦点与选中，提供无需一直按修饰键的多选模型和显式全选／取消选择建议；含可交互子控件的卡片不应机械套 `listbox/option`。来源：[W3C Listbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)。建议沿用当前卡片语义，配可聚焦选择控件与已选数量播报；先读现有组件再决定是否需要 grid，不能为了多选强换角色。

**不能推出**：ELAN 这页没有证明其所有命令都对离散集合执行，也没有证明同一批动作是单事务或一步撤销。Jieyu 需独立规定并验证这些保证。

## 2. 批量删除：对象删除与清空正文分开

**核实事实**：ELAN 的多层移除操作先选层，再明确选择删除标注对象还是仅删除标注值，并可按全部、空标注或指定值筛选。来源：[ELAN Deleting annotations and annotation values on multiple tiers](https://www.mpi.nl/corpus/html/elan/ch05s09s17.html)。

**适配建议**：1b-6 仅实现已选段批量删除，不顺带增加按值清洗、整层清空或批量清空正文。确认框显示目标数量及受影响的关联正文、分析、备注与录音；取消保留原内容和草稿。确认后一次提交、一步撤销，失败不能留下前半批已删除、后半批未删除的结果。无论选择视觉上是否连续，实际目标只来自明确 id 集合。

**风险**：祖先与后代若同时入选，要按实际删除闭包去重；撤销快照不能重复恢复子树。删除不能提前清理仍由撤销账本握住的录音。上述为 Jieyu 的设计建议，不是 ELAN 已证明的行为。

## 3. 多段合并：参考相邻合并，不复制改时间规则

**核实事实**：ELAN 在独立层上提供与前一段／后一段合并；结果覆盖首段起点至末段终点，依附层标注也参与处理。该实现会拉伸一处依附标注的结束时间。来源：[ELAN Merging annotations](https://www.mpi.nl/tools/elan/docs/manual/Sec_Merging_annotations.html)。

**适配建议**：Jieyu 多段合并沿用 1b-4 已接受规则并扩为 N 段：同稿、同层、同说话人且在该说话人的序列中连续；其他说话人的段不自动纳入。保持下级内容、顺序和既有时间，仅调整归属；不复制 ELAN 的拉伸子段时间策略。预览列出每层正式正文及未保存草稿、字段冲突、分析处理和录音取舍。

**反模式**：页面循环调用两段合并。这样会产生中间新 id、多个回执和多步撤销，还可能在后续失败时留下部分结果。应在领域层一次计算最终结果、一次事务提交，保留所有旧 id 到最终 id 的映射。无时间或一有一无的合并仍归 1b-7。外部手册只证实两段入口，不能拿它宣称任意 N 段安全。

## 4. 说话人与备注：借鉴分离建模，不复制参与者层

**核实事实**：ELAN 的 Participant 是层属性，允许为空。来源：[ELAN Adding new tiers](https://www.mpi.nl/tools/elan/docs/manual/Sec_Adding_new_tiers.html)。Jieyu 已采用项目说话人目录与 unit 指派，不能据此复制“一人一组层”，也不能把筛选说话人等同于改层归属。

**核实事实**：ELAN 评论可指向时间选区和活动层，评论列表和编辑区独立于转写正文。来源：[ELAN Adding, deleting & changing comments](https://www.mpi.nl/tools/elan/docs/manual/Sec_Adding_deleting_changing_comments.html)。

**适配建议**：本片先提供已有句段锚点的备注增删改和可见入口，不引入评论服务器、协作权限、邮件或自动创建时间范围锚点。新建说话人入口应明确创建目录项与指派目标；若把“新建并指派”做成一次用户动作，就需要定义创建成功但指派失败时的结果，不能沉默留下半成品。目录筛选只改变可见结果，不改项目数据。

## 5. FLEx 的补充证据与边界

官方《FLEx 9.1 Conceptual Model》§6.2（PDF 印刷页 69–70）将 Segment 的自由译文、直译、Notes 分开；Notes 可为多条。该文同时明确：从 ELAN 保存的 Speaker、BeginTimeOffset、EndTimeOffset、MediaURI 等字段当时没有对应 FLEx UI。§2.8 列出项目 Confidence Levels 列表，但这不能证明 Segment 自带可编辑确信程度或批量修改入口。来源：[SIL FLEx Conceptual Model](https://downloads.languagetechnology.org/fieldworks/Documentation/FLEx%209.1%20Conceptual%20Model.pdf)。

**适配建议**：备注不能塞进正文；显示确信程度应沿用 Jieyu 既有枚举／数值与空值语义，不能借 FLEx 的列表凭空设计概率或增加状态。此次未找到足以证明 FLEx 某个原生句段批量说话人 UI 的一手证据，不把它写为标杆能力。模型字段存在也不代表产品入口存在。

## 6. 部分转写：空正文是有边界对象，不是静音判定

**核实事实**：Praat TextGrid 的区间层创建后就有覆盖时间域的区间，文本可为空；点层可没有点。来源：[Praat TextGrid file formats](https://praat.org/manual/TextGrid_file_formats.html)。

**适配建议**：Jieyu 应允许先有合法时间段但无原文，之后只补选定部分；没有原文时仍能在合法层录入译释，不能强迫虚构一行原文。空正文不自动删除时间段，也不代表静音、已确认、已处理或可导出为有效文字。已有录音、备注等信息不得因为正文变空而被丢弃。

**不能照搬**：Praat 区间层完整覆盖时间域，空区间也承担填补时间域作用；Jieyu 不因此需要为所有空白自动造 unit。空正文与无时间是两条轴：本片补前者，1b-7 补后者。有效语料、查询／统计与导出资格仍按所属合同决定。

## 7. 馆藏音频：精确跳转与写入边界分开

**核实事实**：ELAN 支持输入 `hh:mm:ss.sss` 跳转、部分零位省略，以及点击波形／时间轴等视图定位。来源：[ELAN Accessing points in time](https://www.mpi.nl/tools/elan/docs/manual/Sec_Accessing_points_in_time.html)。

**适配建议**：本片先让用户精确定位、试听并手动确定边界；复用已存在的毫秒时间输入、波形选区和建段／调时入口。跳转仅改变播放位置，不应顺手修改句段起止。提交边界才走正常校验和会话撤销。长录音不得因“定位”触发全文件识别、自动对齐或生成边界，自动分段留 #604。

**边界检查**：非法时间、超时长、未就绪媒体、切稿后的迟到 seek、拖选取消、定位后未确认退出均要有行为测试；外部文档不证明本地长录音性能，需在 Jieyu 自己的桌面合成数据上测。

## 8. 适配候选与验证建议

采用已有 React/controller、SQLite 业务操作、回执和撤销模块；不引入通用选择库、批处理框架或新标注存储模型。新依赖的维护、体积、许可及集成成本因此不增加。

各子片至少验证：真实入口选目标 → 展示动作范围 → 提交或取消 → 一步撤销／重做 → 关库重开读回。批量指派测试最终同说话人重叠拒绝；批量删除测试子树、录音引用和重开；N 段合并测试草稿冲突、录音超过上限、最终映射、回执丢失和撤销恢复；部分转写测试空正文仍保留时间与关联信息；手动定位测试不会悄悄改边界。

本文不声称这些验证已经通过。具体落位、现有能力、Pixso 对照和可执行命令由 1b-6 SDD 规划补齐。
