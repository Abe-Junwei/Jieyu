# 转写、标注、词典联动需求

依据是 2026-09 对田野标注批评、FLEx 联动和 Plaid `master` 源码的对照，对着解语现有的转写层正文、`unit_tokens`、`unit_morphemes`、`token_lexeme_links`、`lexemes`。路线图仍是 [标注页与词典页开发路线图](./标注页与词典页开发路线图-2026-04-25.md)。本文只写三页之间该共享什么、哪些建议可以落成字、哪些做法明确不做。

总要求：原文、这一次出现的词形和注释、词典义项分开存放，用 id 相连。人确认过的分析不被建议盖掉。导出留下整句，并能回到媒体。

## 1. 工作树里已经对着做的

下列行为在当前工作树里有实现和测试。合入前保持这些验收，不要再做成另一套写回。

| 编号 | 行为 | 验收 |
| --- | --- | --- |
| K1 | 词典命中的主行是转写层句子，词形是次行 | `baselineText` 为句子；新链接后当前词条的命中列表重查 |
| K2 | 多个义项时先选，再写 `senseId` | 未选义项不写链接；一个义项时用那一条 |
| K3 | 义项译文和 `token.gloss` 分开 | 两者不同时只提示；保存不把义项译文写入 `token.gloss` |
| K4 | 词头、词条词性、义项译文随词条更新 | `lexeme-updated` / `lexeme-deleted` 后标注重取；空词头显示断裂 |
| K5 | 标注按转写层语言读正文 | 该语言键有字时不用 `default` 盖住它 |
| K6 | 「在转写中打开」带 `layerId` | 深链选中对应层和单元 |
| K7 | 转写侧栏只读一行词性加注释 | 听 `unit-updated`；侧栏不编辑 token，也不把词形写回转写层 |

| K10 | 整词词类和语素词类分列保存（R10 的保存半边） | 只改语素 `pos` 时 token `pos` 不变。导出两列见 R8 |
| K11 | 转写备注和译文备注分开（R11） | `user_notes`：转写 `comment`，译文 `topic`。两页读同一处 |

## 2. 还要做的需求

进度以本节标题后的状态为准。已落地的条目留着验收，不再排切片。全局顺序在 [主路线图](./解语-主路线图-master-roadmap-2026-06-01.md) **B4u** 起。

### R1 说话人在标注行可读

**已落地（K8）。** 不再单列切片。

档案里多人材料靠说话人层或话轮前缀区分（von Prince & Nordhoff，LREC 2020）。转写单元已有 `speakerId`，标注行读取姓名。

- 标注句段显示该单元的说话人姓名。没有姓名时留空，不造一个默认说话人。
- 转写改说话人后，已打开的标注行跟着变。
- 验收：同一单元在转写侧栏和标注行显示同一个姓名；无 `speakerId` 的单元不出现姓名。

听话人、不合语法、实际形式和目标形式见 R14。不塞进备注键。

### R2 译文跟当前译文层

**已落地。切片 B4w。** 选择写在布局的 `translationLayerId`。从转写页打开时，URL `layerId` 若是该文本的译文层就用它，并写回布局。直译层不能被选成自由译文。该层为空时这一句的译文为空，不改去显示别的层。

- 标注译文行读用户在转写页选中的译文层。该层为空时，这一句的译文为空。
- 另一种元语言留在自己的层里，打开那一层才显示。不把多种译文拼进一行。
- 验收：两层译文内容不同时，切换选中层，标注行只显示被选中的那一层。

### R3 同形建议：提示，整包只铺到空白词

**已落地。切片 B4y。** 规格：`docs/execution/specs/annotation-precedent/`。

Plaid `precedent.js` / `glossGuess.js` / `analysisMemory.js`。FLEx 会在每次链接时改掉所有同形，Plaid 的使用者拒绝了这个默认。解语已有按词形改词性，还没有整包复用。

- 项目内按「词或语素、词形、栏位」计已有决定。词和语素分开计。词形比较前做 NFC。
- 格子里的建议不落库。回车才写入，并带 `provenance.reviewStatus`。
- 排序：人手确认过的链接所对义项字段，然后是语料里的严格多数，然后是尚未确认的链接。平局不给建议。
- 会自动写入的步骤不采用 `suggested` 的结果。
- 「按这个分析其余同形」只作用在空白词：一个语素、语素形式等于词面、没有链接、没有注释。已有任何分析的词不动。两种整包分析次数相同则不铺。
- 一次链接只改当前 token。铺到其他同形是单独动作，且只碰还没有链接的 token。
- 整词不自动挂到词缀或附着词条上。
- 验收：空白词回车后写入多数注释；平局格子保持空白；已有注释的词在「按这个分析」之后不变；`suggested` 不增加下一次自动写入的计数。

### R4 例句可以引用出现处

**已落地。切片 B3an。** 规格：`docs/execution/specs/lexicon-sense-citation/`。

[义项例证](../specs/lexicon-sense-examples/requirements.md) 已经能手写原文和译文。Plaid 和 CLDF 的例句是指回语料里的那一次出现。

- 义项可以增加一条引用：`textId`、`unitId`、`tokenId` 或语素 id、`lexemeId`、`senseId`。
- 打开时读该单元的转写层句子和当前译文层。不另存一份句子副本。
- 链接被删、改挂到别的词条或别的义项时，这条引用标成失效，仍可删除。
- 手写例证继续按原 spec 保存。引用和手写互不覆盖。
- 验收：引用保存后重开词条仍指向同一 token；改挂后列表标失效；清空手写原文不影响引用。

### R5 删改先搬走会一起消失的分析

**已落地。切片 B4z。** 规格：`docs/execution/specs/annotation-token-detach/`。

合并和强制重切分已在提交里保住语素、其他语言、`senseId`、confidence。这条需求覆盖以后的删除和转写层改字。

- 删除带语素或词典链接的 token 之前，先把它们改挂到保留下来的 token，或在确认里写出将失去的条数。没有这些附着物时直接删。
- 改转写层正文时，保留该单元上其他语言的正文、语素的多语言表、链接上的 `senseId` 和 confidence。
- 验收：删掉右词之前，右词的语素和链接已改挂到左词；只改一种语言的转写正文后，另一种语言的键还在。

### R6 和句子时间不一致的层保持自己的时间

后续项目，当前不做。见 [路线图](./标注页与词典页开发路线图-2026-04-25.md)「多模态功能标注」。句子起止时间内的波形、频谱和语调曲线不在这项里，见该路线图「一句时间内的语音学图」。

### R7 句内另一种语言不必先造词条

**已落地（K9）。** `unit_tokens.languageId` 经 `saveAnnotationTokenLanguage` 写回。没有词典链接的 token 仍走现有词形和注释保存。不再单列切片。

工具常假定一句一种语言，转语只好不分析，或收成假词条。

- token 可以记录一个不同于文本主语言的语言 id。
- 没有词典链接的 token 仍可保存词形和注释。
- 验收：同一句里两个 token 语言 id 不同，保存后读回仍不同；没有 `lexemeId` 的 token 重开后词形还在。

### R8 导出留下整句和媒体参照

**已落地。切片 B4aa。** 规格：`docs/execution/specs/annotation-sentence-export/`。整词词类和语素词类分列。

Flibl、Ligt 一类批评指出：导出把短语层清空之后，行间对齐要重做，结果不能直接交出去。

- 导出的每一句包含转写层正文、该句的译文层、词和语素的 form / gloss / pos、`senseId`、说话人、起止时间、`unitId`。
- 词和注释靠 token id 相连，不靠导出的列位置。
- 验收：往返一次后，句子正文、`unitId`、时间和 `senseId` 还在；列顺序变化不改变 token 与义项的对应。

### R9 导入不写死以后才能确定的语言

**不在本行动里单列。** 继续走 [EAF 导入对齐改进](./EAF导入对齐改进-2026-09-28.md) 和 [FLEx 与 ELAN 导入字段映射](./FLEx与ELAN导入字段映射-2026-09-28.md)。

历史文献的转写惯例常常分析完才知道。已有 [EAF 导入对齐改进](./EAF导入对齐改进-2026-09-28.md) 和 [FLEx 与 ELAN 导入字段映射](./FLEx与ELAN导入字段映射-2026-09-28.md)。

- 导入保留文件里的其他书写或译文，不在导入时丢掉非默认语言键。
- 导入之后可以改单元或层的语言 id，token id 和链接 id 不变。
- 验收：带两种语言键的导入，两种键都在；改语言 id 后原 token id 仍能读到原链接。

### R10 整词词类和语素词类分开

**已落地（K10，导出在 B4aa）。** 保存和导出都分列。不再单列切片。

档案里词类有时标在语素上，整词词类不能从语素词类推出来（Savosavo；Mojeño 两层都有）。词性选择和重叠、异干、换段、删段、声调、中缀已在 [标注词性与形态关系](../specs/annotation-pos-relations/requirements.md) 和 [注释结构](../specs/annotation-gloss-structure/requirements.md)。

- 保存语素词类不写入整词词类，保存整词词类不写入语素词类。
- 导出两列都在，靠 token id 和语素 id 区分。
- 验收：只改语素词类后，整词词类仍是原值。

### R11 转写备注和译文备注分开

**已落地（K11）。** 不再单列切片。

有的语料把转写备注和译文备注分成两层（层名 nt 或 Note）。

- 一条单元上，转写备注和译文备注是两处文本。改一处不改另一处。
- 标注页和转写页读的是同一处。转写页保存后，已打开的标注页跟着变。
- 验收：写入转写备注后，译文备注仍为空；反向同样成立。

### R12 按原文、词、语素检索，打开整句并播放

**已落地（K12）。** 检索在转写侧栏。字符变体比较见 R13，不在这一片里。

FLEx 的 Concordance 把 Baseline、Word、Morpheme 分开搜，点开回到句子（Thieberger：句子这一级连回可播放的媒体）。

- 检索可以按转写层句子、词形、语素形分别查。
- 一条结果打开该句的 `unitId`，并可以从该句的起止时间播放。
- 词形命中的标题仍是整句，词形是次行（K1）。
- 验收：用词形搜到的结果能播放该句；用句子里的一个词搜不到只含该词形、句子里没有它的另一条。

### R13 字符变体先登记，再当成同一个词

**已落地。切片 B4ab。** `comparableForm` 在 NFC 之后使用 `projectCharacterVariantStore` 的登记。同形建议和转写检索共用。原文不改写。

喉塞音写成不同码位会变成不同词。FLEx 只能给语素登记变体，不能给字符登记（Skilton 等 §2.2）。R3 的 NFC 只合并组合字符，不处理这种变体。

- 项目可以登记「这些字符在词形比较里相同」。
- 登记之后，同形建议和 R12 的词形检索把它们看成同一个词形。未登记的不同码位仍然分开。
- 导入不要求先选定唯一正字法。原文里的字符原样留下。
- 验收：登记 `ʔ` 与 `'` 之后，两种写法计成同一个词形；未登记时，两种写法各算各的。

### R14 不合语法、听话人、实际形式和目标形式可以检索

**已落地（K13）。** 不再单列切片。

对话和儿童语里，这些字段进了 XML，界面和检索没有（Skilton 等 §3.3）。星号不会被检索排除。

- 话轮上可以标不合语法。检索可以排除这些话轮。
- 同一话轮可以有听话人、实际形式和目标形式。两套形式都留下。
- 标注行能看见这四项。它们不是备注正文。
- 验收：标成不合语法的句子可以被检索排除，未标的句子仍在结果里；实际形式和目标形式保存后同时读回。

### R15 手势或韵律可以指向词，不改词的时间

后续项目，当前不做。与 R6 一起见路线图「多模态功能标注」。

## 3. 明确不做

- 保存词形、切分和注释时不改转写正文。句段菜单里的「写回原文」才把当前词形写入这一句的转写层；其他语言键和译文层不动。
- 不把义项译文或词注释自动抄进整句译文。整句译文是译文层自己的文本。
- 不在多个义项时自动挑一条写入。格子还不能把未确认链接显示成待审时，继续让人选。
- 不做 FLEx 的书写系统管理、解析器、Send/Receive。
- 不把 Plaid 的任意 layer 做成产品表面。转写、标注、词典仍是三页。
- 不把栏位做成每个项目随意加。句、词、语素的栏位保持现有模型。R14 的四项是规定字段，不是开放加栏。
- 不把协作做成必须连到一台中心服务器。数据继续留在本机库。多人同时编辑、可见版本、导出给社群做教材，不在本文写验收。
- 手语不另做一套行间。转写单元挂视频，文本仍走转写层。手势指向词属 R15，当前不做。

## 4. 和已有 spec 的边界

- 跨页刷新沿用 [workspace-cross-page-events](../specs/workspace-cross-page-events/requirements.md)。转写页若要显示 K7 和 R1，订阅落在侧栏读取处，不把新的写路径放进转写编排层。
- 手写例证沿用 [lexicon-sense-examples](../specs/lexicon-sense-examples/requirements.md)。R4 只增加引用。
- 重叠、异干、换段、删段、声调沿用 [标注词性与形态关系](../specs/annotation-pos-relations/requirements.md)。中缀沿用 [注释结构](../specs/annotation-gloss-structure/requirements.md)。本文不再定义一套符号。

## 6. 行动方案（2026-09-30）

切片序以 [主路线图](./解语-主路线图-master-roadmap-2026-06-01.md) 为准。这里只写落位和不要踩的边界。**B4u 至 B4aa、B4ab、B3an 已落地。** 这一串没有下一刀。

复用决定：直译和自由译文在 FLEx 里都是句子级 writing，解语不新开「直译表」，而是绑一条已有类型的译文层。行布局不升 Dexie 版本，放进 `TextDocType.metadata` 已有的自由记录。建层复用 `LayerConstraintService.getLayerCreateGuard` 和 `LayerTierUnifiedService.createLayer`。

### B4u 行布局与直译落库

**已落地。** 键是 `texts.metadata.annotationDocumentLayout`。添加直译行才创建译文层；没有独立边界的转写层时，这一行加不上去，布局也不改。

- 布局对象就是现有的 `AnnotationDocumentLayout`（`annotationIgtLines.ts`）：`added`、`hidden`、`keyOrder`、`languageByLine`，再加直译所绑的层 id。整篇一份，存在 `texts.metadata` 的固定键。不按句存。
- 直译正文写入那条层的单元文本。读回后填进行，不再用 `AnnotationIgtRow` 里只活在内存的 `literalText`。
- 还没有直译层时，添加直译行才创建一条 `translation` 层并记下 id。同语言、同模态已有译文层时必须有 alias。
- 不把提交走 `onCommitLanguageLine('literal')`。不写 `unit_tokens`。不把直译抄进自由译文。
- 验收：刷新后行的显隐、顺序、语言和直译正文还在。词行不出现直译文本。

### B4w 译文跟选定层
