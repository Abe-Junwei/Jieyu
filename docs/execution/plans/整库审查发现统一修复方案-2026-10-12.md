## 1. 边界、目标与拍板点

- 目标：消除已复现的数据或副作用风险，修正已确认的用户路径与门禁缺口；每项从入口写入到重载读回验收。先红测、后修复，再跑对应门禁。按批次小 PR / 小提交，不做伴随式重构。
- 不做：把 3865 个文件逐一重写、引入新目录体系、以 mock 计数替代行为验收、为通过门禁调高预算或删规则、将缺失的外部环境写成通过。
- 已确认产品契约：用户此前明确要求“两条占位轴未选择时提示先选一条；选中时只给选中轴音频”。底层 `default` 会拒绝歧义，但 `WorkbenchFilePane` 当前强制 `add`；按该契约修复，不将它推回为待裁决项。若未来需要“新增录音”，应作为明确的独立操作。
- 环境待补 P-E1：真实 Supabase 双账号/RLS（用户本轮要求先跳过）、Firefox/WebKit、Node 22、物理设备听播及生产回滚。可先完成代码与本机验收，发布签署仍保留这些阻塞。

## 3. 专项技术决策与防误修

1. **B1 分两期，不能提前关闭风险。** B1a 先消除整数组覆盖/防抖丢队列和旧镜像回灌；B1b 才消除本地编辑与 outbox 写入之间的崩溃窗口。两期复用同一主库逐操作 schema，避免先改独立 IDB、再迁主库的双重迁移；B1a 期间显式记录剩余风险，不以 `localStorage` 数组 merge、unload 回调或“保存成功”提示冒充耐久保证。专项 SDD 必须审阅入库后才做迁移。
2. **B2 不采用盲目 upsert。** 当前 `assign_project_revision` 为 BEFORE INSERT 触发器；冲突行仍可能先执行触发器。新增服务端 append RPC 时复用身份/RLS/协议闸门，项目行锁下先查稳定操作键及内容，再为真正新操作分配 revision；用 PGlite 验证重复请求前后 revision 不变。已部署云端只追加迁移，不静默改写 `001` 的既有语义。
3. **B3 不把 AbortSignal 当自动回滚。** 取消只能阻止尚未开始的提交；提交中断点必须以写入结果和重查为准。UI 的“取消/失败/已完成”与持久化事实一致，审计日志记录同一 requestId 的最终状态。
4. **高风险修复的 flag 例外。** 不把已知会丢数据的旧路径当默认 `false` 回退。若迁移需要 flag，`false` 只能停用云写入或保持安全只读；决不能恢复不可靠出站。先自用一周再打开新能力的规则仍适用于非安全功能。

## 4. 执行与验证闸门

1. 每批先补能在旧代码失败的最小回归：真实入口 → 状态转移 → 写入/副作用 → 重载/重查 → 结果；随后只修对应根因。B1a 只签“已入队操作耐久”，B1b 才签“本地业务写与出站意图原子”；B1/B2/B3/B4 任一既定门槛失败即停止对应批次合并，不以 toast 或 mock 调用次数代替读回。
2. 每批执行 `npm run typecheck`、触及域 `npx vitest run <path>`；侧栏/时间轴/交互跑 `npm run test:e2e:chromium`；AI 跑 `npm run check:agent-evals:full`；结构/文档跑 `npm run check:architecture-guard`、`npm run check:docs-governance`、`npm run check:dev-agent-workflow-verify`。落地时替换 `<path>` 为实际文件，不在未运行时写通过。
3. 汇总门禁：`npm run check:all`、`npm run check:build-budgets`、`npm run check:plans-frontmatter`、`npm audit`（含 dev 与 `--omit=dev`）、完整 Vitest、Chromium E2E 无重试、干净生产构建、`git diff --check`。在 `.nvmrc` Node 22 下至少复跑合并门槛；Node 26 结果仅作参考。
4. 浏览器场景至少覆盖：双标签页同时编辑/断网/关闭重开、ACK 丢失、配额、恢复后字段与音频字节读回、冷离线深链、整页 axe/键盘/200% 缩放、项目切换。Firefox/WebKit 及真实 Supabase 双账号在环境具备后补跑；未跑不写“已完成”。
5. 每批 commit 附真实命令与结果；最后更新[发现台账](../governance/repository-review-findings-2026-10-11.md)的复现、修复、证据和剩余风险，逐条关闭 R/V 状态。评估单独 PR；没有一条“测试通过”可自动推出发布批准。
