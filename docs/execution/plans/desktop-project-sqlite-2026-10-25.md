# 桌面项目单库

依据 [ADR-0085](../../adr/0085-desktop-project-one-sqlite.md)、[ADR-0086](../../adr/0086-desktop-release-scope-and-format-freeze.md) 的范围/冻结安排和 [ADR-0087](../../adr/0087-project-deletion-retention-and-media-cleanup.md) 的删除规则。旧的 SQLite `StoragePort` 停在现在的样子，不补拒绝的方法，现在也不删。半成品库文件不迁移。

## 调用

```ts
const project = await openProject(folder);
const manuscript = await project.manuscripts.create({ title, mediaId });
const layer = await project.layers.create({
  manuscriptId: manuscript.id,
  key: 'tx',
  name: { zh: '转写' },
  tierType: 'time-aligned',
  contentType: 'transcription',
});
const unit = await project.units.create({
  layerId: layer.id,
  startTime: 0,
  endTime: 1.2,
  text: '…',
});
```

`units.create` 在同一事务里写 `units` 和一行 `unit_texts`（`role` 为 `transcription`），读回这两行之后才提交。返回的语段带 `text: string`。按 id 读返回同一种形状。

## 执行方式

下文 M1–M7 是唯一活动交付清单，取代原技术七步；不再保留一份顺序不同的实施清单。M1 的函数测试已通过，规格已按 ADR-0051 删除；M2 起逐片另起规格。这仍不是桌面可用，也不关闭 #275。

每个里程碑写明交付、验收、issue 与退出条件。M1–M3 是内部工程交付，M4 才是首个可在内部用合成项目操作的用户流程闭环；本地测试通过不等于 issue 可以关闭。
建表仅在新建时执行。M1 采用 ADR-0085 初始表集；D14 前可按新 ADR 调整必要字段/表并重建受控合成项目，不能据此覆盖任意已有文件。现有不兼容文件只拒绝，不补列、不迁移；D14 才冻结首发表集。首步验收不含任意文件格式拒绝、双进程锁、录音业务登记与 IPC，不向用户暴露尚未验收的路径。

### 并行边界与决定落点

- M1-S1→S2→S3→S4 是当前实现顺序。M2→M3→M4 顺推；M4-A/B 可分提交但不分别发布。M1 不接屏幕/IPC/选择器，也不加图、代际或删除列。
- M4 后 M5 各域按表中引用/API 依赖推进，不要求串行等整个 M5。#277、#312、#303/#305、#313-B 按白名单并行；#311/#333/#299 仅允许开工且不得回落旧写路径，不新增首发阻塞；#298/B7 仍第二程。
- R1 只挡 M5-C 的完整分析合同；审计取舍只挡依赖该成功语义的写路径；九类备注去向只挡对应备注接替；R5 只挡附件文件化；R6 随领域片收口。字段合同不必取得 ADR 编号，新增架构取舍才写 ADR。
- M4 只产生无图分析的合成项目；M5 引入图后，原正文编辑必须升级为正文/快照/卸下/代际一次事务，不能因 M4 曾通过而绕过此要求。C/D 按依赖联合验证，未接能力不开放。
- #329 从 M3 准备、M4 起逐组迁场景；每组 Linux/macOS/Windows 通过后才撤对应旧门槛，不等 #275 整单关闭，也不因 M1 测试通过提前撤旧门槛。
- GitHub 使用现有 #275 的 M1–M4/M6 清单、#280 的 M5 域清单、#325 的 D1–D4 清单，不为每个函数或文件新建 issue。发布、恢复、转写仍由原单负责。
- 每片证据：入口/业务结果、实际文件、前置、测试命令与结果、关闭重开/失败注入、未接路径、提交/PR 与 CI/平台状态。未执行项保持未勾；本地通过不等于远端合并、完成或产品验收。

### M1：单库业务原子性成立

- 交付：src/db/desktop 中 ADR-0085 初始表集；创建文稿、转写层、语段与正文；返回 id 和正文；支持关闭再开读取。只供主进程侧测试，不交付用户屏幕。

- 验收：真实临时库成功闭环；unit 已插入后正文插入失败，关闭全部连接再打开，两表无本次记录、此前数据不变。npx vitest run src/db/desktop --maxWorkers=1 与 npm run typecheck。
- issue：归 #275 的实现进度，不关闭 #275，不触发解冻，不删除旧端口。提交证据明确写“单库函数测试”，不能写“桌面已可用”。

### 当前已确定的删除边界

行为以 ADR-0087 为唯一正文，实施规格已建立但未实施。90 天只是保留期限：清除还要满足本周期实际展示提醒后至少 7 天；未看提醒可长期保留。录音还要等没有任何被保留文稿引用。
删除事务只原子修改目标状态；前置编辑保存/任务停止的已完成效果不回滚。恢复不恢复旧任务的写入资格。AI 只可读必要状态，不能删/恢复或通过状态工具获取已删除正文。
永久清除仅作用当前项目，不追删备份或系统垃圾箱；磁盘操作存在结果未知窗口，保留异常记录和人工处理入口，不承诺全自动收尾。
