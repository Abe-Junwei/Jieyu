# 词典编辑改用 DMLex 基准

决策见 [ADR 0035](../../adr/0035-lexicon-edit-baseline-dmlex.md)。对象形状以官方 JSON Schema 为准，不按规范正文里的抽象属性再发明一层。

规范副本：

- [dmlex.schema.json](../../architecture/dmlex/dmlex.schema.json)（编辑基准，含跨语言模块）
- [dmlex_no-crosslingual.schema.json](../../architecture/dmlex/dmlex_no-crosslingual.schema.json)（不用作基准）
- 来源目录：<https://docs.oasis-open.org/lexidma/dmlex/v1.0/os/schemas/JSON/>

本计划只定落位和切片。运行时代码仍是现有 LIFT 形状，直到切片 1 落地。

## 1. 库里的两份 JSON

`lexemes` 每一行保存：

- `entry`：符合 `dmlex.schema.json` 的 `$defs/entry`。`additionalProperties` 为 false。`headword` 必填。`id` 在 schema 里可选，解语写入并作为主键。每个 `sense.id` 同样写入。
- `jieyu`：schema 之外的字段。校验或导出 DMLex JSON 时删除。

资源级对象单独放一条记录，符合 `$defs/lexicographicResource`，但不把全部 entry 嵌进去（避免一行词库一个文档）。它保存：

- `langCode`（必填）
- `translationLanguages`（带跨语言模块时必填，至少一种分析语言）
- `relations`、`relationTypes`
- 标签词表：`partOfSpeechTags`、`labelTags` 等，用到才写

`relation.members[].ref` 指向 entry 或 sense 的 `id`。子义项关系类型用 `subsense`，同形词用 `homograph`。`relationTypes[].scopeRestriction` 只接受 schema 枚举：`sameEntry`、`sameResource`、`any`。子义项若在同一 entry 的 `senses` 数组里，用 `sameEntry`。同形词是多条 entry，用 `sameResource`。

JSON 里这些成员是字符串，不是对象：`partsOfSpeech[]`、`labels[]`、`translationLanguages[]`。

## 2. 编辑字段

用户编辑的是：

| 界面 | JSON |
| --- | --- |
| 词头 | `entry.headword` |
| 同形编号 | `entry.homographNumber` |
| 词类 | `entry.partsOfSpeech[]` |
| 义项顺序 | `entry.senses[]` 的数组顺序 |
| 义项提示 | `sense.indicator` |
| 词头语言释义 | `sense.definitions[].text` |
| 分析语言对译 | `sense.headwordTranslations[].text` + `langCode` |
| 分析语言解释 | `sense.headwordExplanations[].text` + `langCode` |
| 例句 | `sense.examples[].text` |
| 例句译文 | `example.exampleTranslations[].text` + `langCode` |
| 发音 | `entry.pronunciations[].transcriptions[].text` |
| 屈折或变体形式 | `entry.inflectedForms[].text` |
| 方言、用法、语义域 | `entry.labels[]` 或 `sense.labels[]` 的字符串 |
| 词源 | `entry.etymologies[]` |

多种分析语言时，翻译对象的 `langCode` 必填。这是 schema 根上的 `oneOf` 条件，不是可选风格。

## 3. 解语附加字段

放在 `jieyu`，不放进 `entry`：

- 例句指回语段：`{ senseId, exampleIndex, segmentId }`。`example` 没有 id，用该义项 `examples` 数组下标。
- 自由文本注释：`{ owner: "entry" | "sense", ref, text }`。一种注释，不再拆 FLEx 的 note type。
- 标注链接增加 `senseId`，指向 `sense.id`。现有 `token_lexeme_links.lexemeId` 仍指向 entry `id`。

## 4. LIFT 投影

导入读 LIFT 0.13，写成上面的 JSON。导出从 JSON 写 LIFT。对不上的内容进入诊断列表，不写回编辑字段。

| LIFT | DMLex JSON |
| --- | --- |
| `lexical-unit` 第一条 form | `entry.headword` |
| 其余词头书写形式 | 诊断。词头只能有一个字符串 |
| entry `morph-type` | 诊断 |
| sense `grammatical-info` | 若整条 entry 只有一个值，写入 `partsOfSpeech`；不同义项词类不同则拆成同形 entry，并加 `homograph` relation |
| `gloss` | `headwordTranslations` |
| 与词头同语言的 `definition` | `definitions` |
| 其他语言的 `definition` | `headwordExplanations` |
| `example` / `translation` | `examples` / `exampleTranslations` |
| `pronunciation` | `pronunciations[].transcriptions` |
| `etymology` | `etymologies` |
| `subsense` | 同一 entry 内的后广义项 + `subsense` relation |
| `variant` | `inflectedForms`；若带独立释义则另建 entry + relation |
| `trait`（方言、用法、语义域） | `labels` 字符串 |
| `note`、`reversal`、`import-residue`、科学名等 | 诊断。一般说明可进入 `jieyu` 注释 |

## 5. 切片

1. 类型与保存：`entry` + `jieyu` 写入 `lexemes`，资源记录写入单独一行。用 vendored schema 做 fixture 校验。不新增 Dexie 版本，不加 flag。
2. 编辑表单改为第 2 节的字段。列表按 `headword` 和 `headwordTranslations` 显示。旧的 LIFT 字段控件删除。
3. `subsense` 与 `homograph` relation。界面把同一组画成一篇。
4. 例句语段引用和自由文本注释。标注链接写入 `senseId`。
5. LIFT 导入导出改为第 4 节投影，并输出诊断。

每刀完成前跑 `npm run typecheck`、触及域 vitest、`check:architecture-guard`。改到词典编辑界面的那一刀再跑 `npm run test:e2e:chromium`，并做编辑→保存→列表 readback。

## 6. 不在本计划内

- 语义域浏览、图片、词汇关系图。
- DMLex RDF、XML、关系数据库序列化。导出 DMLex 时直接给出通过 schema 的 JSON。
- 把现有 LIFT 形状字段留作第二套真值。
