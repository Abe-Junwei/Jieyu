### 2.1 H1a architecture-guard 聚合链 `&&` 短路 ✅ 已修复

**修复内容**：
- 新建 `scripts/check-architecture-guard-aggregate.mjs`（39 行），用 `spawnSync` 循环执行 7 个子检查。
- `package.json` 的 `check:architecture-guard` 从 `&&` 串联改为调用 aggregate 脚本。
- 注释明确说明："Unlike shell `&&` chaining, every check runs even when earlier ones fail."

- 当 `:core` 因 `sessionMemory.ts` 硬失败时，后 6 道守卫仍会执行，失败统一汇总后 `process.exit(1)`。

- `stdio: 'inherit'` 导致子命令输出直接打印到 stdout/stderr；若多个子检查同时失败，输出会混杂在一起，难以定位具体失败项。

- 7 个检查项是硬编码数组，若 `package.json` 新增/删除子命令，aggregate 脚本不会自动同步。

**风险等级**：Low（输出可读性），不影响功能正确性。

## 三、Wave 1 — Critical 整改落地审查

### 3.1 C1 WorkerPool 双重派生 + registry 不清理 ✅ 已修复

**修复内容**：
- `WorkerPool.register()` 新增第 4 个可选参数 `existingWorker?: Worker`（`src/workers/WorkerPool.ts:64`）。
- 三个服务（EmbeddingRuntime、WhisperXVadService、AcousticAnalysisService）均改为先创建 Worker 实例，再传入 `register(id, label, factory, existingWorker)`。
- `managedWorkerRegistry.markManagedWorkerTerminated` 从"改 state"改为 `entries.delete(id)`。

**验证**：
- 业务层实例 A 被传入 Pool，Pool 不再内部创建实例 B，双重派生消除。
- Registry 条目在 Worker 终止后被真正删除，内存泄漏消除。

**引入的新问题/风险**：
- `WorkerPool.attemptRestart`（`src/workers/WorkerPool.ts:187-216`）中：
  ```typescript
  (entry as { worker: Worker }).worker = newWorker;
  ```
  用类型断言绕过 `readonly` 修改 `worker` 引用。虽然重启场景下逻辑正确，但这种模式在 TypeScript strict 模式下是隐患——如果未来 `WorkerPoolEntry` 的 `worker` 字段改为 getter-only，此处会在编译期失败。
- `deregister` 中 `try { entry.worker.terminate(); } catch { /* already gone */ }` 的 catch 为空，若 terminate 抛非预期错误（如 Worker 来自不同 origin），信息丢失。

**风险等级**：Low（类型断言是现有代码习惯，非新问题）。

### 3.2 C2 sessionMemory 双真源竞态 ⚠️ 部分修复（2026-06-01 后续补完 bind）

**已修复部分**：
- `localStorage` 彻底移除，三源降为 Dexie + LRU memoryCache。
- 拆分为 `sessionMemory.ts` / `sessionMemoryStore.ts` / `sessionMemoryNormalize.ts`；architecture-guard 通过。
- **`useSessionMemoryConversationBinding`**：`conversationId` 变化时 `bind` + `loadSessionMemoryAsync` 水合 ref；agent-loop reconcile 在 bind 之后运行。
- `CollectionAdapter.insert` 底层为 Dexie **`put`（upsert）**——§6.1 原「insert 唯一键冲突」为误判。

**仍须关注**：
- 快速切会话时 `persistSessionMemory` 为 fire-and-forget；async 写入按调用瞬间的 `conversationId` 捕获，一般安全，但极端竞态需集成测覆盖。

**风险等级**：Medium（bind 缺口已补；需 vitest + reload readback 回归）

### 3.5 C5 声学 decode 无大小门控 ✅ 已修复

**修复内容**：
