# 补充维度代码审查报告

## 一、PWA / 离线能力 — "本地优先"定位与实现的缺口

### 1.1 结论：构建产物有 SW，源码无离线感知

| 检查项 | 结果 | 证据 |
|--------|------|------|
| `src/main.tsx` SW 注册 | ❌ 无 | 全 110 行无 `navigator.serviceWorker.register` |
| `src/App.tsx` 离线状态监听 | ❌ 无 | 全 926 行无 `navigator.onLine` |
| `index.html` manifest 链接 | ❌ 无 | 源码模板中无 `<link rel="manifest">` |
| `public/manifest.json` | ❌ 不存在 | 公共目录无源文件 |
| `vite.config.ts` PWA 插件 | ✅ 有 | `vite-plugin-pwa` + `workbox` precache / runtimeCaching |
| 构建产物 SW | ✅ 有 | `dist/` 中有 `registerSW.js` + `manifest.webmanifest` |
| 离线回退 UI | ❌ 无 | 无任何"网络已断开"提示组件 |

**核心问题**：`vite-plugin-pwa` 的 `injectRegister: 'auto'` 在**构建产物**中自动注入 SW 注册，但源码层对此完全无感知。开发环境默认关闭 SW（`devOptions.enabled: process.env.DEV_PWA === '1'`），开发者日常无法验证离线行为。产品数据存储在 IndexedDB（本地优先），但应用壳层离线后**无降级策略、无用户告知机制**。

**风险等级**：🔶 Medium — "本地优先"不等于"离线可用"，用户在断网时可能遇到不可预期的功能失效。

## 二、Dexie Schema 迁移鲁棒性 — 有备份，无回滚

### 2.1 结论：50 个版本、16 次升级、备份只写不读

| 检查项 | 结果 | 证据 |
|--------|------|------|
| 当前 schema 版本 | v50 | `src/db/engine.ts:138` |
| 含 `.upgrade()` 的版本 | 16 个 | v6, v7, v10, v11, v12, v15, v16, v22, v24, v25, v27, v28, v37, v41, v42, v43 |
| 迁移前自动备份 | ✅ 有 | `engine.ts:1580` 调用 `createPreMigrationBackupSnapshot()` |
| 备份库独立 | ✅ 有 | `jieyu_pre_migration_backups` 独立 IndexedDB |
| 迁移失败后自动恢复 | ✅ **有（内核层）** | `engine.ts:1603` 在 `dexie.open()` catch 分支中调用 `shouldAutoRestoreAfterMigrationOpenFailure` → `getPreMigrationBackupForMigration` → `restorePreMigrationBackup`；失败时自动回滚并 retry open。但 **用户可见层无恢复按钮/提示** |
| 备份失败处理 | ⚠️ 薄弱 | 备份返回值（'created'/'skipped'/'failed'）不被调用方检查；备份失败仍继续迁移 |

### 2.2 SnapshotService.ts — 已由 v2 恢复快照部分收敛

- `RECOVERY_SCHEMA_VERSION = 2`，当前恢复快照通过 `exportRecoveryDatabaseAsJson()` 产出 schemaVersion 4 的全集合 JSON。
- PR-12 已补非 layer 集合 readback 测试，锁定 `media` / `speakers` / `layer_links` 等集合不会被恢复快照裁剪。
- 旧 v1 行仍可被转换为 import-compatible shape，损坏 JSON 会被丢弃并清理。
- 剩余问题：恢复读取仍只做结构存在性检查，**不做 Zod 校验**；核心表 / 派生表边界还没有独立 schema 合同文档。

**结论**：服务已不再是“三张旧表快照”，但仍需后续补 schema validate / 核心集合合同，才能称为完整恢复方案。

### 2.3 Zod Schema 与 Dexie 索引对齐

- Zod schema（`src/db/schemas.ts`）只校验文档字段，**不覆盖任何索引定义**。
- Dexie `stores()` 中的复合索引（如 `ai_session_memories: 'conversationId, updatedAt'`）在 Zod 层完全不可见。
- 16 个 `.upgrade()` 函数中，**无一处**对迁移后数据调用 Zod validate。

### 2.4 数据损坏诊断/修复工具

- `dbIntegrityProbe.ts` 仅对 3 张表做 `limit(1).toArray()` 可读性探测，不覆盖其余 30+ 张表。
- 全代码库无针对现有数据的批量重校验或修复脚本。
- 仅有一处历史问题修复脚本（`migrateV11TextIdRepair.ts`）。

**风险等级**：🔴 High — ~~"有备份无回滚"~~（勘误：内核层已有自动恢复，`engine.ts:1603` 实现）；当前问题：**(1) 迁移遮罩无用户可见恢复入口**，失败时用户只看到等待文案，无法手动触发恢复；**(2) SnapshotService 已死**；**(3) 索引漂移无校验**。

## 四、React 内存泄漏 — 窗口监听器 + MediaRecorder

### 4.1 高风险：`useTimelineResize.ts` 窗口监听器泄漏

```typescript
// src/hooks/transcription/useTimelineResize.ts:L275-277
window.addEventListener('pointermove', onMove);
window.addEventListener('pointerup', onUp);
window.addEventListener('pointercancel', onUp);
```

- 移除逻辑仅在用户释放指针时的 `onUp` 中执行。
- 该 hook **未使用 `useEffect`，无任何 unmount cleanup**。
- **后果**：若用户在拖拽 segment 边界时组件被卸载（路由跳转、父级重渲染），`window` 上的指针监听器及其闭包将**永久残留**。

### 4.2 中风险：`useRecording.ts` MediaRecorder 未在 unmount 时停止

```typescript
// src/hooks/media/useRecording.ts:L139-143
useEffect(() => {
  return () => {
    streamRef.current?.getTracks().forEach((track) => track.stop());
  };
}, []);
```

- Cleanup 仅停止 `MediaStreamTrack`，**未调用 `recorderRef.current?.stop()`**。
- 若组件卸载时正在录音，`MediaRecorder` 仍处于 `recording` 状态，其回调持有对 `unit`/`layer` 的闭包引用。

### 4.3 其他关注点（经检查无泄漏）

| 检查项 | 结论 | 代表性文件 |
|--------|------|------------|
| `window.addEventListener` | 绝大多数正确配对 | `useVoiceDock.ts`、`TranscriptionPage.ChatWindow.tsx` |
| `setInterval` / `setTimeout` | 均有对应清理 | `useVoiceAgent.ts`、`useTranscriptionLifecycle.ts` |
| `AbortController` | 使用规范 | `AcousticAnalysisService.ts`、`useAiChat.*.ts` |
| Context 订阅 | 未发现泄漏 | `useAiEmbeddingState.ts` |

**风险等级**：🔴 High（`useTimelineResize.ts` 是确定性内存泄漏，可在 SPA 长会话中累积）。

## 七、无障碍（a11y）深度 — 扫描范围过窄

### 7.1 `a11ySmoke.spec.ts` 覆盖缺口

- 扫描范围被人为收窄：首页仅 `nav`+`main`；转写页仅 `[data-testid="transcription-workspace-screen"]` + `.left-rail-project-hub-root`。

### 7.2 ARIA live region 缺失

- **命中语段列表**（`SidePaneSidebarSegmentList`）无 `aria-live` 或 `role="log"`；动态插入/删除时读屏用户无法感知。
- **实时转写文本流**（`streamAssistantWords.tsx`）未标记 `aria-live`；流式更新可能不被播报。

### 7.3 `prefers-reduced-motion` 覆盖不完整

- 仅 7 个 CSS 文件覆盖该媒体查询。
- 其余 60 个 CSS 文件中的 `transition` 属性**无降级处理**。

### 7.4 键盘陷阱

- `DbMigrationOverlay.tsx` 使用 `role="alertdialog"`，但**未使用** `useFocusTrap`**，焦点可能逃逸到背景内容。

**风险等级**：🔴 High — 动态内容和模态框的 a11y 缺口直接影响残障用户体验。
