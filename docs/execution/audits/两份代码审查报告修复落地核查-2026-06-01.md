## 四、修复引入的新问题专项核查

### 4.1 aggregate 脚本输出混杂（Low）

**位置**：`scripts/check-architecture-guard-aggregate.mjs`
**问题**：`stdio: 'inherit'` 导致 7 个子检查的标准输出/错误直接打印到终端；若多个子检查同时失败，输出会混杂在一起，难以定位具体失败项。
**建议**：改为捕获各子检查输出，失败时按 label 分组打印。

### 4.2 WorkerPool restart 类型断言（Low）

**位置**：`src/workers/WorkerPool.ts:230`
**代码**：`(entry as { worker: Worker }).worker = newWorker;`
**问题**：用类型断言绕过 `readonly` 修改 `worker` 引用。若未来 `WorkerPoolEntry` 的 `worker` 字段改为 getter-only，此处会在编译期失败。
**建议**：在类型定义层面允许 restart 场景下的 worker 替换（如改为可读写字段或提供正式替换方法）。

### 4.3 segmentMeta 并发 Promise 风暴（Medium）

**位置**：`src/services/segmentMetaSyncBestEffort.ts:14`
**问题**：`scheduleSegmentMetaSyncForUnitIds` 使用 `void` 忽略 Promise。若 `SegmentMetaService.syncForUnitIds` 在高频操作（如批量删除 1000 个 unit）中被调用 1000 次，会产生 1000 个并发的后台 Promise。
**建议**：在 `segmentMetaSyncBestEffort` 层增加防抖或批量合并（如 50ms 窗口内合并 unitIds 数组）。
**处置（2026-06-01 PR-10）**：已在 `segmentMetaSyncBestEffort` 层增加 50ms 微批合并与 unitId 去重；失败日志包含 `contexts`、`unitIdCount` 和错误消息，避免高频调用制造同量级并发 Promise。

### 4.4 check-protobufjs-version-drift 使用 shell: true（Low）

**位置**：`scripts/check-protobufjs-version-drift.mjs:39-41`
**问题**：`spawnSync('npm', ['ls', ...], { shell: true })` 会触发 Node `DEP0190` 警告，并引入不必要的 shell 解释层。
**建议**：移除 `shell: true`，直接用参数数组执行 `npm ls protobufjs --all --json`。
**处置（2026-06-01 PR-9）**：已移除 `shell: true`；`npm run check:protobufjs-drift` 不再触发 `DEP0190`，且输出区分 `OTEL path` 与 `onnxruntime-web path`。

### 4.5 language-mapping-runtime 首屏同步阻塞（Medium，**历史未解风险，非本轮引入**）

**位置**：`src/utils/langMapping.ts` 被 20+ 处同步 import
**问题**：虽被 Vite `manualChunks` 抽成独立文件，但所有消费方均为 `import { ... } from './utils/langMapping'` 同步语法，导致该 chunk 随首屏 bundle 同步加载。
**归类说明**：该问题在补充维度报告中已被识别，**不属于本轮修复引入**，应单列「历史未解风险」维度，不计入「修复副作用率」。
**建议**：将首屏非必需的语言映射功能（如 `ensureLanguageTagMappingsLoaded` 外的函数）改为异步懒加载。

## 七、净结论

1. **Wave 0/1 Critical 修复的整体质量可信**：C1、C5、C7 的根因修复彻底，代码级证据充分；C2 的 sessionMemory 拆分和 C3 的吞错日志化也扎实落地。
2. **未修复项中，C4 和 H4 是最突出的产品级风险**：Embedding 随机失败直接影响 AI 功能可靠性；AI 文案硬编码影响多语言产品完整性。
3. **补充维度报告的勘误项大部分属实，但§3存在反勘误**：7.3（prefers-reduced-motion 全局覆盖）、7.4（DbMigrationOverlay focus trap）、8.1（build-budget 正则）、§10（协作 flag）、§十三 P0（useTimelineResize/useRecording 误报）等确实已修复或为原报告误报。但**§3「死 feature flag 当前不存在」为错误勘误**——`featureFlags.ts` 中确实存在 `singleAxisUnitMode`、`corpusLibraryLabEnabled`、`aiMcpServerEnabled` 三个零业务引用的死 flag。
4. **修复引入的新问题共 6 项（不含历史未解风险）**：P0 恢复入口状态机条件错误会使 open 失败后的手动恢复入口不可用；P1 `DbIntegrityBlockingOverlay` 未接入 focus trap 影响键盘与读屏用户；`check-protobufjs-version-drift` 脚本的 `shell: true` 为 Low 级工程噪声；aggregate 输出混杂、WorkerPool 类型断言、segmentMeta Promise 风暴均为 Low/Medium，不影响核心功能正确性但会增加维护成本。**language-mapping-runtime 同步阻塞为历史未解风险，不计入修复副作用率**。
5. **代码库仍处于「表面合规、深层脆弱」的状态**：architecture-guard 全绿、typecheck 通过、build-budgets 全绿，但 governance 文档与代码事实脱钩、E2E 缺口、PWA/离线/SnapshotService/导入导出 fidelity/AI Provider token 计数等大项**仍未收口**，无界增长风险仍在其他子系统复现。
