## PR-0：恢复入口状态机热修复

### 方案声称
> 将恢复入口条件从「必须处于 migrating」改为「存在最近一次可恢复失败上下文 / open failure 上下文」。

### 代码级核验

**文件**：`src/hooks/useAppDataResilienceEffects.ts`

| 检查项 | 结果 | 证据 |
|--------|------|------|
| 新状态 `preMigrationRestoreTarget` | ✅ 存在 | 第 53 行：`const [preMigrationRestoreTarget, setPreMigrationRestoreTarget] = useState<PreMigrationRestoreTarget \| null>(null)` |
| 迁移版本内存缓存 `activeMigrationRef` | ✅ 存在 | 第 58 行：`const activeMigrationRef = useRef<PreMigrationRestoreTarget \| null>(null)` |
| `onMigrating` 事件缓存版本 | ✅ 存在 | 第 70-72 行：`activeMigrationRef.current = next` |
| `onOpenFailed` 将缓存复制到恢复状态 | ✅ 存在 | 第 78-82 行：`setPreMigrationRestoreTarget(activeMigration)` |
| `onRestoreFromBackup` 条件已改 | ✅ 已改 | 第 155 行：`if (!preMigrationRestoreTarget)`（原条件为 `dbMigration.kind !== 'migrating'`） |
| E2E 专用触发事件 | ✅ 存在 | 第 96-107 行：`jieyu:e2e-db-open-failed` CustomEvent 处理器 |

**结论**：状态机根因已消除。open 失败路径不再依赖 `dbMigration.kind === 'migrating'`，而是直接检查 `preMigrationRestoreTarget` 是否存在。该状态由 `activeMigrationRef` 在迁移过程中缓存，open 失败时复制，不受 `dispatchDbMigrationDoneEvent()` 影响。

## PR-2：Embedding mid-flight terminate 根因修复

### 方案声称
> 将配置变化与运行中任务取消拆开：只有用户显式取消、provider 不兼容切换、页面卸载才允许 terminate。

### 代码级核验

**文件**：`src/hooks/ai/useAiEmbeddingState.ts`

| 检查项 | 结果 | 证据 |
|--------|------|------|
| `embeddingServicesRef` Set 管理 | ✅ | 第 217 行：`const embeddingServicesRef = useRef(new Set<EmbeddingServiceLike>())` |
| 添加服务到 Set（无 cleanup terminate） | ✅ | 第 221-222 行：`embeddingServicesRef.current.add(embeddingService)` |
| 组件卸载时才 terminate | ✅ | 第 226-236 行：cleanup useEffect deps 为 `[]`，仅在卸载时遍历 Set 并 terminate |

**但上游问题仍在**：

**文件**：`src/pages/TranscriptionPage.AnalysisRuntime.tsx`

| 检查项 | 结果 | 证据 |
|--------|------|------|
| `useMemo` deps 引用稳定性 | ❌ 未修 | 第 24-30 行：deps 仍为 `[embedding.provider.config.embeddingProviderConfig, taskRunner]`；若 `embeddingProviderConfig` 对象引用不稳定，每次渲染都会重新创建 `deferredEmbeddingRuntime` |

**结论**：
- ✅ `useAiEmbeddingState` 侧已完成：service 实例变化不再触发 terminate，仅在组件卸载时清理。
