# 协作与同步冲突

## 目标（当前仅能做到）

理解边界：

- 日常田野数据默认在**本机项目**。
- 需要与他人协作时，未来同步的是**按项目裁剪的变更**，不是整台电脑拷贝。
- 两端改同一处会出现冲突；**未处理完不能当成已经同步完成**。

## 适用场景

- 你在评估「能不能多人同时改同一项目」——结论：以 #342 落地为准，本站不提供操作步骤。
- 你需要备份与交换：请用 [导入导出与备份](/export) 的 JYT/JYM/JYB，而不是等待协作同步。

## 前置条件

无。本页不要求打开任何协作开关。

## 界面定位（有代码 ≠ 已交付教程）

仓库里存在协作面板、冲突审阅抽屉等文案模块（如 `collaborationConflictReviewDrawerMessages`），转写台也可能出现协作相关控件。**在 #342 与产品开关明确交付前，不要按这些控件写生产流程。** 若界面显示需要登录或云开关，以当时构建的说明为准，本站不编造账号步骤。

## 分步操作

**无。** 请勿将草稿设计当成步骤执行。

临时替代路径：

1. 各自在本机项目工作。  
2. 用 JYM/JYB 或约定交换格式交接。  
3. 人工合并时保留原始备份。  

## 如何核对成功

在协作落地前，**没有「已同步」核对表**。唯一可核对的是：本地备份文件是否按 [导入导出与备份](/export) 成功生成。

## 常见问题与处理

1. **看到冲突 UI 就点保留** → 在教程缺失时，先导出备份再改动。  
2. **以为浏览器清数据能靠云找回** → 不要假设；先本地备份。
