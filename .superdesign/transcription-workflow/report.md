# 转写核心工作流与多面板审查修复

日期：2026-10-24。基线：`edc2ee7e`。结论：本切片浏览器开发态验证通过，保留现有外观；不等于完整G1、视觉迁移或Electron交付完成。

## 审查契约

使用者围绕媒体、语言层与句段连续播放、定位、编辑、保存。编辑焦点与播放范围必须可辨，声学展开不能挤掉编辑区；非模态AI浮窗可以移动、遮挡部分内容，但不得夺取模态或IME正在处理的快捷键。禁止新增嵌套卡片。

参考：Audacity播放/选区、Praat TextGridEditor、ELAN编辑/播放模式；链接及取舍记录在主实施计划的当前切片。复用现有焦点、控件、滚动与写入路径，无新依赖、controller、数据格式或主题。

## 确认的问题与修复

| 问题 | 行为链与根因 | 修正与证据 |
|---|---|---|
| 对读保存重开后，多行显示同一父句文字 | UI保存→子段内容表正确读回→重开对读却经通用父句lookup取到同一文字；侧栏与对读不一致 | 对读原文优先读`segmentContentByLayer`中子段自己的文字；空字符串也保持为空。三个同父子段（含空文本）的组件回归，以及真实UI保存→重开→再选原句通过；没有修改数据库写入语义 |
| 声学展开后时间轴近乎消失 | 1280×720下检查器固定占40vh，主编辑区缩到约49px，140%字号约9px | 检查器允许收缩并保持内部滚动，主时间轴最低96px；1440×1000、1280×720及140%组合下均通过 |
| 字号放大后底部工具越界 | 顶部提示条由28.5增高到36.3px，但grid隐式行被内容最小尺寸撑住；底部到728.3px，窗口仅720px | 壳层grid行显式`minmax(0,1fr)`，最终底部720px，与窗口一致 |
| 模态、AI与IME的Esc串线 | 新建层使用DialogShell却未接现有焦点陷阱，Esc不关闭；AI全局监听忽略已消费/组合输入事件 | 新建层复用`useFocusTrap`，支持Tab/Shift+Tab循环、Esc与焦点恢复；陷阱和AI监听尊重isComposing/defaultPrevented，AI不处理来自模态内部的快捷键。真实模态关闭后聊天保持展开，IME取消不最小化聊天 |
| 声学下拉框缺名称 | 参数预设、增强provider、路由策略三个select旁边有文字但没有label关联 | 复用现有字典补aria-label；声学+AI打开的三种组合做全页axe，0违规 |
