## 产品视角与设计约束

用户在桌面工作台内反复切换项目、录音、文稿、语言层、句段、词条和语料选集。左侧栏应先回答“当前在处理什么对象”，其次提供对象导航与常用操作；长说明、低频维护和详细属性不能挤掉导航列表。保持当前主题和语义 token，禁止靠新增卡片层层套叠解决分区问题。

设计契约：主对象在首屏可辨；当前选中与键盘焦点可区分；列表必须有实际可用高度；滚动所有者明确且末项可达；加载、空、错误状态保留必要导航；正文与侧栏来自同一份实时状态。宽度 240–420px 内可用，默认 272px。桌面矮窗口优先保住文件、层、句段导航，详细属性可在独立区域滚动。

参考模式：

- [VS Code Sidebars](https://code.visualstudio.com/api/ux-guidelines/sidebars)：相关内容集中，减少侧栏分区和重复命令；“3–5 个视图”仅作为密度参考，不机械照搬。
- [VS Code Views](https://code.visualstudio.com/api/ux-guidelines/views)：数据列表、视图操作和命令分开，名称短而明确。
- [WAI Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)：如果采用树控件，应提供相应键盘行为，并区分选择与焦点；不要求把现有简单列表强改成树。
- [WAI Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)：竖向标签应支持上下键切换焦点，并建立标签与内容区关联；Home/End 是可选增强。

## 证据与方法

- 6 个主页面 × 3 种组合：1440×900 / 272px / 100%；1280×720 / 240px / 100%；1280×720 / 420px / 140%。截图、DOM 尺寸与内部滚动高度同时记录。
- 使用隔离浏览器数据。先导入 4 秒合成 WAV，再通过真实标注导入入口导入 EAF，保证标注页有 canonical 句段。前一轮旧辅助夹具录音仅约 0.3 秒而句段超长，其媒体越界警告不作为产品缺陷。
- 词典实际创建、保存、更新释义、重新载入；语料实际勾选并确认导出按钮启用；设置实际聚焦第一个标签后按 ArrowDown。
- 空标注状态另见 `runtime/`；有效录音与标注数据见 `confirmed/`，中间复核见 `populated/`。`observations.json` 是测量与状态差异，不是“无缺陷测试通过”的证明。`final/` 的长释义实验因侧栏摘要不更新而中断，不算通过；后续改变词头以触发摘要刷新后再检查长内容布局。

## 需要先修的发现

### 1. P1：转写片段列表被压缩到 1px / 0px

路径：转写页 → 展开左栏 → 默认分区同时显示 → 矮窗口。1280×720、240px 宽时，片段滚动区 clientHeight=1、scrollHeight=46；420px 宽并放大到 140% 时 clientHeight=0、scrollHeight=58。外层滚动区自身没有溢出，因此不能通过滚动整个侧栏恢复列表高度。

根因：`src/styles/panels/layer-list.css:1003` 将片段分区改为 `flex:0 1 auto; min-height:0`；overview、文件区与内部列表都允许收缩，维护操作仍占约 94–101px。外层“没有溢出”掩盖了内部导航失效。

修复方向：保留一个明确的纵向空间分配策略，确保导航列表有可操作的下限；低频维护不要抢占刚性高度。验证时断言列表实际高度、首末项可见与可点击，不能只断言 document 无横向溢出。

### 2. P1：词典 / 语料 / 分析侧栏不是实时状态

词典实测：正文保存为 `updated glossary`，侧栏仍为 `original glossary`。语料实测：列表已显示并成功勾选，复制按钮已启用，侧栏仍显示 `0 units / 0 selected`。分析页同样注册静态标题/副标题和动态 ReactNode，代码链存在同类失效条件；本次没有通过修改分析数据单独复现其刷新动作。

根因：`src/contexts/AppSidePaneContext.tsx:117` 对仅内容变化故意不广播，避免不稳定 ReactNode 造成更新风暴。Home、转写、标注通过 portal 维护实时内容，LexiconPage、CorpusLibraryWorkspace、AnalysisPage 却直接注册动态内容。

修复方向：复用项目现有实时 portal 模式或提供有明确稳定更新契约的注册方式，不直接撤销防循环保护。回归需要验证真实保存/选中后的可见摘要，不只看 hook 被调用。

### 3. P2：标注空态 / 加载 / 错误态留下空白侧栏

`src/pages/AnnotationWorkspace.tsx:187` 的条件分支仅在 rows 非空时挂载 `AnnotationDocumentToolsSlot`，而标题注册始终存在。实际空态保留整块 272px 空白，项目文件入口也消失。用户不易从当前侧栏切换或定位可处理文件。

修复方向：项目上下文和必要导航放在状态分支之外，句子操作由是否有选中句子决定。空、加载、失败说明应与恢复动作同屏。

### 4. P2：通用摘要侧栏缺少长内容的滚动契约

`src/styles/pages/feature-availability.css:1` 的 feature-stack 没有滚动边界，而壳层 body-slot 为 overflow:hidden。实际保存长释义并改变词头触发摘要刷新后：内容高856px，底部959px，父容器底部712px且overflow:hidden，“快速访问”已被裁掉。最终长释义实验记录在 confirmed/observations.json；修复应限制摘要展示量或明确设置可访问的滚动区域，不能单靠增加侧栏宽度。

### 5. P2：设置声明 vertical tablist，但方向键不工作

实际从 Appearance 聚焦后按 ArrowDown，焦点与选中项均留在 Appearance。`src/components/settingsModalPrimitives.tsx:13` 声明 tablist/tab，但按钮只有点击处理；缺少方向键和 roving tabIndex。

修复方向：补齐竖向标签的上下/Home/End 键、焦点和选中策略、tab 与 panel 的关联；鼠标布局本身无需重做。

## 逐页布局结论

| 页面 | 已观察的布局 | 结论与建议 |
|---|---|---|
| 首页 | 项目列表独立滚动，活动项目可辨，新建入口明确，当前样本无横向溢出 | 基础结构可保留；新建按钮在列表滚动容器内，超长项目列表时可能离开视口，需要长列表专项复核；长名称省略的完整名称获取需补验 |
| 转写 | 文件、语言层、检索、片段、维护操作垂直串联；240px 下两层只分到约44px，句段降到1px | HOLD；先修高度分配。Find 与 Search segment text 两套检索并列，范围差异没有在分区标题中解释，增加学习成本；低频 constraint repair 单独占一大块不合理 |
| 标注 | 有数据时文件区75–107px，工具区524–671px且能独立滚动；句子操作在检索下方 | HOLD；保留独立工具滚动，文件区需改善；把“项目/范围”“检索/显示”“当前句子操作”用平面标题与分隔线区分，避免模板ID和跳转链接抢首屏 |
| 词典 | 当前词条摘要 + 快速入口，长词头可换行；主词条列表放正文 | HOLD；先修实时摘要和长内容裁切。摘要重复词头，保留“Skeleton / 基础骨架”和“以后可承载...”开发说明，应改为当前真实能力文案；不必强行把正文词条列表再复制一份 |
| 语料库 | 侧栏只有范围、数量、已选数和返回链接，余下大片空白 | HOLD；先修数量实时性，再决定是否保留这么宽的摘要。可强化范围、选集和清空/导出关联，避免正文与侧栏重复大标题和返回入口 |
| 分析 | 侧栏只有范围、数量与返回，正文承载分析 | 数据刷新模式需修；当前侧栏信息密度偏低，但不应为填空白添加无关控件。分析对象、范围和当前选择比工作区介绍更有价值 |
| 语言元数据 / 结构模板 / 正字法 / 桥接 | App 路由以 modal 打开，registerSidePane=false；本次窗口下语言或正字法列表位于弹窗内容上方 | 没有独立展开态左栏，不应强行补一个。顶部对象列表和下面编辑内容共用有限高度，正字法、桥接首屏主要被总览与列表占据；后续做“固定对象选择、编辑区独立滚动”的专项设计。不能把遮罩后的转写侧栏计为资源页通过 |
| 设置 | 132px 标签导航与右侧内容布局明确，七项在720px高窗口可见 | 外观结构可保留；键盘语义需修。未将被遮罩的主页面算作可操作页面 |

## 优先顺序与验收

1. 修片段零高度与摘要滞后：这是实际导航/状态错误。
2. 补标注空态导航、长摘要滚动和设置键盘。
3. 再统一平面分区、标题、链接、检索命名与重复说明，沿用现有 token，不新增嵌套卡片。
4. 验收覆盖 240/272/420px、720/900px 窗口、正常/140%字号、长名字/长释义/多项目/多层、空/加载/失败、跨页返回；真实可见操作与状态断言优先于截图快照。

未验证边界：Electron 真机窗口、深色主题、故障注入、多项目与多层的大数据量压力、完整 tree/list 键盘遍历。140% 通过 CSS token 注入做压力测试，不等价于设置字号完整交互验收。本轮没有修改产品或宣称缺陷已修复。
